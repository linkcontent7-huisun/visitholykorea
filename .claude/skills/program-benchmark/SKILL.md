# 순례·탐방 프로그램 홍보 벤치마킹

참가 후기 자료(안내문·채팅 캡처·인스타 게시물)를 받아, **무엇이 사람을 모았는가** 를
뽑고 비지트홀리에 맞게 옮긴다. 첫 사례와 결과: `docs/50-research/벤치마킹/2026-10-19-칠곡-시간여행자의고백.md`.

## 1. 자료를 받으면 먼저

사용자가 준 파일을 **전부 직접 열어 본다**(경로만 받고 읽지 않은 채 요약하지 않는다).
다음 일곱 가지를 채우고, 비어 있으면 사용자에게 한 번에 묻는다.

| 칸 | 묻는 것 |
|---|---|
| 발견 | 어디서 알게 됐나 (계정·게시물 형태) |
| 신청 | 어디로 신청하나 (링크·QR·폼), 단계 수 |
| 가격 | 참가비와 돌려받는 것 |
| 사전 안내 | 집결·일정·준비물을 어떤 형식으로 보냈나 |
| 당일 운영 | 시간별 공지, 사진 공유, 안내 방식 |
| 사후 | 감사 인사, 인증 이벤트, 재참여 유도 |
| 신뢰 | 후원·주관 기관, 로고, 출처 |

## 2. 사실과 추측을 나눈다 (evidence-first)

- **✅ 사실**: 캡처·안내문에 보이는 것. 숫자는 화면에 보이는 값만, 언제 본 값인지 적는다.
- **주장**: 사용자가 말로 알려 준 것(예: 환급 구조). 안내문으로 확인 안 됐으면 그렇게 표시.
- **❓ 추측 / ⏳ 확인 안 함**: "그래서 효과가 있었다" 같은 인과는 추측이다. 근거 하나로
  효과를 단정하지 않는다(좋아요 수만으로 성과를 말하지 않는다).

## 3. 비지트홀리로 옮길 때 점검

1. **규모 차이**: 상대가 가진 것(팔로워·보조금·행사 자체)이 우리에게 있는가. 없으면 대체 수단을 적는다.
2. **우리 자산**: 성지 수·오디오 가이드·6개 국어·순례 기록 기능 등 **이미 있는 것** 으로 되는가
   (숫자는 `docs/이어서-할-일.md` 의 실측값을 인용하고 날짜를 붙인다).
3. **제약**: 심사 기간 화면 동결(게시물은 화면을 안 바꿔 해당 없음), TourAPI 응답 저장 금지,
   더미 데이터 금지. 홍보 자동화는 보류 중이므로 **수동 게시안** 으로 쓴다.
4. **예산·주최 여부**: 경품 예산, 행사를 직접 열지는 사장님 결정 — 정하지 말고 선택지로 올린다.

## 4. 저장소에 넣지 않는 것

- 채팅 캡처의 **참가자 이름·프로필** (개인정보, 저장소는 공개).
- 타 계정의 이미지·카드뉴스 원본 복제. 구조·문구 유형만 글로 요약한다.

## 5. 끝낼 때

결과 문서를 `docs/50-research/벤치마킹/<날짜>-<프로그램>.md` 에 쓴다
(발견 칸 표 → 사실/추측 구분 → 적용안 → 사장님 결정 필요). 그리고
`docs/이어서-할-일.md` 에 한 줄 남기고 커밋·푸시한다.
