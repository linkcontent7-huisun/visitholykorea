# 도슨트 현장조사 진행법

사용자가 성지 현장에서 핸드폰으로 사진을 올리며 설명하면, 너는 그 자리에서
도슨트 원고를 만들어 저장소에 쌓는다. 전체 배경은
`docs/30-content-ops/도슨트-현장조사-매뉴얼.md` 를 먼저 읽는다.

## 시작할 때

1. 성지 이름을 확인하고 로마자 슬러그를 정한다 (예: 절두산 → jeoldusan)
2. `data/docent/<슬러그>/` 와 `photos/` 를 만들고, `_템플릿.json` 을 복사해
   `points.json` 을 만든다. siteName 은 DB 성지명과 정확히 일치시킨다
   (스냅샷 `data/archive/2026-08-supabase/snapshot_kaahuo_2026-08-10.json` 에서 id 조회)
3. 사용자에게 입구 사진부터 부탁한다

## 포인트마다 (사진 + 구술이 올 때마다)

1. 사진을 `photos/NN-이름.jpg` 로 저장한다. 가능하면 긴 변 1600px 로 줄인다
   (ImageMagick `convert` 가 있으면 사용, 없으면 원본 그대로)
2. 사진 속 안내판·현판 글자를 읽어 근거로 삼는다
3. 원고를 쓴다 — 매뉴얼의 톤 규칙:
   구어체 존댓말 / "무엇"보다 "왜" / 비신앙인 기준 / 3~6문장 / 모르면 모른다고
4. 쓴 원고를 채팅에 보여주고 다음 포인트로 넘어간다 (승인 기다리지 말 것 —
   감수는 나중에 몰아서 한다. status 가 draft 인 이유다)

## "조사 끝" 이라고 하면

1. intro / outro 를 채우고 points.json 을 완성한다 (status: "draft")
2. `python3 -c "import json; json.load(open('경로'))"` 로 JSON 유효성 확인
3. 커밋 메시지에 성지명·포인트 수·사진 수를 적고 푸시한다
4. 사용자에게 요약을 보여준다: 포인트 목록 + 확인 못 해 비워둔 것

## 주의

- 추측을 사실처럼 쓰지 않는다. 연도·인명이 불확실하면 sourceNote 에
  "확인 필요"라고 적는다
- 성지 소개글(description)과 겹치는 내용은 줄인다 — 도슨트는 눈앞의
  사물을 설명하는 것이지 역사 요약이 아니다
- 사용자가 지쳐 있을 수 있다. 현장에서는 짧게 묻고 짧게 답한다
