④ 성지 본문 번역 — 화면 문구와 다른 경로

성지 이름·소개글·역사·주소는 사전이 아니라 DB(holy_site_translations)에 들어갑니다. 갱신 주기가 화면 문구와 다르기 때문에 일부러 분리되어 있습니다. 208곳을 한 번에 하지 않고 교구 단위로 파일을 뽑아 채운 뒤 다시 넣는 방식입니다.

1 · 내보내기

교구 하나를 골라 작업 파일을 만듭니다.

npm run translate:export -- --lang en --diocese 대전

2 · 채우기

data/translations/<lang>-<교구>.todo.json의 target만 채웁니다. source는 참고용이라 건드리지 않습니다.

필드: name · description · history · addressRomanized

3 · 넣기 · 진행률

형식 검사를 통과한 파일만 DB 로 들어갑니다.

npm run translate:import -- --file …
npm run translate:status -- --lang en

번역 규칙 — 코드에 적혀 있는 약속

  • 주소는 번역하지 않습니다. 로마자 표기만 넣습니다 — 택시 기사에게 통해야 합니다.
  • 빈 문자열·null 은 "아직 안 함"으로 보고 건너뜁니다. 빈 껍데기 행을 만들지 마십시오.
  • 대체 순서가 있습니다: 번역이 없으면 영어를 거쳐 한국어로 내려갑니다(FALLBACK_CHAIN, dictionary.ts 74행). 그래서 영어를 가장 먼저 완성하는 것이 다른 모든 언어의 품질을 올립니다.
  • 자리표시자 {'{'}n{'}'} {'{'}total{'}'}은 개수와 이름을 그대로 유지하고 위치만 옮깁니다. 문장을 조각내어 이어 붙이지 마십시오 — 어순이 다른 언어에서 무너집니다.
  • 포르투갈어 음성은 pt-BR 입니다. 본문은 브라질·포르투갈 양쪽이 읽을 수 있는 표현으로 씁니다.
  • 언어 이름은 그 언어로 적습니다(Español, Français…). 못 읽는 언어로 써 두면 고를 수 없습니다.

⑤ 새 언어 하나를 추가하는 절차

현재 지원: 한국어 · 영어 · 스페인어 · 프랑스어 · 포르투갈어 · 이탈리아어(2027 서울 WYD 공식 언어). 일본어·중국어처럼 일곱 번째 언어를 넣을 때 손댈 자리는 여섯 곳뿐이며, 타입 검사가 나머지를 강제로 잡아 줍니다 — 한 곳만 채우면 npm run build가 빠진 곳을 전부 알려 줍니다.

⑥ 이 표를 만든 방법 (재현 가능)

  • 사전 파싱: dictionary.ts의 한 줄 표기와 여러 줄 표기를 모두 읽어 키 · 분류 주석 · 6개 언어 값 · 정의 위치를 추출.
