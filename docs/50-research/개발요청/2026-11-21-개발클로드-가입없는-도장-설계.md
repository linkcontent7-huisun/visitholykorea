# 개발클로드 → 팀장: 로그인 없이 도장 받기 설계서 (지시서 3호 일 ②, 2026-11-21)

코드는 고치지 않았다. 아래 ✅ 는 `origin/main`(2026-11-21) 코드를 직접 읽은 것이다.

## 한 줄 결론

**운영 DB 구조는 그대로 두고 PR 두 개로 된다.** 이미 지도에 있는 「기기에만 남는 가 봤다 표시」를 도장으로 넓히고, 로그인할 때 「이 기기 기록 N곳을 내 여권에 옮길까요?」를 한 번 묻는다. 한 줄 기록(다른 순례자에게 보이는 글)과 사진은 지금처럼 로그인한 사람만 남긴다.

## 1. 지금 흐름과 바뀌는 흐름

**지금 (✅ 코드 확인)**

| 단계 | 무엇 | 근거 |
|---|---|---|
| 도장 = 「기록 쓰기」 | 성지 상세에서 한 줄을 써야 도장이 생긴다. 한 줄이 비면 저장 단추가 꺼진다 | `NoteComposer.tsx:66-76, 232` |
| 로그인 요구 | 저장을 누른 **뒤에** 로그인 화면으로 보낸다. 쓰던 한 줄은 남지 않는다 ❓(화면에서 다시 확인 필요) | `NoteComposer.tsx:85-86`, `stamps.repository.ts:101` |
| 위치 확인 | **없다.** 성지에 가지 않아도 기록할 수 있다 | `features/passport` 에 위치 조회 코드 없음 |
| 내 기록 화면 | 로그인 안 하면 「로그인」 안내만 보인다 | `RecordsPage.tsx:446-455` |
| 이미 있는 기기 기록 | 지도에서 「가 봤다」를 누르면 로그인 없이 기기(`localStorage` 키 `visitholykorea.visited`)에 성지 id·날짜가 남고, 로그인하면 서버 도장과 합쳐 **보여주기만** 한다 | `map/api/visited.ts`, `map/hooks/use-visited.ts` |

**바뀌는 흐름 (권장)**

1. 성지 상세에서 로그인하지 않은 분께 **「다녀왔어요」 단추 하나**를 보인다. 누르면 기기에 도장이 찍힌다(지도의 「가 봤다」와 같은 저장소). 한 줄은 쓰지 않아도 된다.
2. 「내 기록」 화면은 로그인 전에도 기기 도장 목록과 개수를 보여 주고, 그 위에 「이 기록은 이 휴대폰에만 있어요. 로그인하면 잃어버리지 않아요」를 늘 띄운다.
3. 로그인하면 기기 도장이 있을 때 한 번 묻는다: 「이 휴대폰에 남긴 성지 N곳을 내 순례 여권에 옮길까요?」 + 성지 이름 목록 + [옮기기] [나중에] [이 기기에서 지우기].
4. 한 줄 기록·사진은 지금처럼 로그인한 분만. 다른 순례자에게 공개되는 글이라 신고·삭제 책임이 계정에 있어야 한다.

## 2. 손댈 파일과 손대지 않을 것

**운영 DB 구조를 그대로 둘 수 있다.** 근거:
- 옮기기는 로그인한 본인이 자기 도장을 넣는 것이라 지금 규칙(`stamps_insert_own`: `auth.uid() = user_id`)으로 된다. `20260804090100_create_pilgrimage_stamps.sql`
- 같은 성지 두 번은 `unique (user_id, site_id)` 가 막고, 앱은 이미 23505 를 「이미 찍음」으로 처리한다. `stamps.repository.ts:113-117`
- 방문일 열(`visited_on`)이 있어 기기에 적힌 날짜를 그대로 넣을 수 있다.

| 손댈 파일 | 무엇 |
|---|---|
| `src/features/map/api/visited.ts` | 기기 도장 읽기·쓰기를 그대로 쓰고, 「옮긴 것 지우기」 함수 하나 추가 (자리를 `features/passport` 로 옮길지는 PR 1 에서 정함) |
| `src/features/passport/components/site-notes/NoteComposer.tsx` 또는 성지 상세의 새 작은 부품 | 로그인 전 「다녀왔어요」 단추 |
| `src/pages/RecordsPage.tsx` | 로그인 전 기기 도장 목록과 안내 |
| 새 부품 + 훅 (`features/passport/…`) | 로그인 뒤 「옮길까요?」 묻기, `addStamp` 를 차례로 부르기 |
| `src/shared/i18n/dictionary.ts` | 새 문구 4~6개 × 6개 언어 |

**손대지 않을 것:** `pilgrimage_stamps` 표와 보안 규칙, `addStamp` 의 동작, 한 줄 기록·사진 올리기, 관리자 콘솔, 로그인 방식.

**하지 않을 것:** Supabase 「익명 로그인」. 서버에 기록이 남는 장점은 있지만 로그인 설정을 바꿔야 하고, 손님 계정이 계속 쌓이며, 공개 글 책임이 흐려진다. 운영 설정 변경이라 이 일의 범위를 넘는다.

## 3. 합칠 때의 규칙

| 경우 | 규칙 |
|---|---|
| 같은 성지가 기기와 계정에 다 있음 | **계정 것을 남긴다.** 기기 날짜로 덮어쓰지 않는다. 지도도 이미 이렇게 한다(`use-visited.ts:19-24`) |
| 기기에만 있음 | `addStamp(siteId, null, null, 기기 날짜)` 로 넣는다. 한 줄은 비운다. 비공개다 |
| 옮기기 성공 | 그 성지는 기기에서 지운다. 실패한 것만 남기고 다음 로그인 때 다시 묻는다 |
| 한 기기를 두 사람이 씀 | 저절로 옮기지 않는다. **반드시 목록을 보여 주고 묻는다.** [이 기기에서 지우기]로 남의 기록을 버릴 수 있다. 「나중에」를 누르면 그 계정에는 다시 묻지 않는다 |
| 로그아웃 뒤 | 기기 도장은 그대로 남는다(계정 도장은 기기에 복사하지 않는다). 탈퇴하면 지금처럼 기기 기록도 지운다(`AccountPage.tsx:105`) |
| 옛 형식(날짜 없는 id) | 날짜를 지어내지 않는다. `visited_on` 을 비우고 넣는다 |

## 4. 잃어버리는 경우 (숨기지 않는다)

| 경우 | 무슨 일 | 확인 |
|---|---|---|
| 브라우저 기록·사이트 데이터 삭제 | 기기 도장이 모두 사라진다 | ✅ `localStorage` 의 성질 |
| 아이폰 사파리 7일 제한 | 사파리로 7일 동안 이 사이트를 열지 않으면 사이트가 저장한 값이 지워질 수 있다. 홈 화면에 추가한 앱은 이 제한에서 빠진다 | ⏳ 공개 문서 기준. 실제 아이폰에서 재 보지 않음 |
| 홈 화면 앱과 브라우저가 따로 | 사파리에서 찍은 도장이 홈 화면 앱에는 안 보인다(반대도 같음). 안드로이드 앱(Capacitor)도 따로다 | ⏳ 아이폰·안드로이드 실기기에서 재 보지 않음 |
| 기기 바꿈·잃어버림 | 옮기지 않은 도장은 되살릴 수 없다 | ✅ 서버에 없으므로 |
| 사생활 보호 창 | 창을 닫으면 사라진다 | ✅ |

**화면에서 알리는 법:** 「내 기록」 맨 위와 「다녀왔어요」를 처음 누른 직후에 한 번, 「이 기록은 이 휴대폰에만 있어요. 로그인하면 잃어버리지 않아요」. 문구는 새로 지은 것이라 **사장님 확인이 필요하다.** 첫 이용자가 고령 교우이므로 「브라우저 저장소」 같은 말을 쓰지 않는다.

## 6. 일의 크기와 권장안

| PR | 무엇 | 크기 | 운영 DB |
|---|---|---|---|
| 1 | 로그인 전 「다녀왔어요」 + 「내 기록」에 기기 도장과 안내 | 파일 4~5개, 새 문구 6개 언어 | 그대로 |
| 2 | 로그인 뒤 「옮길까요?」 묻기와 옮기기 | 새 부품·훅 1개씩 + 시험 | 그대로(쓰기는 본인 도장 넣기뿐) |

**권장:** PR 1 → PR 2 순서. PR 1 만 올라가도 지도와 같은 「기기에만 남는 기록」이라 따로 위험은 없다. 다만 PR 1 만 오래 두면 도장을 모은 분이 옮길 길이 없으니 둘을 같은 주에 올린다.

**사장님이 정하실 것**
1. 안내 문구 두 개(「이 휴대폰에만 있어요…」, 「옮길까요?」)
2. 「다녀왔어요」 단추를 한 줄 없이도 열지. 지금은 한 줄을 써야만 도장이 된다. 고령 교우에게는 단추 하나가 쉽다는 것이 이 설계의 전제다

**확인 못 한 것:** 실제 아이폰·안드로이드에서 저장이 얼마나 오래 남는지, 로그인 화면에 다녀오면 쓰던 한 줄이 사라지는지(화면으로 재 보지 않음).
