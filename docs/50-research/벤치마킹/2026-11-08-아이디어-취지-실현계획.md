# 아이디어 취지와 실현 계획 (2026-11-08, 사장님 말씀 그대로 기록) — 발표·개발의 기준

> 이 문서가 발표 뼈대와 개발 순서의 **기준**이다. 헷갈리면 여기로 돌아온다.
> 바탕: 사장님 11/8 말씀 + 제출 제안서(`…최종_제출용_수정.docx`) §1·§3·§4.

## 1. 취지 (사장님 말씀 요약)

1. **어떤 경로로든 홍보를 보고**(우리 홈페이지, 인스타그램, 주최 기관 웹자보 링크 등) 참가 신청한다.
2. 참가자는 **성심당에 가서 빵을 사고, 이어서 대흥동성당**으로 간다.
3. **빵 줄을 기다리는 동안** 성심당·대흥동성당, 이어서 갈 옛 충남도청 일대의 역사 이야기를 (오디오·영상 등으로) 미리 보고 듣는다.
4. 기다리면서 **퀴즈를 풀어 포인트를 쌓는다.**
5. 체험을 마친 뒤 **그 포인트를 쓰려고 대전에서 더 소비**하고 간다.
6. 다음 행사 안내에 **동의한 사람에게 2호·3호를 문자·메일로 안내**한다 → 다시 온다.
7. **홍보는 바이브코딩으로 최대한 자동화**해서 쉽게 올린다(채널별).
8. **협업 기관**이 원하는 것(집계, 만족도 등)을 이 사이트에서 한 번에 끝내고 **엑셀 한 파일로** 내려받게 한다.
9. **이용자는 저렴하고 간편하게.** 접수한 **링크 하나로** 들어온 Visit Holy Korea 웹앱에서 모든 정보를 받는다.

**한 문장:** 홍보 → 접수 → 줄에서 이야기·퀴즈 → 체험 → 포인트로 지역 소비 → 다음 호 안내. 이 고리를 **링크 하나**로 잇고, 기관에는 **엑셀 한 파일**을 준다.

## 2. 실현 설계 — 핵심은 「나의 체험 링크」

접수가 끝나면 참가자마다 **개인 링크**(예: `visitholykorea.com/my/접수번호`)가 생긴다. 회원가입 없이 이 링크 하나로 당일의 모든 것을 한다.

| 고리 | 참가자가 하는 일 | 사이트가 하는 일 | 기관이 받는 것 |
|---|---|---|---|
| ① 홍보 | 인스타·웹자보·홈페이지에서 링크를 누름 | 채널마다 꼬리표가 붙은 링크·QR·카드 이미지를 자동으로 만듦 | 「어디서 보고 왔나」 집계 |
| ② 접수 | 인원·동의 2단 입력 | 접수번호 + **나의 체험 링크** 발급(문자로 받을 링크) | 명단 |
| ③ 줄에서 | 링크를 열고 이야기를 보고 들음(성심당 → 대흥동성당 → 옛 충남도청) | 대기 시간에 맞춰 이야기 조각을 보여 줌(글 + 듣기) | 몇 명이 들었나 |
| ④ 퀴즈 | 이야기를 듣고 퀴즈를 풂 | 맞히면 포인트 적립(그 접수번호에 쌓임) | 참여율·정답률 |
| ⑤ 체험 | 대흥동성당·전시관 현장 체험 | 다음 장소 길 안내 | |
| ⑥ 지역 소비 | 포인트를 제휴 상점에서 사용 | 사용 화면·확인 코드 | 지역에서 쓴 포인트 |
| ⑦ 만족도 | 끝나고 링크에서 3문항 응답 | 저장 | 만족도 |
| ⑧ 다음 호 | (동의자) 2호 소식을 받음 | 동의자 명단 + 안내 문구 자동 작성 | 재방문 명단 |
| 기관 | — | — | **①~⑧이 엑셀 한 파일**(시트: 접수·유입 경로·퀴즈 포인트·만족도·안내 동의자) |

| 순서 | 만들 것 | 고리 | 사장님 할 일 | 크기 |
|---|---|---|---|---|
| 0 | 운영 안내 페이지 `/programs/bread-from-heaven` | 전체 | 확인 | ✅ 11/8 (3c3e780) |
| 1 | **나의 체험 링크** — 접수 완료 → 개인 링크 화면(당일 안내·이야기·퀴즈·포인트·만족도가 모이는 곳) | ② | DB 표 적용 `db:migrate` | 중간 |
| 2 | **줄에서 듣는 이야기** — 성심당·대흥동성당·옛 충남도청 3묶음, 1분 조각, 글 + 듣기(휴대폰 읽기 기능, 무료), 대기 시간 선택 | ③ | 원고 확인(사실은 공식 자료로 확인) | 중간 |
| 3 | **퀴즈 → 포인트** — 이야기에서만 문제, 맞히면 그 접수번호에 포인트 | ④ | 문제 확인 | 중간 |

| 5 | **홍보 자동화** — 채널별 꼬리표 링크(홈페이지·인스타·웹자보), QR, 인스타 카드 이미지 자동 생성 + 유입 경로 저장 | ① | — | 중간 |
| 6 | **기관 엑셀 한 파일** — 시트 여러 장(접수·유입·포인트·만족도·안내 동의자) | 기관 | — | 작음(엑셀 기능 ✅ 있음) |

**이후 단계(발표에서 솔직히 말함):** 포인트 제휴 상점 사용(⑥, 상점·지자체 협의), 문자·메일 실제 발송(발송 서비스 비용·수신 동의 규정 확인).

## 4. 발표 뼈대 (이 취지 순서 그대로)

1. 성심당 줄 장면 → 2. 문제(빵만 사고 돌아간다, 정보·접수가 흩어져 있다) → 3. **고리 한 장**(홍보 → 접수 → 줄 이야기·퀴즈 → 체험 → 지역 소비 → 다음 호) → 4. 1호 하루 → 5. **시연: 링크 하나로 따라가기**(홍보 링크 → 접수 → 나의 링크 → 이야기·퀴즈 → 기관 엑셀) → 6. 바이브코딩 자동화(홍보물 자동 생성, 엑셀 한 파일) → 7. 돈 흐름(기관이 내고, 포인트는 지역에) → 8. 같은 틀로 2호 강경 + 동의자에게 안내 → 9. 추후 협의 · 마무리

## 5. 정해야 할 것
- 8번 기관 등록 화면이 시간 안에 안 되면: 2호 강경은 「등록 데이터로 추가」로 보여 줄지(❓ 판단 필요)
- 이야기 원고의 참고 자료(유튜브 링크 등)
- 포인트 단위(예: 문제당 10포인트) — 시연용 가안
