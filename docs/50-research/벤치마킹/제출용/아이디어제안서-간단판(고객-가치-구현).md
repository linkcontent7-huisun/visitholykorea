# 아이디어 제안서 — 하늘에서 빵이 내린다면

**대전 문화유산 하루 코스를 한 번에 접수하는 앱**  
**제안자**: visitholykorea (【대표자 이름】)

## 1. 한 줄 아이디어

**대전의 문화유산과 유명 로컬(성심당 빵, 계족산 황톳길)을 이야기로 이은 하루 코스를, 기관이 한 번 올리면 방문자가 앱에서 한 번에 접수한다.**

## 2. 고객은 누구인가

| 고객 | 누구 | 지금의 불편 |
|---|---|---|
| **돈을 내는 고객** | 프로그램을 여는 기관(성당·문화원·전시관)과 문화유산 활용사업을 신청하는 지자체(대전 중구·대덕구 등) | 프로그램을 열고, 알리고, 접수받고, 결과를 모으는 일을 따로따로 해야 한다 |
| **쓰는 사람** | 아이 동반 가족, 성인, 노인 동반 가족 | 대전에는 빵집 앞 대기 30분~3시간(성심당 하루 2만~3만 명)과 걸어서 닿는 문화유산이 있지만, 이를 이어 주는 체험과 접수를 찾기 어렵다(찾아본 범위) |

## 3. 고객에게 주는 가치

| 고객 | 받는 가치 |
|---|---|
| 기관·지자체 | 프로그램을 **한 번 등록하면** 접수 페이지, 안내 문자, SNS 카드가 만들어지고, **참가자 수·연령대·만족도가 한 화면에 모인다**(결과보고 자료로 사용) |
| 방문자 | ① **기다리는 시간이 이야기가 된다**(줄 사이 20분) ② **성인·아동·노인 수를 한 화면에서 바로 접수** ③ 조부모와 손주가 걸으며 묻는 **세대 대화**(3세대 질문 카드) |

체험 예시: **줄 사이 20분**(성심당 대기시간에 맞춘 오디오 이야기), **종지기를 찾습니다**(대흥동성당 종 이야기, 작은 종 기념품), **두 집 비교 관찰**(조선 선비의 동춘당과 선교사 사택, 한남대 선교사촌). 코스는 원도심 도보(대전역·성심당 → 대흥동성당 → 전시관)와 대덕구(계족산 황톳길 → 동춘당 → 한남대) 중 선택한다.

## 4. 바이브코딩으로 어떻게 구현하나

**이미 만든 것**: 성지 200여 곳 데이터, 출발지·시간 조건으로 코스를 짜는 기능(관광공사 정보를 실시간 호출), 순례 여권, AI 가이드, 6개 언어 화면. 웹·Android·iOS를 한 코드베이스로 지원(https://visitholykorea-app.vercel.app).

**이번에 새로 만들 5가지** (Claude Code와 Codex에 기능을 말로 설명하고, AI가 쓴 코드를 직접 실행해 확인하는 방식)

| # | 만들 것 | 만드는 방법(구상) |
|---|---|---|
| 1 | 프로그램 카드와 접수 화면 | 성인·아동·노인 수, 이동 편의, 동의 항목을 정해 말로 설명 → AI가 화면·저장 코드 작성 |
| 2 | 오디오 이야기 재생 | 원고는 AI가 초안, **사람이 출처를 확인해 확정**. 앱 안에서 재생 |
| 3 | 대기시간 → 이야기 추천 | 분 단위 입력에 맞춰 이야기 길이와 다음 장소를 고르는 **간단한 규칙**(AI 불필요) |
| 4 | 기관 화면: 등록과 집계 | 등록 폼 → 접수 목록 → 연령대·인원 집계 한 화면 |
| 5 | 결과 카드 공유 | 방문 결과를 이미지 카드로 만들어 SNS에 공유 |

**AI의 역할과 안전**: 앱 안의 AI 가이드는 우리가 모은 데이터 안에서만 답하고 없으면 "모른다"고 한다. 녹음은 기기 안에만 저장한다. 아동 이름·생년월일은 받지 않는다.

**본선(11/12) 시연 범위**: 줄 사이 20분(대기시간은 입력식)과 기관 등록→접수→집계.

## 5. 아직 확인하지 못한 것

성당·성심당·한남대·대덕구·중구와는 **협의 예정**이며 협의된 것은 없다. 계족산 "선비길"의 명칭·구간, 코스 간 이동 시간, 맨발 걷기의 어린이·노인 안전, 선교사촌 방문 가능 여부는 확인이 필요하다.
