# 도슨트 현장조사 매뉴얼

성지 입구부터 성당 내부까지, 순례객의 핸드폰이 도슨트가 되어 주는 기능을
만들기 위한 현장조사 절차다. **이 기능이 우리 앱의 차별점이다** — 성당은
건축·부조·스테인드글라스·조각상이 있는 박물관인데, 아무도 설명해주지 않는다.
비신앙인에게도 가치 있는 이야기를 들려주는 것이 목표다.

## 역할 분담

| | 담당 |
| --- | --- |
| 현장 이동·촬영·구술 | **사용자** (핸드폰) |
| 원고 작성·정리·저장·커밋 | **Claude** (같은 채팅에서) |
| 감수 (사실 확인) | 사용자, 나중에 몰아서 가능 |

## 현장에서 하는 법 — 이게 전부다

1. 핸드폰 Claude 앱 → `</>` 코드 → **새 세션** (visitholykorea 저장소)
2. 성지 입구에서: **"○○성지 도슨트 조사 시작"**
3. 포인트마다: **사진 찍어 올리고 + 아는 것을 말로(글로) 설명**
   - 설명이 없어도 된다 — 사진 속 안내판을 Claude 가 읽고, 모르는 건 모른다고 적는다
4. 다 돌았으면: **"조사 끝"** → Claude 가 정리·커밋·푸시까지 하고 요약을 보여준다

Claude 는 저장소의 `docent-survey` 스킬을 자동으로 알고 있으므로,
어느 세션에서 하든 같은 형식으로 쌓인다. **따로 가르칠 것 없다.**

## 무엇을 포인트로 잡는가

성지마다 6~12개가 적당하다. 흐름은 실제 동선을 따른다:

1. **입구** — 이 성지가 왜 성지인가 (여는 말)
2. **길** — 십자가의 길, 조형물, 순교탑
3. **성당 외부** — 건축 양식, 왜 이렇게 지었나, 종탑·벽돌·지붕
4. **성당 내부** — 제대, 스테인드글라스, 부조, 14처, 성상, 액자·유해
5. **부속 공간** — 경당, 박물관, 묘역, 기념관
6. **나가는 길** — 맺음말

## 원고 톤 — 도슨트지 설교가 아니다

- **구어체 존댓말.** TTS 가 그대로 읽는다. "~했습니다", "~보이시나요"
- **"무엇을"보다 "왜".** "스테인드글라스가 있습니다" ❌ →
  "제대 뒤 유리가 조개 모양인 건, 이 성당이 바닷가 순교터를 향해 서 있기 때문입니다" ⭕
- **비신앙인 기준.** 전례 용어는 한 번은 풀어준다 (제대 = 미사를 드리는 단)
- **모르면 모른다고.** 추측을 사실처럼 적으면 신뢰가 무너진다 — AI 가이드와 같은 원칙
- 한 포인트 3~6문장. 걸으면서 듣는 분량이다

## 데이터가 쌓이는 곳

`data/docent/<슬러그>/points.json` + `photos/`. 형식은 `data/docent/_템플릿.json`.
상태는 `draft → reviewed → published`.

## 웹 구현은 언제

조사가 3~5곳 쌓이면 화면을 붙인다 (성지 상세 → "도슨트 시작" → 포인트
카드 넘기며 TTS 재생). 데이터 없이 화면부터 만들면 더미가 생기므로
**조사 먼저, 화면은 데이터가 생긴 뒤** — 공모전 원칙(더미 금지)과 같다.
DB 테이블(`docent_points`)은 화면 붙일 때 JSON 을 임포트하는 식으로 간다.
