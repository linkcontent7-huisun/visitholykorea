# 오디오 도슨트 설계 (2026-08-27 승인)

박물관 오디오 가이드처럼, 성지를 둘러보는 동안 핸드폰이 역사·건축·예술품·전례를
소리로 설명해주는 기능. 사용자가 2026-08-27 대화에서 방향 B(플레이어 + 초안 원고)를
승인했다.

## 왜 지금 이 형태인가

- 도슨트 조사 체계(템플릿·매뉴얼·스킬)는 2026-08-20 에 완성됐지만 현장조사 데이터가
  **0곳**이다. 원래 계획은 "조사 3~5곳 후 화면 구현"이었는데, 그러면 개발이 사용자의
  현장 방문에 묶여 멈춘다.
- 그래서 **지금 있는 진짜 데이터(208곳의 소개·역사)로 먼저 동작하는 플레이어**를 만들고,
  현장조사 `points.json` 이 생기면 그 성지만 포인트별 투어로 풍부해지는 구조로 간다.
- 사진이 39/208곳뿐인 상황에서 소리 해설은 사진 공백을 메우는 강점이 된다.

## 사용자 경험

성지 상세의 "성지 이야기" 옆 읽어주기 버튼 자리를 **오디오 가이드 플레이어**로 바꾼다.

- 챕터 목록: 원고가 있으면 `여는 말 → 포인트 1..n → 맺음말`,
  없으면(대부분) `여는 말(소개) → 역사 → 맺음말` 자동 구성
- 재생 / 일시정지 / 이전·다음 챕터 / 현재 위치 표시
- 포인트 챕터에는 "찾아가는 위치"와 "눈여겨볼 것"을 글로도 병기
- 초안 원고 성지에는 **"초안 — 현장 확인 전"** 배지 (더미 금지 원칙: 상태를 정직하게 표시)
- 영어 모드: 기본 챕터는 기존 번역으로 읽고, 포인트 원고는 당분간 한국어만
- 음성은 브라우저 내장 TTS(`speechSynthesis`) 그대로. 성우 녹음·AI 음성은 범위 밖.

## 데이터

- 원고는 `data/docent/<성지>.json` (기존 `_템플릿.json` 형식). **DB 테이블 없음,
  마이그레이션 없음.** 앱이 빌드 시 Vite glob import 로 읽는다.
- 원고 상태: `draft`(현장 확인 전) → 사용자가 현장 검증하면 정식 전환.
- 초안 3곳: 절두산·명동·약현. 근거는 **DB 원문 + 교구·성지 공식 홈페이지**로 제한하고
  포인트마다 `sourceNote` 를 남긴다. 확인 안 되는 디테일은 쓰지 않는다
  (AI 답변을 DB 로 제한하는 기존 원칙과 같은 취지).

## 코드 구조

- `src/features/docent/` 새 feature
  - `lib/chapters.ts` — 성지 + 원고(있으면) → 챕터 목록 만드는 순수 함수 (테스트 대상)
  - `data/` — `data/docent/*.json` glob 로더
  - `components/DocentPlayer.tsx` — 플레이어 UI
- `src/pages/SiteDetailPage.tsx` — 기존 TTS 버튼을 플레이어로 교체
- 의존성 방향(`pages → features → shared`)과 앱 토큰(`app-*`·`brand-*`), rem 기반 크기 준수
