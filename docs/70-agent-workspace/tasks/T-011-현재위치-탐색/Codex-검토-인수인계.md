# Codex 검토 인수인계 — 현재 위치 기반 성지 탐색

작성: 2026-09-11 · 목적: Claude 작업안과 비교할 판단 근거 보존

## 1. 시작 전 확인한 상태

- 지도·길찾기 링크(카카오·티맵·네이버·구글·애플)는 이미 구현·테스트돼 있었다.
- 지도 화면은 전국 성지 조망용 SVG이며, 선택 카드에서 실제 길찾기 링크를 제공한다.
- 출발지는 지역 선택값(`origin`)만 있었고, `navigator.geolocation` 호출은 없었다.

## 2. Codex가 제안한 구현 원칙

- 위치 권한은 메뉴의 사용자가 누른 버튼에서만 요청한다. 페이지 진입·앱 시작 시 자동 요청하지 않는다.
- 좌표는 React 상태에만 둔다. localStorage·Supabase·분석 이벤트에 저장하거나 전송하지 않는다.
- 거리 계산은 `현재 GPS 좌표 → 기존 출발 지역 중심 좌표 → 전국 기본 순서`로 폴백한다.
- 권한 거부·브라우저 미지원·시간 초과·신호 불가를 안내하되 지역 선택 기능은 계속 쓸 수 있어야 한다.

## 3. 확인한 Claude 결과물

- 커밋 `dc2890c feat(location): GPS 현재 위치로 성지 거리 정렬하기`가 `main` 및 `origin/main`에 이미 반영돼 있었다.
- `SettingsProvider`가 GPS 좌표를 React 상태(`gpsLocation`)로만 보관하며, 5분 캐시·10초 제한·저정밀 요청을 사용한다.
- 메뉴에서 GPS 사용·해제를 제공하고, 홈·탐색·빈 여권 미리보기가 GPS 좌표를 지역 좌표보다 우선한다.
- 6개 언어 안내 문구와 기존 설정 목(mock)도 함께 갱신돼 있었다.

## 4. 비교 시 확인할 판단 기준

1. GPS 좌표가 브라우저 메모리 밖(localStorage, URL, DB, 서버 로그)으로 나가지 않는가.
2. 위치 권한 요청이 명시적 버튼 조작에서만 일어나는가.
3. 허용·거부·미지원·오류 뒤에도 기존 지역 선택과 거리 정렬이 깨지지 않는가.
4. 홈·탐색·여권의 거리 기준과 표기 문구가 같은 우선순위를 쓰는가.

## 5. 검증 결과

- `npm run verify` 실행: 타입 검사 통과, ESLint 오류 0건, 전체 테스트 통과.
- `router.tsx`의 Fast Refresh 경고 2건은 기존 경고이며 이번 위치 기능과 무관하다.
- 실제 기기에서 위치 허용·거부를 각각 한 번 눌러 보는 수동 QA는 Codex 세션에서는 수행하지 못했다.

## 6. 공유 작업공간 주의

- 이 문서를 쓸 당시 다른 작업자가 거리·주변 성지 관련 파일을 수정 중이었다.
- 그 미완료 변경은 비교 대상과 섞이지 않도록 커밋·푸시하지 않았다.
