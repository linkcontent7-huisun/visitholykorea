# 완료보고 — T-004 성지 상세 화면 재구성

- 작성: 2026-09-05 (지시자)
- 판정: **통과 (1차)**

## 무엇이 됐나

가장 구획이 많던 화면(최대 16개)을 정리했다. 완료 조건 7개 전부 검토자가
파일·화면 실측으로 통과시켰다. 개발 중 도슨트 재생이 아코디언 토글에
끊기는 실제 버그를 개발자가 스스로 찾아 `useMemo` 로 고쳤고, 지시서가
금지한 "도슨트 훅 내부 수정"은 건드리지 않았음을 검토자가 diff 로 확인했다.

제가 직접 화면으로도 확인했다: 스탬프 버튼이 굵은 보라 테두리로 확실히
구분되고, "방문 정보"는 그 성지에 실제로 있는 항목(들어가기 전 안내 ·
찾아가는 길 · 문의 · 주변 본당)만 미리보기에 나온다. 도슨트를 재생한
채로 아코디언을 열고 닫아도 `speechSynthesis.speaking` 이 계속 `true` 로
유지되는 것도 직접 확인했다.

## 지시자가 추가로 조사한 것 — 개발 콘솔의 "docentChapters is not defined"

검토자가 "제안"으로만 남긴 항목을 제가 직접 더 파봤다. 결론: **실제
소스 코드 결함이 아니라 이 테스트 환경(브라우저 자동화 샌드박스)의
HMR 웹소켓 연결 문제로 보인다.**

근거:
1. `docentChapters` 는 121행에서 선언되고 380행에서만 쓰인다 — 선언이
   사용보다 먼저다. 스코프·순서상 "정의되지 않음"이 날 이유가 코드
   자체엔 없다.
2. 검토자가 `npm run build` + `npm run preview`(실제 배포 방식과 동일,
   HMR 없음)로는 재현이 안 됨을 이미 확인했다.
3. 제가 재확인하는 중 같은 브라우저 탭에서 `WebSocket connection to
   'ws://localhost:3100/' failed` 가 152건 연달아 찍혔고, 곧이어 그
   탭 자체가 완전히 응답을 멈췄다(재접속도 안 됨) — **이 자동화
   브라우저와 Vite 개발 서버 사이의 연결 자체가 불안정하다는 독립적인
   증거**다. HMR(Hot Module Replacement)이 이런 상태에서 오래된 모듈을
   잘못 이어붙이면 이런 유령 같은 참조 오류가 날 수 있다.

**조치**: 근거 없이 코드를 고치지 않았다. 이미 구조적으로 맞는 코드를
"혹시 몰라서" 바꾸는 건 원칙에 어긋난다(요청되지 않은 변경). 대신 이
기록을 남겨서, 다음에 개발 서버에서 같은 에러를 보더라도 당황하지
않도록 했다. 배포판(실사용자가 보는 것)에는 영향이 없다.
