### 완료 조건 때문에 고친 것 (범위 밖이 아닌 이유)

지시서 완료 조건 5번째 항목 "도슨트를 재생한 상태에서 방문정보 그룹을 펼치거나 접어도
재생이 끊기지 않는지" 를 실제로 확인하다가, `useDocentPlayer`(수정 금지 대상)가
`chapters` 배열의 **참조**가 바뀌면 재생을 멈추고 처음으로 되감는 `useEffect`
(`[chapters]` 의존성)를 갖고 있는 것을 발견했다. 기존 코드는 `docentChapters` 를
매 렌더마다 `buildChapters(...)` 로 새로 만들어서, `SiteDetailPage` 의 아무 상태나
바뀌면(내가 추가한 `visitInfoOpen` 포함) 참조가 달라져 재생이 끊기는 구조였다.

`useDocentPlayer` 내부는 손대지 않고, `SiteDetailPage.tsx` 안에서 `docentChapters`
를 `useMemo` 로 감싸 참조를 고정하는 것으로 해결했다 — 이 파일은 원래 이번 작업의
수정 대상이고, 도슨트 컴포넌트/훅 내부는 그대로 뒀다.

### 확인 못 한 것

- 실제 로그인 계정으로 스탬프를 찍어서 "한 줄 남기기 입력창 → 저장 → 공유 버튼"
  까지 전체 흐름을 화면에서 끝까지 눌러보지는 못했다(로그인 정보 없음). 대신
  코드 상 조건(`stamped && !myStamp?.note && !noteDismissed`)과 공유 버튼 조건
  (`stamped &&`)은 옮기기 전과 동일하게 유지했음을 diff 로 확인했다.
- 브라우저 자동화 환경이 `speechSynthesis` 를 지원하지 않거나 모바일 뷰포트에서는
  이어폰 예절 가드가 걸려 실제 음성 재생/일시정지까지는 못 봤다. 대신 데스크톱
  크기(마우스 포인터로 인식되어 이어폰 가드를 건너뜀)에서 재생 버튼을 눌러
  `isPlaying` 상태(aria-label, `speechSynthesis.speaking`)로 재생 중임을 확인했다.
- 실기기(iOS/Android)에서의 확인은 못 했다.
- 무장애 정보(BarrierFreeCard)가 실제로 존재하는 성지를 찾지 못해, 미리보기 문구에
  "무장애 정보" 가 포함되는 경우는 코드 로직으로만 확인했고 화면에서 직접 보지는
  못했다(TourAPI 무장애 API 가 현재 403 승인 대기 상태라 어떤 성지를 넣어도 안 나옴).
