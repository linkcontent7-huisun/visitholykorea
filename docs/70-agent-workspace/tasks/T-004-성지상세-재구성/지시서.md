# T-004 · 성지 상세 화면 재구성 — 주인공을 스탬프로, 방문정보를 한 그룹으로

- 작성: 2026-09-05
- 담당: developer
- 근거: `docs/70-agent-workspace/tasks/T-002-화면단순화-조사/조사기록.md`
  "SiteDetailPage" 절 — 세로 구획이 최대 16개까지 쌓이고, 이 화면의 진짜
  주인공인 "순례 스탬프 찍기" 버튼이 12번째쯤에 다른 정보성 섹션과
  똑같은 무게로 묻혀 있다는 조사 결과.

## 목표

`src/pages/SiteDetailPage.tsx` 를 고쳐서 (1) 스탬프 찍기를 시각적으로
확실한 주인공으로 만들고 (2) 방문정보 성격의 섹션 5개를 한 그룹으로
묶어 스크롤 길이를 줄인다. 도슨트·스탬프·순례자이야기 등 기존 동작은
하나도 깨뜨리지 않는다 — **이 페이지는 이번 세션에서 이어폰 가드·다국어
사전·성당 예절 안내 등 공들여 만든 로직이 많다. 로직을 옮기지 말고
배치만 바꾼다.**

## 결정된 것 (다시 판단하지 말 것 — 오케스트레이터가 정함)

방문정보를 접었을 때 "안에 뭐가 있는지 미리 보이는" 쪽으로 정했다.
50대 이상이 주 사용자라(수요조사 실측 85%), "눌러봐야 뭐가 있는지 아는"
방식보다 "미리 보여서 안심되는" 방식이 접근성에 낫다고 판단했다.

## 완료 조건

- [ ] **스탬프 찍기 섹션을 시각적으로 구분한다.** 다른 섹션과 같은
      "보라 세로줄 + h2" 제목 스타일을 쓰지 않는다 — 배경색을 넣거나
      카드 테두리를 강조하는 등, 이 페이지에서 가장 먼저 눈에 띄게 만든다.
      **위치는 지금 그대로(성지 이야기 섹션 다음) 두어도 되고, 조금 더
      위로 당겨도 된다 — 시각적 강조가 핵심이지 순서 자체는 필수가 아니다.**
- [ ] **다음 5개 섹션을 "방문 정보" 라는 이름의 접이식 그룹 하나로 묶는다**:
      VisitEtiquette(들어가기 전 안내) · DirectionsCard(찾아가는 길) ·
      ContactCard(문의) · BarrierFreeCard(무장애 정보, 조건부) ·
      NearbyParishesCard(주변 본당). 각 컴포넌트 **내부는 수정하지 않는다**
      — 바깥을 감싸는 접이식 래퍼만 새로 만든다.
      - 접힌 상태에서 "찾아가는 길 · 문의 · 무장애 정보" 처럼 **안에 있는
        항목 이름을 짧게 미리 보여준다.** 성지마다 있는 항목이 다르므로
        (무장애 정보는 조건부) 실제로 그 성지에 존재하는 항목만 나열한다
        — 없는 걸 있는 것처럼 보여주면 안 된다(더미 금지 원칙).
      - 펼치면 5개 컴포넌트가 순서대로 그대로 나온다.
      - 기본 상태는 **접힘**으로 한다.
- [ ] **"기본 정보" 카드(주소+교구/감성태그)와 히어로 부제의 주소 중복을
      줄인다.** 완전히 삭제하지 않아도 된다 — 예를 들어 "기본 정보"
      카드에서 주소를 빼고 교구/감성태그만 남기는 정도로도 충분하다.
      DirectionsCard 의 주소는 "찾아가는 길" 목적이 분명하므로 그대로 둔다.
- [ ] **"순례 스탬프 카드 공유하기" 버튼을 스탬프 찍기 섹션 바로
      아래(또는 안)로 옮긴다.** 지금은 방문정보 섹션들 뒤에 있어서
      스탬프를 막 찍은 사람이 다시 스크롤해야 한다.
- [ ] 도슨트 플레이어(챕터 선택·재생 상태), 이어폰 예절 가드, 성지 이야기
      섹션, 한 줄 기록·사진 업로드, 순례자 이야기(신고 포함)는 **동작·조건
      전부 그대로 유지된다.** 특히 스탬프를 막 찍은 직후 나타나는 "오늘
      그곳은 어땠나요?" 입력창의 표시 조건을 건드리지 않는다.
- [ ] `npm run verify` 통과
- [ ] 모바일 375px 에서 다음을 실제로 확인한다:
      - 사진·도슨트·방문정보가 전부 있는 성지 하나(WYD 대상지 등)로 열어서
        전체 스크롤 길이가 실제로 줄었는지
      - 방문정보 그룹을 펼치고 접었을 때 5개 컴포넌트가 정상 렌더되는지
      - 도슨트를 재생한 상태에서 방문정보 그룹을 펼치거나 접어도 재생이
        끊기지 않는지 (DocentPlayer 상태와 아코디언 상태가 서로 안전한지)
      - 스탬프를 찍는 흐름(로그인 → 스탬프 찍기 → 한 줄 남기기 → 공유
        버튼 위치)이 여전히 자연스러운지

## 범위 밖 (하지 말 것)

- VisitEtiquette·DirectionsCard·ContactCard·BarrierFreeCard·
  NearbyParishesCard **내부 로직/문구를 고치지 않는다** — 배치만 바꾼다
- 도슨트 플레이어·이어폰 가드·스탬프·순례자이야기 기능을 새로 추가하거나
  로직을 바꾸지 않는다
- 다른 화면은 건드리지 않는다
- RecordsPage·T-002 조사에서 나온 다른 화면 관련 항목은 이번 범위가 아니다
- 이 성지 저 성지 데이터를 새로 만들지 않는다(더미 금지)
