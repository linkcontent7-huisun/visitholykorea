# T-017 — 순례자 후기: 사진 여러 장 업로드 + 성지 상세 「후기 보기」

작성 2026-09-13 · 담당 Codex · 지시자 Claude

## 목표

순례자가 성지 한 곳에 **사진 여러 장**(모바일 5장·PC 10장)과 한 줄 감상을 남기고, 다른 사람이 그 성지 상세에서
「후기 보기」를 누르면 같은 장소의 모든 후기(사진·한 줄·날짜)를 볼 수 있게 한다.
지금은 스탬프당 사진 1장(`pilgrimage_stamps.photo_url`)이고, 「순례자 이야기」 절이 최대 6개만 보여준다.

## 현재 구조 (읽고 시작)

- `pilgrimage_stamps` (user_id, site_id 유일) · `photo_url` 1장 · `note` · 관리자 숨김 `note_hidden`(있으면) — `supabase/migrations/20260819000000_add_stamp_note.sql`, `20260901000000_add_pilgrim_photos.sql`
- 공개 뷰 `site_visit_notes` (site_id, note, photo_url, created_at, id) — 이름·user_id 없이 공개
- 업로드 `attachStampPhoto` (`src/features/passport/api/stamps.repository.ts`, 경로 `<uid>/<siteId>.jpg`), 축소 `src/shared/lib/photo.ts` (긴 변 1600 · JPEG 82%)
- 상세 화면 `src/pages/SiteDetailPage.tsx` — 스탬프 카드(약 173행 `shrinkPhoto`), 「순례자 이야기」 절(약 796행 `visitNotes`)

## 만들 것

### A. DB — `supabase/migrations/20260913110000_add_stamp_photos.sql` (적용은 지시자)

- 표 `stamp_photos`: id uuid pk, stamp_id uuid → pilgrimage_stamps(id) on delete cascade, url text not null, position int not null, created_at; unique (stamp_id, position)
- RLS: select 공개(후기로 보여주니까), insert/update/delete 는 그 스탬프의 주인만 (`exists (select 1 from pilgrimage_stamps p where p.id = stamp_id and p.user_id = auth.uid())`)
- 기존 `photo_url` 이 있는 스탬프는 `stamp_photos` position 1 로 **복사** (원본 열은 지우지 않는다 — 다른 화면이 아직 쓴다)
- 뷰 `site_visit_notes` 를 바꿔 `photos text[]`(position 순) 를 함께 돌려준다. 관리자가 숨긴 글(`note_hidden = true` 등 기존 숨김 열이 있으면)은 **사진도** 빠지게 한다. 기존 `photo_url` 열은 그대로 두고 `photos` 를 추가한다
- `src/shared/types/database.ts` 에 `StampPhotoRow` 추가

### B. 업로드 — 모바일 5장 / PC 10장, 크기 자동

- `src/shared/lib/photo.ts` 의 `shrinkPhoto(file, opts?)` 에 `{ maxEdge, quality }` 옵션 추가. 기본값은 지금 그대로(1600/0.82)
- `src/shared/lib/photo.ts` 에 `photoPolicy()` 추가: `window.matchMedia('(pointer: coarse)').matches || window.innerWidth < 768` 이면
  `{ maxCount: 5, maxEdge: 1280, quality: 0.8 }`(카카오톡 일반 화질 수준), 아니면 `{ maxCount: 10, maxEdge: 1600, quality: 0.82 }`
- `stamps.repository.ts` 에 `uploadStampPhotos(stampId, siteId, blobs[])`: 경로 `<uid>/<siteId>/<n>.jpg` (n = 1..), 올린 뒤 `stamp_photos` 에 insert. 첫 장은 기존처럼 `photo_url` 에도 넣어 옛 화면과 호환
- 상세 화면 스탬프 카드의 사진 고르기 `<input type="file" accept="image/*" multiple>` — 정책 장수를 넘으면 앞에서 자르고 "최대 N장" 안내. 올리기 전 미리보기 격자, 개별 삭제(×). 안내 문구: 「올린 사진과 한 줄은 이 성지 후기로 다른 순례자에게 보입니다」
- 문구는 전부 `dictionary.ts` 6개 국어 키로 (`reviewPhotosMax`, `reviewPublicNotice`, `reviewsTitle`, `reviewsShow`, `reviewsHide`, `reviewsEmpty` 등)

### B-2. 「기록」 탭에서도 올린다 (2026-09-13 사장님 추가)

- `src/pages/RecordsPage.tsx` 의 내 스탬프 목록에서 각 스탬프 카드에 **「사진 올리기 +」** 버튼. 누르면 같은 `multiple` 파일 선택 →
  같은 정책(모바일 5·PC 10) → `uploadStampPhotos`. 이미 올린 사진은 작은 격자로 보이고 × 로 지울 수 있다(`stamp_photos` delete, 스토리지 파일도 삭제)
- 한 줄 감상도 여기서 고칠 수 있으면(기존 note 수정 함수가 있으면) 같이 두고, 없으면 상세 화면 스탬프 카드로 안내 링크만
- **안내문**(6개 국어 키 `reviewModerationNotice`): 「장소와 관련 없거나 부적절한 내용·사진은 관리자 판단으로 후기에 공개하지 않을 수 있습니다」 — 업로드 칸 아래와 후기 목록 맨 아래 두 곳

### B-3. 관리자 콘솔 — 사진 여러 장이어도 대표 사진 승인이 되게

- 기존 `admin_pending_photos` 뷰·`admin_set_photo_featured` RPC 는 스탬프당 사진 1장(`photo_url`) 기준이다.
  뷰를 `stamp_photos` 기준(사진 한 장 = 한 행, `photo_id`)으로 바꾸고, RPC 가 `photo_id` 를 받아 그 사진을 성지 대표 사진으로 승인하게 한다.
  화면 `src/pages/AdminPage.tsx` 의 사진 승인함은 격자에 사진마다 「대표로」 버튼. 기존 동작(승인·해제)이 그대로 되어야 한다
- 관리자 화면 외 다른 관리자 기능은 건드리지 않는다

### C. 상세 화면 「후기 보기」

- 「순례자 이야기」 절을 개편: 제목 `순례자 후기 (N)` + 버튼 「후기 보기」/「접기」. 접힌 상태가 기본이고, 접혀 있을 때는 첫 후기 한 줄만 미리보기
- 펼치면 그 성지의 **모든** 후기 (limit 없이, 최신순): 사진 격자(가로 3열, 누르면 크게), 한 줄, 날짜, 기존 「신고」 버튼 유지
- `getSiteNotes(siteId, limit)` 의 limit 기본값을 없애거나 `all` 옵션 추가. 캐시 키 `queryKeys.passport.siteNotes` 그대로
- 위치: 「방문 정보」 절 **아래**, 스탬프 카드 위 — "모든 설명 뒤에 후기". 목록 맨 아래에 `reviewModerationNotice` 안내문

## 완료 조건 (어떻게 확인)

1. 마이그레이션 SQL 이 두 번 적용돼도 오류 없음(`if not exists`, `on conflict`), 복사 `insert … select` 에 `where not exists`
2. `npm run verify` 통과 + 새 로직 테스트: `photoPolicy()` 모바일/PC 판정, `shrinkPhoto` 옵션 반영 (jsdom 에서 canvas 가 없으면 옵션 전달만 검사)
3. `npm run dev` 로 띄워 헤드리스 크롬 400px 로 성지 상세를 찍어 「순례자 후기」 절과 「후기 보기」 버튼이 보이는 스크린샷을 개발기록 폴더에 남긴다 (로그인 없이 보이는 부분까지)
4. 바꾼 파일·추가 키 목록을 표로
5. 관리자 승인함: 사진 2장 이상인 스탬프에서 두 번째 사진을 「대표로」 눌러 `holy_sites.image_url` 이 바뀌는 흐름을 코드로 설명(로그인 없이는 실행 못 함)
