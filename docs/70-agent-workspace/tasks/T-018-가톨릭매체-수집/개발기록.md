- 범위는 기사 표 마이그레이션, `scripts/crawl/`, 기사 연구 결과, 이 기록 및 DB 타입으로 한정했다. `.env.local`과 DB 적용 명령은 읽거나 실행하지 않는다.

## 구현 및 검증

- `articles`, `article_sites`, `site_artworks` 마이그레이션과 공개 읽기·admin/editor 쓰기 RLS를 추가했고, DB 타입 세 개를 맞췄다. 적용은 하지 않았다.
- `python -m py_compile scripts/crawl/crawl.py`는 통과했다.
- `python scripts/crawl/crawl.py --source catholicnews --since 2021-09-01 --limit 300` 및 cpbc 명령을 실제 실행했다. 두 사이트의 robots.txt가 각 지시서의 사이트맵 URL을 허용하지 않아 각각 새 기사 0건으로 끝났으며, 정책을 우회하지 않았다.
- JSONL 검사 결과는 `기사 0건: 인용문 200자 이하·본문 필드 없음`이었다. 본문을 저장하는 필드는 수집기 출력에 만들지 않았다.
- `npx tsx scripts/crawl/load.ts --dry-run`과 `npm exec -- tsx scripts/crawl/load.ts --dry-run`은 모두 실행 환경의 Node `uv_os_get_passwd ENOMEM` 오류로 시작 전에 실패했다. DB에는 연결하거나 변경하지 않았고, 환경이 안정된 뒤 지시자가 같은 dry-run 명령을 다시 실행해야 한다.

## 완료 조건 판단

- 수집기·마이그레이션·적재기 형식은 만들었지만 robots 정책 때문에 100건·20곳 매칭 완료 조건은 충족할 수 없었다.
- `npm run verify`는 typecheck와 lint(경고 2개, 오류 없음)까지 통과했다. 테스트 시작 시 Vite/esbuild가 상위 디렉터리 읽기 권한을 받지 못해 `Cannot read directory "..": Access is denied`로 실패했으며, 이번 범위 파일과 무관한 실행 환경 문제다.
