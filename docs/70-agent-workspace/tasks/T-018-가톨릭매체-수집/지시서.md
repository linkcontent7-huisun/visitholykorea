# T-018 — 가톨릭 매체 기사 수집기 + `articles`·`site_artworks` 표

작성 2026-09-13 · 담당 Codex(두 번째 워커) · 지시자 Claude

## 목표

가톨릭뉴스 지금여기(catholicnews.co.kr)와 cpbc 가톨릭평화방송(news.cpbc.co.kr)에서 **순례 코스 · 한국 성지·성당 순례 기록 ·
성모상 · 스테인드글라스 · 성물 · 조각 · 예술품** 기사를 찾아, 저작권 선 안의 정보만 DB 에 넣는다.
나중에(T-019) 이 자료로 성지별 오디오 도슨트 원고 초안을 새로 쓴다.

## 저작권·예의 — 반드시

- **본문 전체를 저장·커밋하지 않는다.** 저장하는 것: 제목 · URL · 날짜 · 매체 · 기자명(있으면) · **우리가 쓴 요약 300자 이내** ·
  **인용 200자 이내**(따옴표 표시용) · 추출한 사실(성지명·인물·연도·작품명·작가) · 주제 태그
- 원문 HTML 은 `scripts/crawl/.cache/`(gitignore) 에만 두고 지운다
- 가톨릭신문(catholictimes.org)은 robots.txt 로 AI 봇을 막았다 → **자동 수집 제외.** 대신 `scripts/crawl/manual-urls.txt` 에 사람이 적은 URL 만 같은 형식으로 처리한다(없으면 빈 파일)
- 요청 간격 최소 1.5초, `User-Agent: VisitHolyKorea-research/1.0 (+https://github.com/linkcontent7-huisun/visitholykorea)`, robots.txt 준수, 실패는 3번까지만 재시도
- 최근 **5년**(2021-09 이후) 기사만

## 만들 것

### 1. 마이그레이션 `supabase/migrations/20260913120000_add_articles_artworks.sql` (적용은 지시자)

`articles`: id uuid pk · source text check in ('catholicnews','cpbc','catholictimes','other') · url text unique not null · title text not null ·
published_at date · author text · summary text (우리 요약) · excerpt text (≤200자) · topics text[] (아래 태그 중) · facts jsonb (아래 형식) ·
fetched_at timestamptz default now() · status text default 'new' check in ('new','reviewed','used','skip')

`article_sites`: article_id → articles(id) on delete cascade · site_id → holy_sites(id) on delete cascade · confidence real (0~1) · pk (article_id, site_id)

`site_artworks`: id uuid pk · site_id → holy_sites(id) · kind text check in ('statue','stained_glass','relic','sculpture','painting','architecture','other') ·
title text not null · artist text · year text · description text (우리가 쓴 2~3문장) · article_id → articles(id) on delete set null · created_at
— 성모상·스테인드글라스·성물·조각·회화·건축을 성지별로 모은 표. 도슨트 「볼거리」 포인트의 원천이 된다

RLS: 세 표 모두 읽기 공개, 쓰기는 `public.admin_role() in ('admin','editor')`. `src/shared/types/database.ts` 에 타입 3개.

### 2. 수집기 `scripts/crawl/` (Python 3, `requests` + `beautifulsoup4` + `lxml` — `scripts/crawl/requirements.txt`)

- `crawl.py --source catholicnews|cpbc|manual --since 2021-09-01 --limit N`
  1. 사이트맵(`/sitemap.xml`, `https://news.cpbc.co.kr/seo?type=basic_sitemap`)에서 기사 URL 을 모은다
  2. 제목·URL 에 1차 키워드가 있는 것만 본문을 받는다: `순례, 성지, 성당, 성모상, 스테인드글라스, 성물, 조각, 성미술, 유물, 순교, 도보, 코스, 걷기, 성당 건축, 제대, 십자가의 길, 성화`
  3. 본문에서 사실을 뽑는다 → `facts`: `{"sites":[…성지명…], "people":[…], "years":[…], "artworks":[{"title","artist","kind"}], "route_stops":[…순서…]}`
     성지명은 `data/exports` 가 아니라 **DB 의 `holy_sites.name` 208개**(지시자가 `scripts/crawl/site-names.json` 으로 넣어 둠)와 부분 일치로 잡는다
  4. `summary` 는 본문을 그대로 자르지 말고 **문장 재구성**(기사 첫 두 문단의 요지, 300자). `excerpt` 는 성지 관련 핵심 한 문장 200자 이내 그대로
  5. 주제 태그 `topics`: `pilgrimage_route`(코스 소개), `pilgrimage_record`(순례기·탐방기), `statue`, `stained_glass`, `relic`, `sculpture`, `artwork`, `architecture`, `shrine_news`(그 밖의 성지 소식)
  6. 결과를 `data/research/articles.jsonl` 에 한 줄 한 기사로 쓴다(커밋 대상 — 본문 없음). 이미 있는 URL 은 건너뛴다
- `load.ts`(tsx, `scripts/crawl/load.ts`) — `articles.jsonl` 을 읽어 `articles`·`article_sites`·`site_artworks` 에 upsert (`scripts/db-migrate.ts` 와 같은 접속 방식). **실행은 지시자.**

### 3. 결과 보고 `data/research/articles-요약.md`

매체별 수집 수 · 주제별 수 · 성지 매칭 수(매칭 안 된 기사 수도) · 상위 20개 성지(기사 수) · 예술품 후보 수

## 완료 조건

1. `python scripts/crawl/crawl.py --source catholicnews --since 2021-09-01 --limit 300` 과 `--source cpbc` 를 실제로 돌려 `articles.jsonl` 에 **합계 100건 이상**, 매칭된 성지 20곳 이상 → 요약 파일을 개발기록에 붙인다
2. `articles.jsonl` 의 어떤 행에도 `excerpt` 가 200자를 넘지 않고, 본문 필드가 없다 — 검사 스크립트 결과를 붙인다
3. `load.ts` 는 `--dry-run` 으로 넣을 행 수만 출력하는 모드가 있고, 그 출력이 개발기록에 있다
4. `npm run verify` 통과 (Python 은 `python -m py_compile scripts/crawl/crawl.py`)
5. 바꾼 파일 표
