# T-032 — 성지 이름·소개·역사를 es·fr·pt·it 로 번역한다 (206곳)

작성 2026-09-21 · 담당: Codex (지시서만 보고 일한다) · 검수·DB 반영: Claude

## 왜

`holy_site_translations` 표에 영어(en) 206행만 있고 es·fr·pt·it 는 0행이다(2026-09-21 01:10 실측).
그래서 스페인어 화면에서 **성지 이름**과 상세 맨 위 **인용문(소개)** 이 영어로 떨어진다.
오디오 가이드·성지 이야기는 6개 국어가 다 있다 — 이 작업은 그 나머지다.

## 입력 파일 (이미 만들어 둠)

`data/translations/{es,fr,pt,it}-all.todo.json` — 언어당 206항목. 각 항목:

```json
{
  "siteId": "…",
  "diocese": "대전",
  "source":   { "name": "갈매못 순교성지", "description": "한국어 원문…", "history": "…", "location": "…" },
  "sourceEn": { "name": "Galmaemot Martyrdom Shrine", "description": "영어 번역(검수됨)…", "history": "…", "addressRomanized": "…" },
  "target":   { "name": "", "description": null, "history": null, "addressRomanized": null }
}
```

**`target` 만 채운다.** `source`·`sourceEn` 은 절대 고치지 않는다.

## 번역 기준

1. **`sourceEn`(영어)을 기준으로 옮기고, 뜻이 애매하면 `source`(한국어)를 본다.** 영어는 사람이 검수한 것이고 고유명사 로마자 표기가 확정돼 있다.
2. **고유명사는 영어의 로마자 표기를 그대로 쓴다.** Galmaemot, Kim Taegon, Daveluy, Byeongin, Naepo … 언어별로 바꾸지 않는다.
   성인 세례명만 각 언어 관용 표기(Andrew→Andrés/André/André/Andrea, Paul→Pablo/Paul/Paulo/Paolo, Luke→Lucas/Luc/Lucas/Luca, Peter→Pedro/Pierre/Pedro/Pietro).
3. **연도·날짜·숫자는 하나도 빠뜨리지 않는다.** 검사기가 영어 원문의 연도가 target 에 없으면 잡는다.
4. 종교 용어는 각 언어 가톨릭 관용어: martyrdom shrine → santuario de los mártires / sanctuaire des martyrs / santuário dos mártires / santuario dei martiri, Vicar Apostolic → vicario apostólico 등.
5. `addressRomanized` 는 **영어 값을 그대로 복사**한다 (주소는 번역하지 않는다 — 택시 기사에게 통해야 한다).
6. 문체: 순례자에게 읽어 주는 안내문. 존중하되 딱딱하지 않게. 영어 문장 구조를 억지로 따르지 말고 그 언어답게.

## 진행 방법 — 한 번에 다 하지 말 것

- **언어 하나씩, 교구(`diocese`) 단위로** 채우고 저장한다. 파일이 크니 항목을 통째로 다시 쓰지 말고 `target` 만 바꾼다.
- 한 교구를 마칠 때마다 검사기를 돌린다:
  ```bash
  npm run translate:check -- data/translations/es-all.todo.json
  ```
  `[영어 그대로]`·`[한글 섞임]`·`[연도 누락]`·`[언어 의심]` 이 나오면 **그 항목을 고치고 나서** 다음 교구로 간다. `[빈 이름]` 은 아직 안 한 곳이니 무시.
- 순서: **es → fr → pt → it.** 한 언어가 끝나면(빈 이름 0) 그 파일은 완료다.
- 중간에 멈춰도 된다 — 채운 만큼만 DB 에 넣을 수 있다(import 가 빈 칸은 건드리지 않음). 멈추면 어디까지 했는지 보고서에 적는다.

## 완료 조건

1. 네 파일 모두 `npm run translate:check` 가 **문제 0건** (빈 이름 0 포함). 출력을 보고서에 붙인다.
2. `sourceEn.description` 이 있는 항목은 `target.description` 도 있다. `history` 도 같다. (검사기 첫 줄의 "소개 채움" 수 = 영어에 소개가 있는 수)
3. `node -e "JSON.parse(require('fs').readFileSync('data/translations/es-all.todo.json','utf8'))"` 네 파일 모두 통과.
4. 보고서 `docs/70-agent-workspace/tasks/T-032-성지이름-소개-4개국어/개발기록.md`: 언어별 채운 수, 검사기 출력, 번역하면서 판단이 필요했던 것(고유명사 표기 등) 목록, 못 한 것.
5. **커밋하지 않는다.** Claude 가 검사기를 다시 돌리고 `npm run translate:import` 로 DB 에 넣은 뒤 커밋한다.

## 범위 밖

- DB 접근 (`SUPABASE_DB_URL` 쓰지 않는다). `scripts/translation-import.ts` 를 돌리지 않는다.
- `en-*.todo.json`, `data/docent/`, `src/` — 건드리지 않는다.
- 서브에이전트 사용 금지. 낮은 추론 수준 금지 — 번역 품질이 곧 신뢰다.
- **번역은 Codex 자신이 쓴다.** Ollama 등 로컬 모델(`hermes3` 8B 가 깔려 있다)·외부 번역 API·번역 스크립트로 생성하지 않는다.

  틀리고, 그 오역은 검사기가 못 잡는다. 시간이 걸려도 직접 쓴다.
