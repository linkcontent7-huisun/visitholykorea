# T-030 — 화면 문구가 6개 국어를 빠짐없이 갖는지 검사한다

작성 2026-09-20 · 검사 담당: 별도 AI 세션 (이 문서만 보고 일한다)

## 목표 (한 문장)

지구본 아이콘으로 언어를 바꿨을 때 **한국어·영어가 남아 있는 화면과 문구를 전부 찾아 목록으로 만든다.**
고치지 않는다. 찾아서 적는 것까지가 이 일이다.

## 먼저 알아야 할 구조 (다시 짜지 말 것)

6개 국어(ko·en·es·fr·pt·it) 구조는 이미 있다. 세 층으로 나뉜다.

| 층 | 무엇 | 파일 |
| --- | --- | --- |
| ① 화면 문구 사전 | 버튼·제목·안내문. `t('키')` 로 꺼내 쓴다 | `src/shared/i18n/dictionary.ts` |
| ② DB 번역표 | 성지 이름·소개·역사 | `holy_site_translations` (앱은 `src/features/sites/hooks/use-site-translation.ts` 로 읽음) |
| ③ 값 대응표 | 분류·감정 태그처럼 DB 값 자체가 한국어인 것 | `src/shared/i18n/domain-labels.ts` |

문제는 구조가 아니라 **구조를 안 탄 문장**이다. 그 문장들을 찾는다.

## 검사 4가지 — 각각 명령을 그대로 돌리고 결과를 적는다

작업 폴더: 저장소 루트. 시작 전 `git pull`. 검사 1~3 은 코드만 보면 되고, 검사 4 는 브라우저가 필요하다.

### 검사 1. 사전에 있지만 es·fr·pt·it 칸이 영어를 복사해 둔 문구

사전 테스트("모든 문구가 6개 언어를 갖는다")는 **칸이 비었는지만** 본다. es 칸에 영어를 그대로 넣어 두면 통과한다.
그래서 언어별로 영어와 똑같은 줄을 센다.

```bash
for L in es fr pt it; do
  echo "== $L =="
  paste <(grep "^    en: " src/shared/i18n/dictionary.ts | sed 's/^    en: //') \
        <(grep "^    $L: " src/shared/i18n/dictionary.ts | sed "s/^    $L: //") \
    | awk -F'\t' '$1==$2 && length($1)>8' | cut -f1
done
```

- `length($1)>8` 은 "Facebook", "KO" 같이 언어를 안 타는 짧은 값을 빼기 위한 것이다.
  결과에 그런 고유명사가 섞이면 목록에서 빼고 "제외한 것"으로 따로 적는다.
- **2026-09-20 기준값: es 약 55줄.** 거의 「오늘의 성지 일정」 화면 문구였다. 이보다 크게 다르면 명령이 잘못 돈 것이니 다시 본다.
- 결과에는 영어 문장만 나온다. **어느 키인지** 적으려면 그 문장으로 `dictionary.ts` 를 검색해 키 이름(`todayPlan` 같은 것)을 함께 적는다.

### 검사 2. 사전을 안 거치고 한글이 직접 박힌 화면

```bash
grep -rnP --include=*.tsx --exclude=*.test.tsx \
  "^\s*[^/*].*(>|=\s*[\"'\`]|\?\s*[\"'\`]|:\s*[\"'\`])[^<{}]*[가-힣]" \
  src/pages src/features src/app src/shared/components | cut -d: -f1 | sort | uniq -c | sort -rn
```

나온 파일마다 **줄을 직접 열어** 아래 넷 중 무엇인지 가른다. 주석과 내부 값은 문제가 아니다.

| 종류 | 예 | 판정 |
| --- | --- | --- |
| 주석 | `// 사장님 지적 2026-09-20 …` | 무시 |
| 내부 값(화면에 안 나감) | `useState('전체')`, `row.label !== '문의'` | 무시 — 단, 그 값이 화면에 찍히는지 한 번 확인 |
| 관리자 전용 화면 | `AdminPage`, `AdminSitePage`, `AdminGate` | "관리자용, 한국어 유지" 로 따로 적고 끝 |
| **이용자 화면에 나가는 한글** | FAQ 질문·답, 약관 본문, 버튼 글자 | **목록에 올린다** |

- **2026-09-20 기준값:** `FaqPage`·`TermsPage`·`PrivacyPage` 가 한국어만, 그 밖에 소수.

### 검사 3. 한국어·영어 둘로만 가른 곳 (나머지 4개 언어는 영어로 떨어짐)

```bash
grep -rnE --include=*.ts --include=*.tsx --exclude=*.test.* \
  "language === 'ko' \?|ko \? '|isKo \?" src
```

- **2026-09-20 기준값: 17곳 / 11파일.** 이 중 훅(`use-*.ts`)이나 `chapters.ts` 처럼 데이터 폴백을 고르는 자리는
  의도된 것일 수 있다 — 줄을 열어 **화면 문구를 둘로 가른 것만** 목록에 올린다 (`AccountPage` 가 대표).

### 검사 4. 실제 화면에서 눌러 본다 (필수 — 코드 검사만으로 "됐다"고 하지 않는다)

배포 주소 `https://visitholykorea.com` 또는 로컬 `npm run dev`.
개발자 도구 콘솔에서 `localStorage.setItem('vhk_language','es')` 후 새로고침하면 스페인어가 된다
(지구본 버튼을 눌러도 된다). **스페인어 하나로만** 다음 화면을 돌며 한글·영어가 보이면 화면 이름과 문구를 적는다.

홈 → 성지 찾기(목록) → 성지 상세 하나 → 오디오 가이드 재생 → 지도 → 오늘의 성지 일정(끝까지) →
마음 나침반 → 메뉴 → FAQ → 약관 → 개인정보 → 로그인 화면

스크린샷은 `docs/70-agent-workspace/tasks/T-030-6개국어-누락-검사/screenshots/` 에 화면 이름으로 저장한다.

## 완료 조건 — 이것이 다 있어야 끝

같은 폴더에 `검사결과.md` 를 만들고 아래를 채운다.

1. 검사 1 결과: **키 이름 + 영어 문장 + 어느 화면인지** 표. 언어별 개수.
2. 검사 2 결과: 파일별 "무시 / 관리자용 / 목록" 판정과, 목록에 올린 줄의 실제 문구.
3. 검사 3 결과: 17곳 각각 "의도된 폴백 / 고쳐야 할 화면 문구" 판정.
4. 검사 4 결과: 화면별 "이상 없음 / 한글·영어 남음(문구 적기)" + 스크린샷 파일명.
5. 맨 위에 **요약 표**: 고쳐야 할 것을 화면 단위로 묶어 개수와 함께. 예) 「오늘의 성지 일정 — 사전 55키 영어 그대로」.
6. 명령을 돌린 날짜·시각과 `git log -1 --oneline` 결과(어느 커밋 기준인지).

확인 못 한 것은 추측하지 말고 "확인 못 했다" 라고 적는다.

## 범위 밖 (하지 말 것)

- **고치지 않는다.** 사전에 번역을 채우거나 `t()` 로 바꾸는 것은 다음 작업(T-031)이다.
- 구조를 바꾸자는 제안을 쓰지 않는다. 구조는 이미 있다.
- DB 번역(성지 소개·오디오 가이드)은 9/20 SQL 로 206곳×6 완비를 확인했다. 다시 세지 않는다.
- 관리자 화면(`Admin*`)은 한국어 유지가 방침이다. 번역 대상에 넣지 않는다.
- 커밋은 `검사결과.md` 와 스크린샷만. `main` 에 직접 커밋하지 않고 `audit/i18n-0920` 같은 브랜치에서 한다.
