# T-022 — 「마음 나침반」을 「오늘의 성지 일정」으로 바꾼다

작성 2026-09-15 · 사장님과 1문1답으로 결정한 내용을 그대로 옮겼다. 아직 착수하지 않았다.

> ⚠️ **기능 동결일(9/14)이 지났고 제출은 9/21 16:00 다.** 이 작업은 화면·로직을 모두 건드린다.
> 착수 여부는 `이어서-할-일.md` 「사장님 판단이 필요한 것」에 올려 두었다.
> 착수한다면 아래 「단계」의 1·2 만 제출 전에 하고, 3·4 는 제출 후로 미루는 것을 권한다.

## 목표 한 문장

질문 6개에 답하면 **성지 한 곳을 중심으로 한 하루 일정(오전 성지 → 점심 → 오후 관광지)** 을 보여 주고,
마음에 안 들면 답을 다시 하지 않고 **다른 성지로 갈아탈 수 있다.**

## 왜 바꾸는가 (2026-09-15 코드 실측)

| 문제 | 근거 |
| --- | --- |
| 이름 「마음 나침반」이 무슨 기능인지 안 읽힌다 | 나침반→방향→추천 이라는 비유를 사용자가 스스로 풀어야 함. 50대 이상 85%, 외국어 6개 |

## 결정 사항 (전부 사장님 확정)

### 1. 이름

| 자리 | 지금 | 바꿀 값 |
| --- | --- | --- |
| 홈 큰 카드 제목 (`compassTitle`, `HomePage.tsx:285`) | 마음 나침반 | **마음 상태로 고르는 오늘의 성지 일정** |
| 홈 히어로 알약 버튼 (`HomePage.tsx:201`) | 마음 나침반 | **오늘의 성지 일정** (같은 키를 쓰고 있으므로 키를 둘로 나눈다) |
| 퀴즈 상단 작은 라벨 (`HealingQuiz.tsx:294`) | 마음 나침반 | 오늘의 성지 일정 |

- 라우트 경로(`paths.compass`)·코드 식별자·`compass_*` 키 이름은 **바꾸지 않는다.** 화면 문구만.
- 6개 언어 값을 모두 고친다. 첫 화면 인사말 「지금, 어떤 마음으로 여기 오셨나요? …」 는 그대로 둔다 (사장님 OK).

### 2. 질문 — 8개 → 6개

| 새 순번 | 질문 | 옛 순번 | 결과에 미치는 영향 |
| --- | --- | --- | --- |
| 1 | 지금 마음에 가장 가까운 색 (5개 이모지) | 1 | **성지 선택** (`emotion`) |
| 2 | 요즘 어떤 것에 마음을 많이 쓰고 계세요? | 2 | 결과 첫 문장 (`CONCERN_OPENER`) — 성지는 안 바꾸지만 "내 얘기를 들었다"는 느낌을 주므로 **남긴다** |
| 3 | 어디서 출발하세요? | 3 | 거리 정렬 + 반경 기준점 |
| 4 | 오늘 얼마나 시간을 낼 수 있으세요? — **반나절 · 하루 · 1박2일 이상** | 6 | **반경** + 일정 줄 수 (아래 3항) |
| 5 | 이번 길은 몇 분이 함께하세요? | 7 | 결과 문장 (`PARTY_NOTE`). 옛 Q5 의 혼자/함께 의미를 여기로 흡수 |
| 6 | 마음에 담아두고 싶은 말 (건너뛰기 가능) | 8 | 저장만 |

**뺀 것**
- 옛 Q4 성별 — 묻지 않는다. "결과에 표시만" 하려 했으나 성별 정보(`target_gender`)는 `catholic_directory`(피정의집·수도회) 에만 있고 3줄 일정에는 붙을 자리가 없다. **나중에 「근처 피정의집」 줄이 생기면 그때 붙인다.**
- 옛 Q5 참여 방식(침묵형·나눔형) — 어디서도 안 읽던 값. 삭제.

`TOTAL_QUESTIONS = 8 → 6`, `canProceed` 사다리, 진행바, `compass.repository.ts` 의 `gender`·`style` 저장 컬럼 처리(null 로 두거나 컬럼 제거 — 마이그레이션 여부는 구현자가 판단)를 함께 고친다.

### 3. 시간 → 반경과 줄 수

| 답 | 반경 (출발지 기준) | 결과 일정 |
| --- | --- | --- |
| 반나절 | 약 30km | 오전 성지 → 오후 근처 관광지 (2줄, 점심 없음) |
| 하루 | 약 80km | 오전 성지 → 점심 근처 식당 → 오후 근처 관광지 (3줄) |
| 1박2일 이상 | 제한 없음 (전국) | 1일차 3줄 + **「2일차 일정은 준비 중이에요」 한 줄** |

- 반경 숫자는 **"이동 시간 ≤ 머무는 시간"** 원칙으로 잡은 임시값. 상수 하나(`RADIUS_KM_BY_TIME`)로 두고 조정한다.
- 반경 안에 후보가 없으면 반경을 넓히지 말고 **"이 시간으로 갈 수 있는 곳이 없어요 — 시간을 늘려 보시겠어요?"** 를 보인다. 없는 걸 있는 척하지 않는다.
- 1박2일의 2일차는 만들지 않는다 (1안). 답이 저장되므로 실제로 몇 %가 고르는지 본 뒤 2일차를 만들지 결정한다.

### 4. 결과 화면 — 하루 일정 (가안: 성지 1곳 중심)

```
[오늘의 성지 일정]                       ← 이름
  요즘 일로 마음이 많이 쓰이셨죠 …       ← Q2 첫 문장
  오전  ○○성지         (출발지에서 N km)
  점심  △△식당          (성지에서 도보 N분)   ← 「하루」이상만
  오후  □□관광지        (성지에서 도보 N분)
  2일차 일정은 준비 중이에요             ← 「1박2일 이상」만

  [ 다른 성지로 추천해 주세요 ]           ← 주 버튼 (새로 만든다)

  앞서 본 성지
  · △△성지  · □□성당                    ← 누르면 그때 본 일정으로 돌아감
  처음부터 다시                           ← 기존 reset. 작은 링크로 격하
```

- 점심 줄은 지금 관광지를 받는 TourAPI 주변 조회(`getNearbyByLocation`)에 **음식점 유형(contentTypeId 39)** 을 더해 받는다. 실시간 호출이라 저장 금지 규칙(ADR 0002)에 맞다. 없으면 그 줄을 "근처 식당 정보 없음" 으로 정직하게 비운다.
- 성지 카드의 기존 요소(사진·설명·상세로 가기 버튼)는 「오전」 줄 안에 유지한다.

### 5. 「다른 성지로 추천해 주세요」 알고리즘

1. 결과를 처음 낼 때 후보 성지를 **한 번에 넉넉히(10곳) 받아 둔다.** `getRecommendedCourses(emotion, …, limit)` 의 `limit` 을 키우면 된다 (`fetchCandidateSites` 가 이미 `limit * 2` 를 받는다).
2. 반경(3항) 안에 드는 것만 남기고 **가까운 순**으로 줄 세운다.
3. 버튼을 누를 때마다 **다음 순번** 성지를 보인다. 무작위 재추첨(`jitterShuffle`)을 다시 돌리면 방금 본 성지가 또 나올 수 있으므로 순번 방식으로 한다.
4. 그 성지의 점심·관광지(TourAPI)는 **그 성지를 보여줄 때** 부른다. 후보 10곳의 주변을 미리 다 부르지 않는다.
5. 후보가 바닥나면 버튼 대신 **"이 조건으로는 여기까지예요 — 시간을 늘리거나 마음을 바꿔 보시겠어요?"** 를 보인다.
6. 「앞서 본 성지」 목록은 이름만이 아니라 **그때 받은 일정(점심·관광지 포함)을 통째로** 화면 상태(`useState`)에 들고 있는다. 다시 눌렀을 때 TourAPI 를 재호출하면 결과가 달라질 수 있고, 사용자는 "아까 그 일정"을 기대한다. 화면 상태로만 들고 있고 저장하지 않으므로 ADR 0002 에 어긋나지 않는다.

## 완료 조건 (확인 방법까지)

1. 홈 카드에 「마음 상태로 고르는 오늘의 성지 일정」, 알약 버튼에 「오늘의 성지 일정」 — 6개 언어 모두. **확인**: 언어 토글 돌려가며 스크린샷
2. 퀴즈가 6문항이고 진행바가 6등분. 성별·참여방식 화면이 나오지 않는다. **확인**: 끝까지 눌러 본다
3. 「반나절」을 고르면 출발지 30km 밖 성지가 나오지 않는다. **확인**: 서울 출발·반나절로 3번 갈아타며 거리 표시 확인
4. 「하루」면 점심 줄이 있고 「반나절」이면 없다. 「1박2일 이상」이면 "2일차 준비 중" 줄이 있다
5. 「다른 성지로」를 5번 누르면 5곳이 전부 다르고, 「앞서 본 성지」에 쌓인다. 쌓인 것을 누르면 **점심·관광지가 처음 본 것과 같다**
6. 후보가 바닥나면 안내 문구가 나오고 버튼이 사라진다. **확인**: 후보가 적은 마음(예: 감사)·반나절·제주 출발로 시험
7. TourAPI 응답을 localStorage·DB·서비스워커 어디에도 쓰지 않는다. **확인**: 코드 grep + 개발자도구 Application 탭
8. `npm run verify` 통과. 기존 `HealingQuiz` 테스트·`course-matching.test.ts` 갱신
