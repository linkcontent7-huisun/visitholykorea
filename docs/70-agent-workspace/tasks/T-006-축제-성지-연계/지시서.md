# 지시서 — T-006 「축제 가는 김에, 성지 한 곳」

**담당: developer** · 작성: 지시자 · 2026-09-05
> 먼저 `.claude/agents/developer.md` 를 읽고 그 역할대로 일한다.
> 그 다음 저장소 루트의 `CLAUDE.md` 를 읽는다. TourAPI 관련 규칙이 이 작업의 핵심이다.

## 목표 (한 문장)

**오늘 열리는 지역 축제 옆에 그 지역 성지를 붙여**, "축제 다녀오시는 길에 성지 한 곳"을
권하는 화면을 만든다.

배경: 기존 `붐빔 피하기`(`/alternatives`)는 **붐비는 곳을 피해** 성지로 보낸다.
이번 것은 그 **반대 방향**이다 — 이미 사람이 모이는 행사에서 성지로 **끌어온다.**
둘이 한 쌍이 되어야 "관광데이터로 순례 수요를 만든다"는 이야기가 완성된다.

한국관광공사 「디지털 관광주민증」 이벤트의 **'지역을 고르면 그 지역 것이 쏟아진다'**
장치를 차용한다. 다만 우리는 쿠폰·할인을 줄 수 없다(예산 없음, 배포 약관상 비상업용).
**주는 것은 혜택이 아니라 "지금 거기서 갈 만한 성지"라는 정보다.**

## 🔴 이 작업에서 가장 중요한 규칙

**TourAPI 응답을 저장하지 않는다.** 축제 데이터는 한국관광공사 OpenAPI 응답이다.
DB 테이블·`localStorage`·서비스워커 캐시 어디에도 넣지 않는다. 공모전 실격 사유다.
→ **기존 `src/features/quiet/api/use-alternatives.ts` 가 하는 방식을 그대로 따른다.**
   새로운 저장 계층을 만들지 않는다. (성지 데이터 `holy_sites` 는 우리 것이라 무관하다.)

## 이미 있는 것 — 새로 만들지 말 것

이 작업에 필요한 배관은 **거의 다 깔려 있다.** 없는 것은 화면뿐이다.

| 있는 것 | 위치 |
| --- | --- |
| 오늘 진행 중인 **전국 축제 목록** | `src/shared/api/tour-api.ts` → `getOngoingFestivals()` |
| 성지 반경 축제 | 같은 파일 → `getNearbyFestivals()` |
| 좌표 간 거리 계산 | `src/shared/lib/geo.ts` |
| 붐빔 지수·배지 | `src/features/quiet/api/crowding-score.ts` · `components/CrowdingBadge.tsx` |
| 성지 목록 조회 | `src/features/sites/api/holy-sites.repository.ts` |
| 비슷한 화면의 본보기 | `src/pages/AlternativesPage.tsx` · `src/features/quiet/api/alternatives.ts` |

**`getOngoingFestivals()` 는 전국을 한 번에 받아온 뒤 거리를 우리가 계산하는 구조다.**
성지마다 API 를 부르지 않는다 — 이 방식을 반드시 유지한다(호출 수가 208배가 된다).

## 만들 것

### 1. 새 화면 `/festivals`

- 경로 문자열은 **`src/app/routes/paths.ts` 에만** 정의한다(`festivals`).
- 라우트를 `src/app/routes/router.tsx` 에 등록한다. 다른 페이지와 같은 lazy 방식.
- 페이지 파일: `src/pages/FestivalsPage.tsx`
- 로직·컴포넌트: **새 폴더 `src/features/festivals/`** 에 `api/` · `components/` 로 나눈다.
  (`AlternativesPage` + `features/quiet` 의 구조를 그대로 본뜬다.)

### 2. 화면에 나오는 것

1. **제목·부제** — 예: "축제 가는 김에" / "행사 근처의 성지를 함께 둘러보세요"
2. **시·도 필터** — 17개 시·도 칩. 기본은 전체.
   (관광주민증의 '지역 픽' 장치가 여기에 해당한다.)
3. **축제 카드 목록** — 카드 하나에:
   - 축제 이름 · 기간 · 주소
   - 그 축제에서 **가까운 성지 1~2곳**: 성지 이름 · 거리 · 붐빔 배지
   - 성지를 누르면 성지 상세(`paths.siteDetail(id)`)로 간다
4. **반경 20km 안에 성지가 하나도 없는 축제는 목록에서 뺀다.**
   성지 없는 축제를 보여주면 이 화면의 존재 이유가 없다.
5. **빈 상태** — 조건에 맞는 축제가 없으면 정직하게 그렇게 쓴다.
   가짜 카드·자리표시어를 절대 넣지 않는다.
6. **출처 한 줄** — `AlternativesPage` 하단의 한국관광공사 출처 문구와 같은 형식으로 적는다.

### 3. 진입점

`HomePage.tsx` 에 이미 있는 **칩(붐빔 피하기 · 마음 나침반 옆)에 하나를 더한다.**
칩의 기존 생김새를 그대로 따르고, 홈 화면의 다른 구조는 건드리지 않는다.

### 4. 다국어

문구는 **`src/shared/i18n/dictionary.ts` 공용 사전에 넣는다.** 컴포넌트 안 상수로 두지 않는다.
2026-09-04 에 도슨트 문구가 상수에 박혀 있어 6개 국어 작업에서 통째로 누락된 사고가 있었다.
사전에 넣으면 한 언어만 빠져도 타입 검사가 잡는다. **6개 국어(ko·en·es·fr·pt·it) 모두 채운다.**

## 완료 조건 — 각 항목을 무엇으로 확인했는지 `개발기록.md` 에 적는다

- [ ] `/festivals` 가 열리고 **오늘 실제 축제 데이터**로 카드가 그려진다
      — 확인법: 브라우저로 직접 열어 카드에 나온 축제 이름 2개와 짝지어진 성지·거리를 적는다.
- [ ] 축제마다 20km 안의 성지가 **실제로 가까운 곳**이다
      — 확인법: 카드 하나를 골라 축제 주소와 성지 주소를 적고, 표시된 거리가 말이 되는지 판단해 적는다.
- [ ] 20km 안에 성지가 없는 축제는 목록에 **없다** — 확인법: 필터링 코드 위치와, 전체 축제 수 → 남은 수를 적는다.
- [ ] 빈 상태에 **가짜 데이터가 없다** — 확인법: 결과가 0건이 되는 조건(예: 성지 없는 시·도)을 실제로 만들어 화면을 확인한다.
- [ ] TourAPI 응답이 **어디에도 저장되지 않는다** — 확인법: 새로 추가한 파일에 `localStorage`·`supabase.from(...).insert`·서비스워커 캐시 코드가 없음을 `grep` 으로 보이고, 데이터 흐름을 세 줄로 설명한다.
- [ ] API 호출 수가 성지 수에 비례하지 않는다 — 확인법: 화면 1회 로드에서 TourAPI 를 몇 번 부르는지 세어 적는다.
- [ ] 문구가 **6개 국어 전부** 사전에 있다 — 확인법: 새로 넣은 키 목록과, 언어 하나를 일부러 지웠을 때 타입 검사가 실패하는지 확인한 결과를 적는다.
- [ ] 홈 칩에서 들어가진다 — 확인법: 홈에서 칩을 눌러 이동하는 것을 직접 확인한다.
- [ ] **375px** 에서 가로 넘침이 없고, **큰 글자 모드**에서 글자가 겹치지 않는다
      — 확인법: 두 상태를 실제로 만들어 확인한 결과를 적는다(사용자의 85%가 50대 이상이다).
- [ ] `npm run verify` 통과 — **직접 돌린** 출력의 마지막 요약(타입·린트·테스트 수)을 적는다.
      새 로직(거리 필터·시·도 필터)에는 테스트를 붙인다.
