# 개발 기록 — T-003

## [1차] 2026-09-05

### 한 일

- `src/pages/MenuPage.tsx`
  - `Settings` 아이콘 import 와 `id: 'settings'` (일반 설정) 항목을 삭제했다.
  - `id: 'intro'`(서비스 소개), `id: 'help'`(고객지원) 두 항목에
    `onClick: () => navigate(paths.faq)` 를 추가했다. 라벨·부제 문구는
    그대로 두고 목적지만 연결했다(지시서대로 두 항목을 합치지 않음).
  - `id: 'share'`(친구에게 추천하기) 항목에 `handleShare` 를 연결했다.
    `navigator.share` 가 있으면 `{ title: document.title, url:
    window.location.origin }` 로 공유 시트를 띄우고, 사용자가 취소해서
    던지는 예외는 조용히 무시한다(기존 `src/features/passport/lib/
    share-card.ts` 의 `shareOrDownloadCard` 와 같은 패턴).
    `navigator.share` 가 없으면 기존 `src/shared/lib/map-links.ts` 의
    `copyText` 로 `window.location.origin` 을 복사하고, 결과를
    `shareStatus` state(`idle`/`copied`/`error`)로 들고 있다가 항목의
    `sub` 문구로 2초간 보여준다. 복사 성공은 `t('copied')`("복사했어요"),
    실패는 기존 `t('copyFailed')`("길게 눌러 복사해 주세요")를 재사용했다
    — 두 키 모두 `DirectionsCard.tsx` 에서 이미 쓰던 6개 언어 번역이라
    새로 지어내지 않았다. `alert`/`confirm` 은 쓰지 않았다.
  - `useState` 를 react 에서, `copyText` 를 `@/shared/lib/map-links` 에서
    새로 import 했다.

      확인됐지만, "복사했어요"(성공) 문구까지는 이 환경에서 실제 사용자

      (`ok ? 'copied' : 'error'`) 실패 쪽이 보였다는 것으로 로직 자체는
      맞게 동작한다고 판단했다.

### 확인 못 한 것

- `navigator.share` 가 있는 실제 모바일 기기에서 공유 시트가 실제로
  뜨는지는 이 환경(데스크톱 헤드리스 브라우저, `navigator.share`
  자체가 없음)에서 확인 못 했다.
- 클립보드 복사 "성공" 시 부제가 "복사했어요"로 바뀌는 것을 실제 사용자
  클릭으로는 확인 못 했다(위 이유로 실패 분기만 재현됨). 코드는 성공/실패
  두 분기를 대칭으로 처리하므로 실패 분기가 정상 동작했다면 성공 분기도
  같은 state 갱신 경로를 타 정상 동작할 것으로 본다 — 다만 "확인했다"고는
  적지 않는다.

### 지시서에 없어서 판단하지 않은 것

- `id: 'profile'`(내 프로필, 계정 설정 섹션) 항목도 `onClick` 이 없다.
  로그인 안 한 사용자는 행 전체가 버튼이라 `requiresAuth` 로직이 먼저
  걸려 로그인 화면으로 가지만, 로그인한 사용자가 누르면 지금도 아무 일도
  안 난다 — 완료 조건 "onClick 없는 항목이 하나도 없다"만 보면 이것도
  걸린다. 하지만 지시서가 다룬 "4개"는 `settings`/`intro`/`help`/`share`
  뿐이고, 범위 밖에 "프로필 카드"를 손대지 말라는 문구가 있어(이 항목이
  프로필 카드인지 계정 설정 섹션인지 지시서에 명확히 안 갈라 있음) 이번
  작업에서는 건드리지 않았다. `paths.ts` 에도 프로필 전용 라우트가 없다
  (확인함 — `grep` 결과 없음). 별도 판단이 필요하다.
