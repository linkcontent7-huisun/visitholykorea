## 검증 결과

- `npm run lint`: 오류 0건, 기존 Fast Refresh 경고 2건만 남았다.
- `npm run typecheck`: 이번 변경과 무관하게 다른 워커가 수정 중인 `src/features/sites/lib/nearby-directory.test.ts`의 `cbck_code` 선택 속성 타입 오류로 실패했다.
- 선택 테스트 실행은 이 환경의 Vite/esbuild가 상위 디렉터리를 읽지 못해 시작 단계에서 실패했다. 따라서 실제 API 첫 응답과 400px 브라우저 캡처는 남기지 못했다. `.env.local`은 지시대로 읽지 않았다.
- `rg -n "localStorage" src/shared/api/tour-api.ts` 결과는 0건이다. TourAPI 응답을 DB·localStorage·서비스워커에 저장하는 코드는 추가하지 않았다.

## 남은 확인

- 연관 관광지·지역 중심 관광지(C)는 API가 요구하는 시군구 행정코드의 신뢰 가능한 실시간 해석 경로를 확보한 뒤 화면에 연결해야 한다. 주소 이름만으로 코드표를 하드코딩하지 않는 지시를 지키기 위해 임의 코드 연결은 하지 않았다.
- 다른 워커의 타입 변경이 정리된 뒤 `npm run verify`와 실제 승인 키가 있는 브라우저에서 API 응답·세 장의 캡처를 다시 확인해야 한다.

- `src/pages/RouteDetailPage.tsx`에서 두루누비 걷기길 조회와 「이 근처 걷기길」 영역을 제거했다. 순례 코스 자체에는 코스 경유지만 남긴다.

- T-020 걷기길 위치 변경 끝.

## 2026-09-20 집중률 행 범위·시도 매칭 보완

- `src/shared/api/tour-api.ts`의 `getCongestionRates`가 여전히 `numOfRows: 300`인 것을 확인했다. 관광지별 30일치 행이 연달아 오는 응답 구조에서는 관광지 약 10곳에서 잘리므로, 2,000행으로 늘렸다.
- `src/features/crowding/api/congestion-lookup.ts`는 주소 전체에서 시도를 찾고 있었다. 수정 전 `경기도 광주시 퇴촌면 천진암로 1203`을 직접 넣으면 `광주`로 판정됨을 재현했고, 첫 낱말만 쓰도록 바꿔 `경기`로 판정되게 했다.
- `congestion-lookup.test.ts`에 경기도 광주시 회귀 테스트를 추가했다. 관련 테스트 8건 통과, `npm run verify` 통과 — 타입 검사 통과, 린트 오류 0건(기존 Fast Refresh 경고 2건), 테스트 407건 통과·1건 스킵(2026-09-20).
- `.env.local`은 지시대로 읽지 않았다. 따라서 실제 승인 키를 통한 TourAPI 응답 재호출은 확인하지 못했고, 배포 뒤 실제 성지 상세·일정 화면에서 라벨 표시를 다시 확인해야 한다.

- T-020 집중률 행 범위·시도 매칭 보완 끝.
