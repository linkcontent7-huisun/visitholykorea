# T-014 — 순례 코스 4개 추가 (서울순례길 1·2·3코스, 최양업 신부의 길) + 서울 성지 미사 시간

작성 2026-09-12 · 담당 Codex · 지시자 Claude

## 목표

`pilgrimage_routes` 에 코스 4개와 경유지를 넣고, 서울 성지 15곳의 설명에 미사 시간·연락처를,
최양업 신부 관련 성지 8곳의 역사에 한 문단을 **덧붙이는** 마이그레이션 SQL 한 파일을 만든다.
**DB 에 적용하지 않는다** — 지시자가 검토한 뒤 `npm run db:migrate` 를 직접 돌린다.

## 만들 파일 (하나)

`supabase/migrations/20260912230000_add_seoul_and_choi_routes.sql`

형식은 `supabase/migrations/20260818010000_create_pilgrimage_routes.sql` 의 시드 부분과 같다:
- `insert into public.pilgrimage_routes (slug, title, subtitle, description, sort_order) values (...) on conflict (slug) do nothing;`
- 경유지는 `values` 표 → `join public.holy_sites s on s.name = v.site_name` → `on conflict (route_id, position) do nothing`.
- 성지 이름은 **아래 표의 DB 이름 글자 그대로** 쓴다 (띄어쓰기·괄호 포함). 하나라도 안 맞으면 join 에서 조용히 빠지므로,
  파일 맨 끝에 각 코스의 경유지 수를 세는 `do $$ ... raise notice` 블록을 넣어 기대 수와 다르면 `raise exception` 으로 멈추게 한다.
- 설명 덧붙이기는 `update public.holy_sites set description = coalesce(description,'') || E'\n\n' || '...' where name = '...' and coalesce(description,'') not like '%미사 시간(2025-11-30 기준)%';`
  처럼 **두 번 돌아도 두 번 붙지 않게** 한다. history 도 같은 방식(표식 문구: `최양업 신부와의 인연`).
- 전화번호는 `phone` 이 비어 있을 때만 채운다: `update ... set phone = '02-774-1784' where name = '명동대성당' and coalesce(phone,'') = '';`
