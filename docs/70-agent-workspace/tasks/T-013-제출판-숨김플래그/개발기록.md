# T-013 개발기록

## 작업 시작 상태

- 2026-09-12 `git status --short`에서 다른 작업으로 보이는 미추적 파일 `.claude/settings.local.json`, `movie/`가 있었다. 해당 파일은 건드리지 않았다.

## 완료 조건 확인

1. 제출 모드에서는 `SUBMISSION_MODE`를 기준으로 관리자 메뉴·관리자 라우트·상세의 하트·탐색의 즐겨찾기·순례기록 작성 입구를 숨겼다. `VITE_SUBMISSION_MODE=true npm run build`을 실행해 TypeScript 검사와 Vite 번들이 시작되는 것을 확인했고, `npx vite preview --port 4173`에서 `/admin`, `/menu`, `/explore`, `/records`의 로컬 HTTP 응답이 모두 200인 것을 확인했다. SPA의 HTTP 응답은 항상 진입 HTML을 돌려주므로, `/admin`의 최종 404 화면은 관리자 라우트를 배열에 넣지 않는 코드 조건으로 확인했다.
2. 플래그가 없을 때는 모든 조건이 거짓이어서 기존 요소와 라우트가 렌더링되도록 구현했다. 일반 `npm run build`가 `✓ built in 15.12s`로 끝나 개발 모드와 같은 기본 환경의 컴파일을 확인했으며, 이 실행 환경의 헤드리스 Edge는 스크린샷 파일을 생성하지 않아 화면 스크린샷은 남기지 못했다.
3. `npm run verify`를 실행해 `typecheck`, `lint`, `test` 순서로 완료했다. 린트에는 기존 `router.tsx`의 Fast Refresh 경고 2건만 있었고 오류는 없었다.
4. 변경 파일은 `.env.example`, `src/shared/lib/feature-flags.ts`, `src/shared/types/env.d.ts`, `src/app/routes/router.tsx`, `src/pages/MenuPage.tsx`, `src/pages/SiteDetailPage.tsx`, `src/pages/ExplorePage.tsx`, `src/pages/RecordsPage.tsx`, 그리고 이 기록 파일뿐이다. `git diff --check`도 통과했다.

## 판단 기록

- 즐겨찾기 조회와 순례기록 작성 컴포넌트의 기능 코드는 삭제하지 않고, 제출판에서 입구만 렌더링하지 않게 했다. 제출 후 환경 변수 하나를 비우면 기존 운영·개발 기능이 그대로 돌아와야 하기 때문이다.
