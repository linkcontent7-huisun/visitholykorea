# T-015 — DB·사진 내보내기 스크립트 (`npm run db:export`)

작성 2026-09-13 · 담당 Codex · 지시자 Claude

## 목표

Supabase 가 사라져도 자료가 남도록, 표 전부와 사진 목록을 한 번의 명령으로 날짜 폴더에 내보낸다.
Supabase 무료 등급은 자동 백업이 없다 — 이 스크립트가 유일한 보험이다.

## 만들 것

1. `scripts/db-export.ts` — `scripts/db-migrate.ts` 와 같은 방식으로 `.env.local` 의 `SUPABASE_DB_URL` 로 접속한다
   (파일을 읽는 건 스크립트다. Codex 는 `.env.local` 을 열지 않는다).
   - `public` 스키마의 모든 표를 `select *` 로 읽어 `<출력폴더>/<YYYY-MM-DD>/tables/<표이름>.json` 과 `.csv` 로 쓴다
   - `information_schema` 로 표·열·형·제약을 읽어 `<날짜>/schema.md` (표별 열 목록, 마크다운 표) 를 만든다
   - `storage.objects` 를 읽어 `<날짜>/storage-files.csv` (bucket, name, size, created_at) 를 만든다
   - 공개 버킷(`site-photos`)의 파일은 `https://<SUPABASE_URL>/storage/v1/object/public/<bucket>/<name>` 으로 받아
     `<날짜>/photos/site-photos/…` 에 저장한다. 비공개 버킷(`pilgrim-photos`)은 목록만 남기고 "비공개라 건너뜀"을 요약에 적는다
   - 출력 폴더: 환경 변수 `BACKUP_DIR`, 없으면 `C:\VisitHoly-백업`. 폴더가 없으면 만든다
   - 끝나면 `<날짜>/요약.md` 에 표별 행 수·파일 수·총 용량을 쓴다
2. `package.json` 에 `"db:export": "tsx scripts/db-export.ts"` 추가
3. `.gitignore` 에 `backups/` 추가 (저장소 안에 실수로 만들 때 대비)
4. `docs/20-architecture/README.md` 표에 「DB 백업 → `npm run db:export`」 한 줄 추가

## 완료 조건

1. `npm run db:export` 를 **실제로 실행**해 `C:\VisitHoly-백업\2026-09-13\` 이 생기고 요약.md 에 표 15개 이상·행 수가 찍힌다 → 요약.md 내용을 개발기록에 붙인다
2. `schema.md` 에 `holy_sites`·`pilgrimage_stamps`·`holy_site_translations` 의 열이 보인다
3. 사진: `site-photos` 파일 수가 storage-files.csv 의 site-photos 행 수와 같다
4. `npm run verify` 통과
