# T-023 · 도슨트 원고 208곳 — 「소개글」+「지금 이야기」 를 써서 DB 에 넣는다

작성 2026-09-17 · 지시자: 노희선(사장님) · 실행: **Codex** (이 저장소에서) · 이 지시서는 Codex 가 메인 대화를 못 보므로 필요한 것을 전부 적었다.

## 목표 한 문장

208개 성지·성당마다 안내자가 옆에서 말해 주는 **「소개글」(700~1,000자)** 을 쓰고, 그중 우선 11곳은 마당에서 바로 찾아볼 수 있는 **「지금 이야기」 지점 3~5개** 까지 써서, 전부 Supabase `docent_scripts` 표에 올린다.

## 왜 하는가 (배경)

- 앱의 오디오 도슨트(`src/features/docent/lib/chapters.ts`)는 원고가 있으면 지점별로, 없으면 DB 의 `holy_sites.description`(평균 281자)을 읽어 준다. 지금 208곳 중 193곳이 1분짜리 소개글뿐이고, 건축·성물·예술품 이야기는 거의 없다(9/17 실측: 건축 언급 34곳).
- 사장님 결정(9/17): 도슨트는 **「소개글」**(역사·어떻게 지어졌나·건축 배경·인물) 과 **「지금 이야기」**(건축미·성모상·성물·예술품 — 현장에서 찾아볼 것) 두 부분. 말투는 **안내자 1인칭 존댓말**("~보세요", "~입니다"). 위치는 "성모상은 마당 한쪽에…" 정도로 **애매하게** — 정확한 위치를 지어내지 않는다.
- 사장님 지시: **사진·안내 설명글은 전부 DB 화.** 저장소 파일은 작성·검토용 원본이고, 앱은 DB 를 읽는다.

## 원고 규칙

0. **자료는 넓게 찾는다.** 성지·성당 공식 홈페이지 → 교구 홈페이지·SNS(인스타그램·유튜브 소개 영상 설명) → 가톨릭신문·가톨릭평화신문·굿뉴스 → 국가유산청·향토문화전자대전 → 일반 신문(동아·조선·한겨레·지역지) 순으로 검색해 읽는다. 그 자료로 **소개·역사적 배경·건축미·예술품·어떻게 조성되었는지** 를 재미있게 엮는다.
1. **근거 없는 숫자·이름은 쓰지 않는다.** 연도·높이·건축비·작가·설계자는 공식 홈페이지·국가유산청·가톨릭신문·가톨릭평화신문·굿뉴스(maria.catholic.or.kr) 에서 확인된 것만. 자료마다 다르면 숫자를 빼고 말로("당시 대전에서 가장 높은 건물"). 블로그는 단서로만 쓰고 근거로 적지 않는다.
2. **출처를 `sources` 에 남긴다** (label + url). 확인 못 한 것은 원고에 넣지 않거나, 정말 필요하면 "전해집니다"로 쓰고 sources 에 `현장 안내판으로 확인 필요` 를 적는다.
3. **분량**: 소개글 700~1,000자 (TTS 로 2~3분). 지점은 150~250자씩 3~5개. 1,000자를 넘기지 않는다.
4. **말투**: 안내자 1인칭 존댓말. "~에 오신 것을 환영합니다"로 열고 "평화로운 여정 되시기 바랍니다"류로 닫는다. 교리 설명이 아니라 **"왜 이것이 여기 있는가"** 를 들려준다. 비신자·외국인이 들어도 흥미로워야 한다(성심당·이명래 고약 같은 생활 이야기 환영).
5. **TTS 를 위해** 숫자는 한글로("천구백이십이년" 대신 "1922년"은 허용 — 브라우저가 읽는다 — 다만 "144호"처럼 단위 붙는 것은 "백사십사 호"), 괄호·기호·영문 약어를 피한다.
6. 소개글 구성: ① 이곳이 무엇인가 한 문장 → ② 왜·어떻게 생겼나(역사) → ③ 어떻게 지어졌나(건축·설계·재료) → ④ 얽힌 사람 한 명 → ⑤ 지금 이곳(현재 쓰임·주변 순례길).
7. 지점 구성: 무엇을 보라 → 왜 여기 있나 → 눈여겨볼 디테일 하나(`lookFor`). 위치는 "정문 앞", "마당 한쪽", "성당 안" 수준.
8. **DB 의 기존 `holy_sites.description`·`history` 를 먼저 읽고** 거기 있는 사실을 뼈대로 쓴다(우리가 이미 검증한 자료다).

## 파일 형식 — 이 두 형식만 쓴다

**소개글**: `data/docent/소개글/<성지이름>.md` (예시: `data/docent/소개글/공세리성지성당.md`)

```md
---
siteId: <holy_sites.id>
siteName: <DB 의 name 과 같게>
language: ko
kind: intro
status: draft
writtenBy: Codex (문헌 초안 2026-09-17)
sources:
  - label: 굿뉴스 성지 안내 · ○○
    url: https://…
  - label: 국가유산청 ○○
---

(낭독문 700~1,000자)
```

**영어 소개글**: `data/docent/소개글/en/<성지이름>.md` — 같은 형식, `language: en`. 본문은 영어. `sources` 는 한국어 판과 같게.

**지금 이야기(지점)**: `data/docent/<성지이름>.json` — 형식은 `data/docent/_템플릿.json`, 예시는 `data/docent/대흥동-성당.json`. `siteId`·`siteName`·`points[].seq/title/location/narration/lookFor/sourceNote` 를 채운다. 영어(`narrationEn` 등)는 **쓰지 않는다** — 이번 단계는 한국어만.

## 명령

```bash
git fetch origin && git checkout -b data/docent-scripts origin/main   # 처음 한 번. main 에 직접 커밋 금지
npm ci                                                                  # node_modules 없으면

# 대상 목록 뽑기 (사진 있는 곳 중 소개글 없는 곳)
npx tsx -e "
import pg from 'pg'; import { loadEnvLocal } from './scripts/lib/env.ts'; loadEnvLocal();
const c = new pg.Client({ connectionString: process.env.SUPABASE_DB_URL }); await c.connect();
const r = await c.query(\`select h.id, h.name, h.diocese, h.homepage_url, length(h.description) d from holy_sites h
  where h.image_url is not null and not exists (select 1 from docent_scripts s where s.site_id=h.id and s.kind='intro' and s.language='ko')
  order by h.diocese, h.name\`);
for (const x of r.rows) console.log(x.id, '|', x.name, '|', x.diocese, '|', x.homepage_url ?? '-', '|', x.d+'자');
console.log(r.rows.length, '곳'); await c.end();"

# 한 성지의 기존 자료 읽기
npx tsx -e "
import pg from 'pg'; import { loadEnvLocal } from './scripts/lib/env.ts'; loadEnvLocal();
const c = new pg.Client({ connectionString: process.env.SUPABASE_DB_URL }); await c.connect();
const r = await c.query('select name, location, description, history, homepage_url, image_source from holy_sites where id=\$1', [process.argv[1]]);
console.log(JSON.stringify(r.rows[0], null, 2)); await c.end();" <siteId>

# 원고를 DB 에 올리기 (같은 성지는 덮어씀)
npm run docent:load              # 전부
npm run docent:load -- 전동       # 파일명에 '전동' 이 든 것만

git add data/docent && git commit -m "data(docent): ○○ 외 N곳 소개글" -- data/docent
```

`.env.local` 에 `SUPABASE_DB_URL` 이 있어야 한다(이 노트북엔 있다).

## 완료 조건 — 단계마다

1. `npm run docent:load` 가 오류 없이 끝나고, 아래 SQL 이 기대값을 낸다:
   `select count(distinct site_id) from docent_scripts where kind='intro' and language='ko'` → (가) 뒤 **11**, (나) 뒤 **89**, (다) 뒤 **208**.
   `… and language='en'` → (라) 뒤 **208**.
2. 모든 소개글이 700~1,000자, `sources` 1개 이상.
3. 원고 안에 근거 없는 연도·높이·금액·작가 이름이 없다 — 의심되면 뺀다.
4. `npm run verify` 통과. 커밋은 `data/docent` 와 `scripts/`, `docs/70-agent-workspace/tasks/T-023-…` 만.
5. 끝나면 이 폴더에 `개발기록.md` 를 쓴다: 몇 곳 썼는지 · 근거를 못 찾아 짧게 쓴 곳 목록 · 사장님 확인이 필요한 것.

## 범위 밖 (하지 말 것)

- `src/` 의 화면·낭독 코드는 건드리지 않는다 (앱이 DB 를 읽게 바꾸는 일은 별도 작업).
- `holy_sites.description` 을 덮어쓰지 않는다 — 소개글은 `docent_scripts` 에만.
- 영어·다른 언어 번역, 사진 추가, 마이그레이션 수정.
- `main` 에 직접 커밋·푸시.
