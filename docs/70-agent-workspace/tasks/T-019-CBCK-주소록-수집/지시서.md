# T-019 — 한국 천주교 주소록(CBCK) 전체 수집 → `catholic_directory` 보강

작성 2026-09-14 · 담당 Codex · 지시자 Claude · 출처: 사장님이 준 https://directory.cbck.or.kr

## 목표

한국천주교주교회의 온라인 주소록에서 **본당·공소·성지/사적지·피정의 집** 전부(약 2,700곳)의 기본 정보를 받아
`catholic_directory`(지금 5,918행, 이름·주소·전화·좌표만 있음)를 채우고, 성지 208곳(`holy_sites`)의 빈 전화·홈페이지·팩스를 메운다.
AI 가이드가 「대산성당」 같은 질문에 주소·전화·주임신부·설립일까지 답할 수 있게 하는 것이 목적이다.

## 사이트 구조 (지시자가 2026-09-14 실측 — 그대로 쓰면 된다)

- robots.txt 없음(404). `User-Agent: VisitHolyKorea-research/1.0 (+https://github.com/linkcontent7-huisun/visitholykorea)`, 요청 간격 **1.5초**, 실패 3회까지
- **교구 코드** (gyogu): 서울 201000011 · 춘천 201000013 · 대전 201000016 · 인천 201000017 · 수원 201000018 · 원주 201000019 · 의정부 201000020 ·
  대구 201000021 · 부산 201000022 · 청주 201000023 · 마산 201000024 · 안동 201000025 · 광주 201000026 · 전주 201000027 · 제주 201000028 · 군종 201000029
  (평양 201000012 · 함흥 201000014 · 덕원 201000015 는 0건)
- **구분 코드** (gubn): 본당 4 · 공소 5 · 성지/사적지 16 · 피정/기도의 집 15 (수도회 6·7, 기관 10~14 는 이번 범위 밖)
- **목록** — `https://directory.cbck.or.kr/OnlineAddress/Catholic/Church.aspx?cgubn=g&gubn=<gubn>&gyogu=<gyogu>&tbxSearch=&scnt=0&start=1&paged=50&sort=0&gubn2=all&char=all`
  한 교구의 항목이 **한 페이지에 전부** 나온다(지구별 묶음, 페이지 넘김 없음). 각 항목은 `<a class='today0' href='DetailInfo.aspx?…&code=<code>…'>이름</a>`.
  `SearchList.aspx` 는 빈 목록을 주니 쓰지 않는다
- **상세** — `https://directory.cbck.or.kr/OnlineAddress/Catholic/DetailInfo.aspx?cgubn=g&gubn=<gubn>&gyogu=<gyogu>&code=<code>&gubn2=all&char=all`
  본문은 `라벨|값` 쌍의 표. 본당 예(대산, code 201000664): `소속` 대전교구 · `지역/지구` - / 서산지구 · `한글명칭` 대산 · `대표주소` 31909 충청남도 서산시 대산읍 충의로 1882 -5 ·
  `대표 전화 번호` (041)681-8802 · `팩스번호` · `주임신부번호` · `홈페이지 주소` · `주임신부` 박종훈 안토니오 신부 / Rev. Antonius Park Jong-Hun · `설립일` 1989.8.19. · `주보` 그리스도의 성체 성혈 · `신자수` 903 · `공소수` 0.
  기관형(주교회의 등)은 `영문명칭`·`대표주소(영문)`·`전자우편 주소` 가 더 있다. 좌표·미사 시간은 없다
- HTML 은 태그를 `|` 로 바꾼 뒤 `라벨|값` 으로 읽으면 된다 (지시자 검증 방식). 값 없는 라벨은 null

## 만들 것

### 1. 수집기 `scripts/crawl/cbck.py` (Python, requests + beautifulsoup4)

- `python scripts/crawl/cbck.py --gubn 4 --gyogu all` 처럼 구분·교구를 골라 돌린다. `all` 이면 위 코드 전부
- 결과 `data/research/cbck-directory.jsonl` — 한 줄 한 곳. 필드:
  `cbck_code, gubn, kind('본당'|'공소'|'성지사적지'|'피정의집'), diocese('대전' 처럼 "교구" 뗀 이름), district, name, name_en, address, zipcode, address_en, phone, fax, pastor_phone, homepage, email, pastor, pastor_en, founded_on(YYYY-MM-DD 또는 null), patron, members_count(int|null), mission_count(int|null), fetched_at`
- 이미 있는 `cbck_code` 는 건너뛴다(중단 뒤 이어 돌리기). 원문 HTML 은 `scripts/crawl/.cache/cbck/`(gitignore) 에만 둔다
- 끝에 `data/research/cbck-요약.md`: 구분×교구 건수 표, 전화 없는 곳 수, 홈페이지 있는 곳 수

### 2. 마이그레이션 `supabase/migrations/20260914100000_extend_catholic_directory.sql` (적용은 지시자)

`catholic_directory` 에 열 추가(`add column if not exists`): `cbck_code text unique`, `district text`, `zipcode text`, `fax text`, `pastor_phone text`,
`homepage text`, `email text`, `pastor text`, `pastor_en text`, `founded_on date`, `patron text`, `members_count int`, `mission_count int`,
`address_en text`, `name_en text`, `cbck_synced_at timestamptz`. 기존 열(name, category, diocese, address, phone, lat, lng, name_romanized, address_romanized)은 건드리지 않는다.
`src/shared/types/database.ts` 의 `CatholicDirectoryRow`(있으면) 에 같은 열 추가.

### 3. 적재기 `scripts/crawl/cbck-load.ts` (tsx, `scripts/db-migrate.ts` 와 같은 접속 방식 — 실행은 지시자)

- `--dry-run` 이면 넣을/고칠 행 수만 출력
- 매칭 순서: ① `cbck_code` 가 같은 행 → 갱신 ② 없으면 `diocese` 같고 `replace(name,' ','')` 가 같은 행(기존 5,918행에는 code 가 없다) → `cbck_code` 를 채우고 빈 열만 채운다(**기존 값은 덮어쓰지 않는다**) ③ 그래도 없으면 새 행 insert (lat/lng 는 null — 좌표는 다음 작업)
- category 는 kind 에 맞춰 기존 값 체계(`본당`/`공소`/`성지사적지`/`피정의집`)로
- `holy_sites` 보강: 성지/사적지(gubn 16) 행 중 `replace(name,' ','')` 이 `holy_sites.name_compact` 와 같거나 포함되는 곳은
  `holy_sites.phone / homepage_url / fax` 가 **비어 있을 때만** 채운다. 몇 곳을 채웠는지 출력
- `site_sources` 에 그 성지들 출처 한 줄: kind `web`, title `한국 천주교 주소록 (directory.cbck.or.kr)`, url 상세 페이지, note `전화·홈페이지·팩스`

## 완료 조건 (어떻게 확인하는지)

1. **대전교구 본당(gubn 4, gyogu 201000016) 144곳**을 실제로 돌려 jsonl 에 144행 → 요약 표를 개발기록에 붙인다. 그 뒤 나머지 교구·구분을 이어 돌린다(전체 약 2,700곳, 약 70분). 다 못 돌려도 대전 144 는 반드시
2. jsonl 표본 5행을 개발기록에 붙인다 — `대산`(201000664) 행에 전화 `(041)681-8802`, 설립일 `1989-08-19`, 주임신부가 들어 있어야 한다
3. `npx tsx scripts/crawl/cbck-load.ts --dry-run` 출력(갱신/보강/신규 행 수, holy_sites 보강 예정 수)을 개발기록에
4. `npm run verify` 통과, `python -m py_compile scripts/crawl/cbck.py`
5. 바꾼 파일 표
