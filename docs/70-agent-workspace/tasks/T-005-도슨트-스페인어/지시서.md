# 지시서 — T-005 도슨트 원고 스페인어 추가 (대표 3곳)

**담당: Codex (데이터 담당)** · 작성: 지시자(Claude Code) · 2026-09-05

> 먼저 저장소 루트의 **`AGENTS.md`** 와 **`CLAUDE.md`** 를 읽는다.
> 특히 "지시서에 적힌 파일만 고친다 / 커밋하지 않는다" 두 줄은 이 작업에서 실제로 중요하다 —
> 지금 **다른 에이전트가 같은 저장소의 `src/` 를 동시에 고치고 있다.**

## 목표 (한 문장)

대표 성지 3곳의 오디오 도슨트 원고에 **스페인어 낭독문**을 추가해,
스페인어로 앱을 여는 순례자가 스페인어 도슨트를 끝까지 들을 수 있게 한다.

배경: 2027 세계청년대회(WYD) 주최국 언어가 스페인어다. 앱 화면 문구는 이미 6개 국어인데
**낭독 원고만 한국어·영어뿐**이라, 스페인어 사용자는 재생 버튼 앞에서 영어를 만난다.

## 고칠 파일 — 이 3개뿐이다

```
data/docent/명동대성당.json
data/docent/절두산-순교성지.json
data/docent/전동성당.json
```

## 무엇을 넣는가

각 파일에서 **`En` 으로 끝나는 필드가 있는 자리마다 `Es` 필드를 같은 모양으로 하나씩 더한다.**
필드 이름은 정확히 아래와 같다(대소문자 포함).

| 위치 | 추가할 필드 |
| --- | --- |
| `intro` | `narrationEs` |
| `points[]` 각 항목 | `titleEs` · `locationEs` · `narrationEs` · `lookForEs` |
| `outro` | `narrationEs` |

- **`En` 필드가 `null` 이거나 없는 자리는 `Es` 도 만들지 않는다.** 짝을 정확히 맞춘다.
- `forEveryone` · `photos` · `sourceNote` · `seq` · `siteId` 등 **나머지 필드는 손대지 않는다.**
- 기존 `narration`(한국어) · `narrationEn`(영어) 값을 **고치거나 다듬지 않는다.**

## 번역 규칙

1. **한국어 원문(`narration`)이 기준이다.** 영어(`narrationEn`)는 이미 번역본이므로,
   용어를 맞출 때만 참고한다. 영어를 다시 번역하면 오차가 두 번 쌓인다.
2. **원문에 없는 사실을 만들지 않는다.** 연도·인명·순교 경위는 종교 성지 정보라
   틀리면 신뢰가 바로 무너진다. 모르면 문장을 줄이지, 채우지 않는다.
3. **소리 내어 읽히는 글이다**(음성합성 `es-ES`). 한 문장을 너무 길게 쓰지 않고,
   괄호·기호·약어를 피한다. 숫자와 연도는 그대로 써도 된다(TTS 가 읽는다).
4. **가톨릭 용어는 스페인어 교회 표준어를 쓴다** — 예: 순교자 `mártir`,
   성인 `san/santa`, 미사 `Misa`, 주교좌성당 `catedral`, 순례 `peregrinación`,
   성지 `lugar de peregrinación`, 시복·시성 `beatificación/canonización`.
5. **고유명사는 한국어 로마자 표기를 유지하고**, 처음 나올 때만 짧게 뜻을 덧붙인다.
   영어 파일이 이미 쓰는 표기를 따른다(예: `Myeongdong`, `Jeoldusan`, `Jeondong`).
6. 존댓말·차분한 안내 톤을 유지한다. 한국어 원고의 어조가 기준이다.

## 완료 조건 — 각 항목을 무엇으로 확인했는지 개발기록에 적는다

- [ ] 3개 파일이 **유효한 JSON** 이다 — 확인법: `node -e "JSON.parse(require('fs').readFileSync('<파일>','utf8'))"` 가 오류 없이 끝난다. 3개 다 돌린 결과를 적는다.
- [ ] **`En` 과 `Es` 의 개수가 파일마다 정확히 같다** — 확인법:
      `grep -c 'narrationEn' <파일>` 과 `grep -c 'narrationEs' <파일>` 의 값을 나란히 적는다. `titleEn/titleEs`, `locationEn/locationEs`, `lookForEn/lookForEs` 도 같은 방법으로.
- [ ] `Es` 값 중 **빈 문자열·한국어·영어가 섞여 남은 것이 없다** — 확인법: 각 파일의 `Es` 필드를 전부 눈으로 훑고, 한글이 남았는지 `grep -n '"[a-zA-Z]*Es": "[^"]*[가-힣]' <파일>` 로 확인해 결과를 적는다(0건이어야 한다).
- [ ] **파일 인코딩이 UTF-8 그대로**이고 기존 한국어가 깨지지 않았다 — 확인법: 파일을 다시 열어 한국어 문장 한 줄을 그대로 옮겨 적는다.
- [ ] `git status` 결과에 **위 3개 파일과 개발기록만** 올라와 있다(다른 파일 수정 없음).
- [ ] `npm run verify` 통과 — 직접 돌린 출력의 마지막 요약(타입·린트·테스트 개수)을 적는다.
      ⚠️ 이 작업만으로는 화면에 스페인어가 아직 안 나온다(아래 참고). verify 통과 여부만 본다.

## 범위 밖 — 하지 말 것

- ❌ **`src/` 아래 어떤 파일도 고치지 않는다.** 코드가 스페인어를 읽게 만드는 일
  (`src/features/docent/lib/chapters.ts` 등)은 **다른 에이전트가 동시에 하고 있다.**
  건드리면 그쪽 작업이 사라진다.
- ❌ 나머지 10곳의 도슨트 원고 (`data/docent/` 의 다른 파일들)
- ❌ 프랑스어·포르투갈어·이탈리아어 (이번엔 스페인어만)
- ❌ 한국어·영어 원고 손질, 오타 수정 포함
- ❌ `git commit` · `git push` — 파일만 고쳐두면 지시자가 확인하고 커밋한다
