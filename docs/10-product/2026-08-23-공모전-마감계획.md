> **자문단(대전교구)에 여쭐 것 — 3건으로 정리됨**
> ⓐ 해미순교성지가 가리키는 곳이 **여숫골**인지 **읍성**인지 (영어와 한국어가 다른 장소를 설명한다)
> ⓑ 해미 — 이름이 밝혀진 순교자가 **132명**인지 **179명**인지
> ⓒ 황새바위 — 이름이 확인된 순교자가 **337위**인지 **248위**인지

*2026-08-24 추가 — 내포 축 5곳 더 → **감수 완료 9곳***

여사울 · 합덕 성당 · 갈매못 · 수리치골 · 신리성지. 다섯 곳 모두 내부 모순이 없어 그대로 옮겼다.

## 🔴 그런데 — 번역이 화면에 하나도 안 나온다 (2026-08-24)

감수한 영어가 실제로 보이는지 확인하려고 언어를 EN 으로 두고 신리성지를 열었더니
**성지 내용이 전부 한국어였다.**

```
grep -rln "holy_site_translations|translation" src/
  → src/shared/i18n/dictionary.ts   ← UI 라벨 사전일 뿐
```

**앱 어디에서도 `holy_site_translations` 테이블을 읽지 않는다.**
`holy-sites.repository.ts` 는 전부 `holy_sites` 만 조회한다(`select('*')`).
언어 토글 KO/EN 은 **버튼·제목 같은 UI 문구만** 바꾼다.

| | 상태 |
| --- | --- |
| DB 영어 번역 | **72곳** |
| 그중 감수 완료 | **9곳** |
| **화면에 나오는 것** | **0곳** |

### 왜 이게 가장 큰 문제인가

- **WYD 2027 논리 전체가 다국어 위에 서 있다.** 해외 청년 20~30만 명이 근거인데,
  앱은 영어로 성지를 읽을 수 없다
- 사업계획서에 **"대전교구 27곳 영어 100% 완료"**를 강점으로 써 놨다
- 심사위원이 EN 으로 토글하면 **UI 라벨만 영어가 되고 내용은 한국어** —
  다국어가 있다는 사실이 오히려 **미완성으로 읽힌다**

### 우선순위를 바꾼다

**번역을 더 하는 것보다, 있는 번역을 보이게 하는 것이 먼저다.**
남은 21곳 재번역은 그다음이다. 재료는 이미 다 있다 —
72곳 데이터 · 언어 설정(`language`) · 감수 등급(`translation_status`).

필요한 것: 저장소에서 번역을 함께 조회 → 언어가 `en` 이면 번역을 쓰고,
**없으면 한국어로 떨어뜨린다**(fallback). 초벌(`machine`)임을 화면에 밝히는 것도 함께 검토한다.

*남은 재번역 16곳* — 백업 대조로 목록이 확정돼 있다.

**⑥ 안정성 점검** — 구현성 30점의 "안정성"
- 네트워크 실패 / TourAPI 한도 초과(에러 23) 시 화면이 깨지지 않는가
- 로딩 상태, 빈 상태, 오류 상태가 모든 화면에 있는가
- 모바일 뷰포트, 큰 글자 모드, 다국어 토글

### W4 (9/14~9/21) — 기능 동결, 제출물

**신규 기능 추가 중단.** 발표자료·데모 영상·버그 수정만.
- 심사 4항목별 대응 슬라이드
- **TourAPI를 저장하지 않는다는 설명을 발표자료에 명시** — 심사위원 오해 방지
  (`holy_sites`는 자체 수집 자산이라 저장해도 무방하다는 구분)
- 화면 녹화 데모
