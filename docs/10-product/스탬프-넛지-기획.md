# 스탬프 넛지 기획 — 사람들이 스스로 쓰고 스스로 공유하게 만드는 장치

작성: 2026-09-01 (웹 세션). 기획과 함께 1~6번 전부 코드로 구현됨 (아래 상태 표 참조).

## 왜 이 기획인가 — Strava 와 산티아고에서 배운 것

Strava 성장 분석(Contrary Research·community.inc)과 2024 Year in Sport
리포트에서 공통으로 확인되는 사실:

1. **활동이 끝나면 "자랑할 수 있는 예쁜 결과물"이 자동으로 생긴다.**
   GPS 궤적이 그 자체로 그림이 되는 지도 카드. 사용자가 만드는 게 아니라
   앱이 만들어 손에 쥐여준다.
2. **수집과 완주.** 배지·챌린지 — "다 모으고 싶다"는 본능.
3. **사회적 인정.** 2024 조사에서 운동 지속 동기 1위는 건강도 기록도 아닌
   "사회적 연결"이었다 (Kudos).
4. **연말 결산(Year in Sport).** 1년치 기록을 개인화 카드로 만들어주면
   사람들이 알아서 SNS에 퍼나른다. Spotify Wrapped 와 같은 구조.

단, **Strava 의 경쟁 장치(리더보드·KOM)는 이식하지 않는다.** "고요 속으로"
라는 앱의 톤과 정면 충돌하고, 성지에서 속도 경쟁은 부적절하다.

순례 도메인의 선례는 **산티아고 순례길의 credencial(순례 여권)**이다.
숙소·성당마다 다른 도장(sello)이 찍힌 여권 사진은 지금도 인스타그램에서
가장 많이 공유되는 순례 콘텐츠다. 도장이 사랑받는 이유는 "다녀왔다는
증명"이 아니라 **도장마다 그 장소의 얼굴이 담겨 있어서**다.

**핵심 원리 한 줄: 사용자가 콘텐츠를 만들게 하지 말고, 사용자의 행동이
저절로 콘텐츠가 되게 하라.**

## 색다른 축 1 — 성지 건축 모티프 스탬프 ("성지 이모티콘")

교구별·성지별 도장의 그림을 **실제 성지의 건축·지형을 본뜬 선화(線畵)**로
만든다. 명동은 고딕 쌍탑, 약현은 벽돌 단탑, 해미읍성은 성곽, 배론은
옹기 토굴, 솔뫼는 솔숲 생가 — 여권을 펼치면 어느 하나 같은 도장이 없다.

- 구현: `src/features/passport/lib/stamp-motifs.ts` — 13종 모티프
  (viewBox 100×100 path 데이터). React SVG(`StampMotifIcon`)와
  Canvas(`drawStampMotif`) 양쪽에서 같은 그림을 그린다.
- **사실 원칙**: 건축이 문서로 확인된 13곳만 이름으로 매핑한다
  (명동·계산·공세리=고딕, 약현·풍수원=벽돌, 전동=로마네스크,
  되재·나바위=한옥, 해미읍성=성곽, 절두산·갈매못=물가, 솔뫼=솔숲,
  배론=토굴). 확인 안 된 곳에 아무 건물이나 그리면 그게 더미 데이터다 —
  분류(순교성지→기념비, 주교좌성당→성당, 역사사적지→비석, 순례길→길)의
  상징 도장으로 폴백한다.
- 확장 방법: 성지 건축이 확인될 때마다 `NAME_MOTIFS` 에 한 줄 추가
  (+ 필요하면 모티프 path 추가). 도슨트 현장조사(3.8)가 곧 이 목록을
  불리는 공급선이다.
- 전례 시기(기존 기능)는 그대로 **잉크 색**을 정한다 — 그림은 장소가,
  색은 시간이 정한다. 같은 성지라도 사순에 찍은 도장과 성모성월에 찍은
  도장이 다르다.

## 색다른 축 2 — 순례 별자리 (지도 대신 밤하늘)

연대기 카드는 지도를 그리지 않는다. 방문한 성지들을 **실제 위경도
그대로** 밤하늘의 별로 찍고, 시간순으로 옅어지는 선으로 잇는다 (지도
화면의 "시간이 지날수록 옅어지는 여정 선" 문법을 카드로 옮긴 것).
내 순례가 나만의 별자리가 된다 — 같은 별자리는 세상에 없다.

### 5번의 DB 요구사항 — 로컬에서 `npm run db:migrate`

`supabase/migrations/20260902000000_create_note_read_counts.sql`:

- `note_read_counts` 테이블 (stamp_id → read_count). **누가 읽었는지는
  저장하지 않는다** — 숫자 하나면 충분하고, 읽는 사람의 발자국은 과하다.
- 조회는 글쓴이 본인만(RLS). 남의 조회수는 비교거리가 되므로 비공개 —
  이 기능은 랭킹이 아니라 "읽혔다"는 확인이다.
- 증가는 `increment_note_reads` RPC 로만. 성지 상세에서 한 줄이 실제로
  화면에 보였을 때 1회 호출된다.
- **마이그레이션 적용 전에도 화면은 깨지지 않는다** — 코드가 오류를 조용히
  삼키고 숫자만 숨긴다. 적용되는 순간부터 세기 시작한다.

## 톤 가드레일 (이 기획이 지키는 선)

- 리더보드·랭킹·타인과의 비교 없음. 숫자는 전부 "나 자신의 축적"이다.
- 읽힘 수도 본인에게만 보인다.
- 더미 금지: 건축 도장은 확인된 곳만, 전국 성지 수는 DB 실측값
  (하드코딩 208 없음 — 교구별 합계로 계산), 좌표 없는 성지는 별자리에서
  "표시하지 못했다"고 정직하게 적는다.
- 공유는 항상 사용자가 버튼을 눌러야 일어난다. 자동 게시 없음.
