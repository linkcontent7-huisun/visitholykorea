# 오늘의 성지 일정 — 마음나침반 + 고요 속으로를 하나로 (스펙)

작성 2026-09-15. 결정은 사장님, 「실측」 표시는 이 날 코드·DB 를 직접 본 값.
우선순위 문서 `docs/DSH/2026-09-15-노력-대비-성과-우선순위.md` 의 **A-1** 이 이 스펙이다.
이 문서 하나로 개발자가 물어보지 않고 만들 수 있게 쓴다.

## 1. 한 줄과 목적

**마음에 맞는 성지 후보를 최대 3곳 카드로 보여 주고(카드마다 근거 태그 1개), 고른 성지 한 곳을 중심으로
하루 일정(오전 성지 → 점심 → 오후 관광지)을 짜 준다. 마음에 안 들면 답을 다시 하지 않고 카드로 돌아가 다른 곳을 고른다.**

| 심사 기준 | 이 화면이 답하는 방식 |
| --- | --- |
| 지정과제 **오버투어리즘 완화** | 하루의 축을 관광지가 아니라 **성지**에 둔다. 오후 관광지는 관광공사 집중률로 **덜 붐비는 곳**을 고르고, 붐빌 예정이면 말해 준다 |
| **관광데이터 활용** | 점심 · 오후 · 붐빔 · 집중률이 전부 TourAPI 실시간 (저장하지 않는다) |
| **완성 서비스** | 빈 결과 · 정보 없음 · 실패를 전부 정직한 문구로 처리한다. 더미 없음 |

고요 속으로(`/quiet`)는 없앤다. 그 자리(하단 탭 3번째 · 홈 큰 카드)를 이 화면이 채운다.

## 5. 결정 2 — 질문 8개 → 3개 (9/16: 결과를 바꾸는 답만 남김)

| 순번 | 질문 (화면 문구) | 선택지 | 필수 | 상태 변수 | 이 답이 하는 일 |
| --- | --- | --- | --- | --- | --- |
| 1 | 지금 마음에 가장 가까운 색을 골라 주세요 | 위로 · 새 시작 · 평온 · 어루만짐 · 감사 (색 원 5개, 그대로) | ✅ | `emotion` | **후보 집합**을 정한다 (`emotion_tag` 일치) |
| 2 | 어디서 출발하세요? | **「현재 위치 쓰기」 버튼이 첫 선택지**, 그 아래 시·도 17개 선택 (GPS 거부 · 미지원 때의 대안) | ✅ (둘 중 하나) | `origin: { lat, lng, label }` | **가까운 순 정렬 · 반경의 기준점** |
| 3 | 오늘 얼마나 시간을 낼 수 있으세요? | 반나절 · 하루 · **1박2일 이상** (라벨만 「이상」 추가) | ✅ | `timeBudget` | **반경과 일정 줄 수** (6절) |

진행 막대: `step / 3`. 「다음」 버튼은 필수 답이 없으면 비활성.

**질문 3 상세 — 「현재 위치 쓰기」**

| 상태 (`gpsStatus`) | 화면 |
| --- | --- |
| `idle` | 화면에 들어오면 **곧바로 위치 권한을 묻는다** (`requestGpsLocation`). 버튼 「📍 현재 위치 쓰기」가 위, 시·도 선택은 아래 「또는 출발 시·도 고르기」 |
| `loading` | 버튼 문구 「위치 확인 중…」, 비활성 |
| `granted` | 버튼이 「✓ 현재 위치에서 출발」 로 바뀌고 시·도 선택은 접힘. 「시·도로 고를게요」 작은 링크로 되돌림 |
| `denied` · `error` · `unsupported` | 한 줄 안내 「위치를 쓸 수 없어요. 출발 시·도를 골라 주세요」 + 시·도 선택 |

현재 위치를 쓰면 `origin.label` 은 「현재 위치」. 시·도를 고르면 `label` 은 시·도 이름, 좌표는 `REGION_COORDS`. 설정에 저장된 출발 시·도(`origin` 설정)가 있으면 지금처럼 미리 선택해 둔다.

**뺀 질문**

- **성별** — 묻지 않는다. "결과에 여성 피정 같은 표시만 붙이자" 했으나, 성별 정보는 피정의집 · 수도회 주소록에만 있고 성지 일정에는 붙을 자리가 없다. 나중에 「근처 피정의집」 줄이 생기면 그때.
- **참여 방식(혼자 조용히 / 누군가와 이야기)** — 1번과 같은 걸 두 번 묻는 셈이고, 답을 결과 문장 한 줄 말고는 어디서도 안 썼다.
- **자유 텍스트(마음에 담아두고 싶은 말)** — 9/16 사장님 결정. 저장만 하고 어디에도 안 보여줬다. `answers.note` 는 항상 `null`.
- **관심사 · 인원** — 9/16 사장님 결정. 성지도 일정도 안 바꾸고 결과 위 문장 한 줄씩만 바꿨다. 50대 이용자에게 결과가 안 바뀌는 질문은 손가락 품이다. `answers.concern` · `answers.party` 는 항상 `null`. 남은 셋은 전부 결과를 바꾼다 — 마음 = 후보 집합, 출발지 = 정렬·반경 기준점, 시간 = 반경·일정 줄 수.

저장은 `answers.gender = null`, `answers.style = null` 로 그대로 넣는다 — JSON 칸이라 **마이그레이션 없음**, 옛 응답도 그대로 읽힌다. `CompassAnswers` 타입은 그대로 두고 `origin` 을 추가한다: `{ kind: 'gps' | 'region', label: string }` (좌표는 저장하지 않는다 — 위치 정보는 남기지 않는다).

## 6. 결정 3 — 시간 답을 반경으로 쓴다

| 답 | 반경 (출발지 기준) | 결과 일정 줄 |
| --- | --- | --- |
| 반나절 | **20km** | 오전 성지 → 오후 관광지 (2줄) |
| 하루 | **60km** | 오전 성지 → 점심 식당 → 오후 관광지 (3줄) |
| 1박2일 이상 | **180km** | 1일차 3줄 + 「2일차 일정은 준비 중이에요」 한 줄 |

```ts
// course-matching.ts — 상수 한 곳. 써 보고 조정한다.
export const RADIUS_KM_BY_TIME = { 반나절: 20, 하루: 60, '1박2일': 180 } as const;
```

- 반경은 **대중교통 이용자 기준**이다 — 문 앞에서 문 앞까지 시속 20km 안팎, 왕복 이동이 머무는 시간을 넘지 않게. 반나절(4시간) 편도 1시간 ≈ 20km, 하루(9시간) 편도 2시간 ≈ 60km, 1박2일은 편도 3시간 남짓(KTX 갈아타기 포함) ≈ 180km. 사장님 결정 2026-09-15. 써 보고 조정한다.
- 반경 안에 갈 곳이 없으면 **몰래 반경을 넓히지 않는다.** 11절의 「없어요」 화면.
- 2일차는 지금 만들지 않는다. 「1박2일 이상」을 실제로 몇 %가 고르는지 `compass_responses` 로 본 뒤 결정. 「준비 중」 표시는 `CLAUDE.md` 규칙 4 그대로.

**후보 만들기 (알고리즘)**

```text
1. DB: holy_sites WHERE emotion_tag = 마음            ← 최대 62곳, 1회, TanStack 캐시
2. 좌표 없는 곳 제외                                  ← 1곳
3. 출발지 ↔ 성지 거리(haversineKm) 계산
4. 거리 ≤ 반경 만 남김                                ← 20 / 60 / 180km
5. 거리 오름차순 정렬                                 ← 동점 없음. 무작위 섞기(jitterShuffle) 제거
6. 앞 3곳 = 카드. 나머지는 「더 보기」용으로 보관 (3장씩, 반경 안 전부)
```

TourAPI 는 여기서 **부르지 않는다** (`pairWithAttraction` 삭제). 후보가 0이면 「없어요」 화면.
후보가 1~2곳이면 있는 만큼만 — 3장을 채우려고 반경을 넓히지 않는다.

이 표가 말하는 것 세 가지:

1. **반나절 20km 는 시·도 중심점으로는 거의 「없어요」다** — 서울 · 대구 · 전북 · 인천 · 충남만 카드가 찬다. 중심점이 시골 한복판인 시·도(경기 · 강원 · 경북 · 경남)가 특히 그렇다. 그래서 **출발지 질문은 「현재 위치 쓰기」가 첫 선택지**고, 시·도 선택은 GPS 를 거부했을 때의 대안이다 (5절).
2. **하루 60km 면 대부분 채워지지만** 부산 · 울산 · 경북 · 광주 · 전남 · 제주는 특정 감정(주로 새출발 22곳)이 0이다. 그 조합은 「없어요」 화면에서 「시간을 늘릴게요」로 간다 — 반경을 몰래 넓히지 않는다.
3. **1박2일 180km 는 전 시·도 · 전 감정이 채워진다.** 제주만 10곳(섬).

## 7. 결정 4 — 결과 화면 「후보 카드 3장 → 성지 1곳 중심 하루 일정」

세 가지 안 중 **(가)** 를 골랐다. (나) 성지 2곳 순례 · (다) 미사 시간 축 배치는 범위 밖.

### 7-1. 후보 카드 화면 — 결과의 첫 화면

```text
┌ 오늘의 성지 일정 ─────────────────────────────── ✕ ┐
│                                                      │
│  '위로'에 맞는 성지 3곳이에요                ← 공통 문구. 마음은 셋 다 같으므로 카드 태그로 안 쓴다
│                                                      │
│  ┌ [사진] ○○성지                          ┐          │
│  │  충남 당진 · 출발지에서 42km            │ ← 누르면 7-2 일정 화면
│  │  [가장 가까워요]                        │          │
│  └────────────────────────────────────────┘          │
│  ┌ [사진] △△성지                          ┐          │
│  │  충남 서산 · 55km                       │          │
│  │  [인근이 조용해요 · 추정]               │ ← 3장 중 인근 붐빔 점수 최저
│  └────────────────────────────────────────┘          │
│  ┌ [사진] □□성당                          ┐          │
│  │  경기 안성 · 71km                       │          │
│  │  [소개가 자세해요]                      │          │
│  └────────────────────────────────────────┘          │
│                                                      │
│  [ 더 보기 ]                                 ← 반경 안에 더 있을 때만. 다음 3장
│                       처음부터 다시            ← 작은 글씨, 질문 1로
└──────────────────────────────────────────────────────┘
```

**태그 규칙** — 한 성지에 태그 하나. 데이터로 증명되는 것만.

| 태그 | 근거 | 호출 | 문구 |
| --- | --- | --- | --- |
| **가장 가까워요** | 출발지 ↔ 성지 거리 1위 (계산) | 0 | 「가장 가까워요」 |
| **인근이 조용해요** | 카드 3장 중 인근 붐빔 점수 최저 **이면서 「조용」 등급(30 미만)** — A-2 와 같은 산식(8절). 셋 다 붐비면 아무에게도 안 붙는다 | 성지당 시설 1회 + 축제 1회(캐시) + 집중률 0~1 | 「인근이 조용해요 · 추정」 |
| **소개가 자세해요** | `contentQualityScore` 최고 (소개글 · 역사 · 사진 유무 — `course-matching.ts` 에 이미 있음) | 0 | 「소개가 자세해요」 |

- 1위가 겹치면(가장 가깝고 가장 조용) 그 성지는 「가장 가까워요」, 조용 태그는 다음 순위에게, 그다음 소개 태그도 같은 방식.
- 카드가 3장 미만이면 있는 만큼. 1장이면 「가장 가까워요」만. 2장이면 가까움 + (조용 또는 소개 중 남는 것).
- 붐빔 조회에 실패한 카드는 조용 태그 후보에서 뺀다. 3장 다 실패하면 조용 태그 없이 두 태그만.
- **쓰지 않는 태그**: 「마음에 꼭 맞아요」(셋 다 같아서 구분이 안 됨) · 「한적한 성지」(성지 안 사람 수를 잴 데이터가 없음 — 거짓 주장).

카드에는 이름 · 지역 · 거리 · 사진 · 태그만. 점심 · 오후는 카드에 안 보인다 — 3장을 한눈에 비교하는 화면이라 길어지면 안 된다.

### 7-2. 일정 화면 — 카드를 누르면

```text

│                                                      │

│  │ [사진]                                │            │
```

일정 화면은 **카드 화면에서 이미 받아 둔 응답**(시설 · 축제 · 집중률)으로 조립한다 — TourAPI 추가 호출 0.

### 7-2-1. 일정 줄마다 규칙

| 줄 | 데이터 | 문구 규칙 | 없을 때 |
| --- | --- | --- | --- |
| 결과 문장 | — | **없다.** 관심사 · 인원 · 시간 · 참여 방식 문장 전부 뺐다(9/16). 일정 자체가 답이다 | |
| **오전 성지** | 후보 큐의 현재 성지 | 이름 · `location` · 「출발지에서 N km」(정수 반올림, 1km 미만은 「1km 안」) | — |
| 인근 붐빔 | 8절 | 「인근 지역이 조용해요 · 오늘 축제 없음」 | 「인근 붐빔 정보를 불러오지 못했어요」 |
| **점심** | 시설 5km 응답 중 `맛집` 그룹 가장 가까운 1곳 | 「성지에서 N」 — 거리 표기 규칙 아래 | 「근처 식당 정보 없음」 한 줄 (숨기지 않는다) |
| **오후** | 시설 5km 응답 중 `볼거리` 그룹, 가톨릭 시설(`CATHOLIC_TITLE`) 제외, 8절 규칙으로 1곳 | 「성지에서 N」 + 집중률 있으면 「관광공사 예측 집중률 N% · 여유/보통/붐빌 예정」 | 「근처 볼거리 정보 없음」 |
| 붐빌 예정 안내 | 오후 관광지 집중률 ≥ 70 | 「오후에 붐빌 예정이에요 — 성지에 조금 더 머무르셔도 좋고, 근처 ◇◇도 있어요 [바꾸기]」. 바꾸기 = 오후 줄만 다음 후보로 | 다음 후보 없으면 [바꾸기] 없이 앞 문장만 |
| 2일차 | `timeBudget === '1박2일'` | 「2일차 일정은 준비 중이에요」 | |
| 숙박 | — | **이번엔 뺀다.** 2일차와 같이 간다 | |

**거리 표기 규칙** (`walkMinutes` · `haversineKm` 있음): 성지 ↔ 시설 거리가 **2km 이하면 「도보 N분」**, 넘으면 「N.N km」. 편의시설 반경이 5km 라 도보 60분 넘는 곳이 흔해서 원안의 "도보 N분" 을 이렇게 나눈다.

**링크**: 점심 · 오후는 지금처럼 카카오맵 새 창(`kakaoPlaceUrl`). 오전 성지 카드와 「이 일정으로 가 볼게요」는 `onSelectSite(id)` → 성지 상세 `#directions` (옛 `CompassPage` 그대로, `replace: true`).

### 7-3. 상태 모델 (컴포넌트 안, 저장 아님)

```ts
type CandidateTag = 'nearest' | 'quiet' | 'detailed';

interface Candidate {
  site: HolySite;
  distanceKm: number;                 // 출발지 → 성지
  quality: number;                    // contentQualityScore
  facilities: GroupedFacilities[] | null;  // 시설 5km 응답 (null = 조회 실패)
  crowding: CrowdingScore | null;     // 인근 붐빔 (null = 조회 실패)
  tag: CandidateTag | null;
  afternoonIndex: number;             // 오후 후보 중 몇 번째 (「바꾸기」)
}

interface PlanState {
  pool: HolySite[];          // 반경 안 후보 전부, 거리순 (DB 만)
  page: number;              // 0 = 첫 3장, 1 = 다음 3장 …
  candidates: Candidate[];   // 지금 보이는 3장 (시설·붐빔 응답 포함)
  selected: number | null;   // 카드를 눌렀으면 그 번호 → 일정 화면
}
```

「다른 후보 보기」는 `selected = null` 뿐이다 — 재호출 없음. 「더 보기」는 `page + 1` 로 다음 3장을 만들고 그 3장만 새로 조회한다.
화면을 닫으면(`reset`) 전부 비운다. 저장이 아니라 열려 있는 동안의 메모리라 TourAPI 규칙에 안 걸린다.

## 8. 붐빔 정보로 성지 쪽으로 이끈다 — 고요 속으로가 남기는 것

「해당 지역의 붐빔 정도」는 **별도 기능 A-2(성지 상세의 「인근 지역 붐빔」)** 으로 들어온다.
이 화면은 그것과 **같은 산식 · 같은 훅 · 같은 문구**를 쓴다. 붐빔은 `crowding-score.ts` 한 곳에서만 계산한다.

### 8-1. 두 자리, 다른 역할

| 자리 | 무엇을 재나 | 문구 | 하는 일 |
| --- | --- | --- | --- |
| **오전 성지 줄** | 성지 좌표 기준 **인근 지역** (축제 15km · 명소 3km · 집중률) — A-2 와 같은 값 | 「인근 지역이 조용해요 / 보통이에요 / 붐벼요」 + 근거 한 토막 | "여기서 하루를 시작하면 한적하다"는 근거. **성지가 조용하다고는 말하지 않는다** |
| **오후 관광지 줄** | 관광공사 **집중률 예측** — 관광지 이름별 0~100 | 「관광공사 예측 집중률 N% · 여유 / 보통 / 붐빌 예정」 | 붐비는 관광지를 **뒤로 미루거나 바꾸는** 근거 |

**등급 → 문구** (5등급 산식을 3문구로 접는다 — 50대 이상에게 「아주 조용 / 조용」 구분은 소음):

| `CrowdingLevel` (점수) | 오전 줄 문구 | 집중률 (오후 줄) | 문구 |
| --- | --- | --- | --- |
| 아주 조용 · 조용 (< 30) | 인근 지역이 **조용해요** | < 40 | 여유 |
| 보통 (30~49) | 인근 지역이 **보통이에요** | 40~69 | 보통 |
| 붐빔 · 매우 붐빔 (≥ 50) | 인근 지역이 **붐벼요** | ≥ 70 | **붐빌 예정** |

근거 한 토막은 `CrowdingScore.reasons[0]` 을 그대로 (예: 「오늘 축제 2건」 · 「주변 명소 7곳」 · 「관광공사 집중률 반영」). `isPartial`(시설 조회 실패) 이면 「추정 · 일부 정보 없음」을 덧붙인다.

### 8-2. 유도 규칙 — 세 가지뿐

1. **오후 관광지 고르기** — 볼거리 후보(가톨릭 제외, 거리순)에 집중률 이름 매칭(`tAtsNm` ↔ `title`, 공백 제거 후 포함 비교). 집중률 있는 곳끼리는 **낮은 순**, 없는 곳은 뒤에 거리순. 즉 같은 거리면 덜 붐비는 곳.
2. **붐빌 예정이면 한 줄 더** — 고른 관광지 집중률 ≥ 70 이면 안내 문구 + [바꾸기]. 바꾸기는 `afternoonIndex + 1`.
3. **성지 인근이 붐비면 숨기지 않는다** — 오전 줄에 「인근 지역이 붐벼요 · 오늘 축제 2건」 그대로. 그때는 카드로 돌아가 다른 후보를 고른다. 순위를 붐빔으로 바꾸지는 않는다 (거리순 유지 — 반나절에 붐빔 피하려고 먼 곳을 먼저 보이면 원칙 위반).

데이터가 없으면 그 자리에 「붐빔 정보 없음」. 광주 · 전남은 집중률 데이터 자체가 없다(실측).

### 8-3. 호출 수 (TourAPI 저장 금지 그대로)

| 언제 | 호출 | 비고 |
| --- | --- | --- |
| 카드 3장 | 시설 5km ×3 + 오늘 축제 ×1(캐시) + 집중률 ×0~1(캐시) = **4~5회** | 시설 응답은 점심 · 오후 후보 · 인근 명소 밀도 **겸용** (`dist` 필드로 3km 안만 셈) |
| 카드 누른 뒤 일정 | **0회** | 카드 화면에서 받아 둔 응답으로 조립 |
| 바꾸기 · 다른 후보 보기 | 0회 | |
| 더 보기 (다음 3장) | +3~4회 | 축제 · 집중률은 캐시 |

**결과 한 번에 4~5회, 갈아타기는 0회.** 더 보기를 두 번 눌러도 12회 안쪽 — 고요 속으로(화면당 7회)와 비슷하거나 적다.
축제는 `getOngoingFestivals`(날짜 단위, TanStack 캐시), 집중률은 메모리 6시간 캐시 `CONGESTION_TTL_MS` 그대로. 둘 다 화면 안 메모리라 저장 규칙에 안 걸린다.

### 8-4. 🔴 먼저 고쳐야 하는 것 — 집중률 결합이 지금 한 번도 작동하지 않는다

이어서-할-일 9/15(2) 실측: `tour-api.ts:508` 이 `signguCd` 없이 시·도 코드만 넘겨 **0행**, `quiet-sites.ts:66` 은 응답에 없는 좌표 필드로 매칭해 **항상 빈 값**.
A-2 와 이 화면이 같은 부품이라 **A-2 쪽에서 한 번 고친다**: (1) 성지 주소 → 시·도 + 시군구 코드(`ldongCode2`, 옛 코드 별칭 포함 — `congestion-coverage.ts` 에 이미 있음) (2) 좌표 대신 **이름 매칭**. 성지 32곳은 관광지 이름으로 올라 있어 오전 줄에도 실측이 붙는다.
이걸 안 고치면 오후 줄 집중률은 전부 「정보 없음」 — 화면은 안 깨지고, 오후 후보는 거리순이 된다.

| 뒤집힌다 | "붐비는 관광지 → 근처 성지" 가 아니라 **"성지에서 시작 → 오후 관광지는 덜 붐비는 곳"**. 발표에서 오버투어리즘 답은 이 화면 + A-2 |

## 9. 결정 5 — 「다른 후보 보기」 · 「더 보기」

- **답은 그대로 두고 성지만 바꾼다.** 카드 3장이 그 역할이다 — 순차 갈아타기 · 순번 큐 · 「앞서 본 성지」 스택은 없다.
- **다른 후보 보기** (일정 화면 → 카드 화면): `selected = null`. 호출 0. 카드의 태그 · 순서는 그대로다.
- **더 보기** (카드 화면): 반경 안 후보가 3장보다 많을 때만 보인다. `page + 1` → 다음 3장을 DB 보관분에서 꺼내 그 3장만 시설 · 붐빔 조회(3~4회). 태그는 **그 페이지 3장 안에서** 다시 매긴다. 반경 안 후보가 다 나올 때까지.
- 반경 안 후보를 다 보여줬으면 「더 보기」 자리에 「이 조건으로는 여기까지예요 — 시간을 늘리거나 마음을 바꿔 보시겠어요?」 + 「시간 바꾸기」(질문 4로) · 「마음 바꾸기」(질문 1로). 답은 유지된다.
- 기존 「다시 골라볼게요」(질문 1로)는 「처음부터 다시」 작은 링크로.
- 저장(`compass_responses`)은 **카드에서 성지를 처음 고른 때 1회**. `matched_site_id` = 고른 성지. 카드만 보고 나가면 저장하지 않는다.

## 12. 접근성 · 다국어

- 모든 버튼은 `<button>` · 링크는 `<a>`.
- 글자 「대」 모드에서 오전 · 점심 · 오후 라벨과 이름이 줄바꿈되어도 겹치지 않는다 (`truncate` 대신 두 줄 허용).
- 카드는 `<ul>` 안 `<button>` 3개. 태그는 색이 아니라 **문구**로 (「인근이 조용해요 · 추정」).
- 「바꾸기」 를 누른 뒤 포커스를 바뀐 줄로, 「다른 후보 보기」 뒤에는 방금 봤던 카드로 옮긴다 (`aria-live="polite"`).
- 색만으로 붐빔을 구분하지 않는다 — 문구가 항상 같이 간다.
- 새 문구는 전부 사전(`dictionary.ts`)에 ko · en. 나머지 언어는 en 값.

## 17. 완료 조건

1. 하단 탭 · 홈 카드 · 헤더에 「오늘의 성지 일정」이 보이고, 누르면 이 화면이 뜬다. `/quiet` · `/alternatives` · `/compass` 모두 이 화면. 고요 속으로 화면 · 메뉴 · 문구가 어디에도 없다 (22개 화면 스크린샷).
2. 질문이 3개다(마음 · 출발지 · 시간). 성별 · 참여 방식 · 자유 텍스트 · 관심사 · 인원을 묻지 않는다. 질문 2에 「현재 위치 쓰기」가 있고, 허용하면 그 좌표가 기준점이다 (거부 · 미지원은 시·도 선택).
3. 결과 성지는 반경 안 · 출발지에서 가까운 순이다. 서울 · 새출발 · 반나절 → 20km 안만, 하루 → 60km, 1박2일 → 180km (테스트).
4. 결과에 오전 · (점심) · 오후 줄이 시간 답대로 2줄 / 3줄 / 3줄 + 「2일차 준비 중」. 식당 · 볼거리가 없으면 「정보 없음」 줄 (도시 1곳 · 시골 1곳 스크린샷).
5. 성지 ↔ 시설 거리 2km 이하는 「도보 N분」, 넘으면 「N km」.
6. 오전 줄의 인근 붐빔이 A-2 상세 페이지와 **같은 값 · 같은 문구** (같은 성지 두 화면 대조 스크린샷). 주어는 항상 「인근 지역」.
7. 오후 줄에 집중률이 있으면 「관광공사 예측 집중률 N% · 등급」, 없으면 표시 없음. ≥ 70 이면 안내 + 「바꾸기」, 누르면 오후 줄만 바뀐다 (테스트).
8. 결과 첫 화면에 카드가 최대 3장, 거리순, 카드마다 태그 1개(겹침 없음). 「가장 가까워요」는 거리 1위, 「인근이 조용해요」는 3장 중 붐빔 최저(「추정」 표기), 「소개가 자세해요」는 품질 1위 (테스트). 후보가 1~2곳이면 있는 만큼 + 「반경을 넓히면 N곳」.
9. 카드를 누르면 그 성지 일정이 **TourAPI 재호출 없이** 뜬다 (네트워크 탭). 「다른 후보 보기」로 카드에 돌아오고 태그 · 순서가 그대로다. 「더 보기」는 반경 안에 더 있을 때만 보이고 다음 3장을 준다. 바닥나면 안내 + 시간 · 마음 바꾸기 버튼.
10. 후보 0곳이면 「없어요」 화면 + 두 버튼. 반경을 몰래 넓히지 않는다 (테스트).
11. TourAPI 호출이 카드 3장에 **4~5회**, 카드 누름 · 다른 후보 보기 **0회**, 더 보기 +3~4회 (네트워크 탭). 응답 저장 없음. 서비스워커 캐시에 TourAPI 없음.
12. 비로그인에서 전부 동작한다. 로그인 시 카드에서 성지를 처음 고른 때 `compass_responses` 1행.
13. 글자 「대」 · 영어에서 깨지지 않는다 (스크린샷 2장). `npm run verify` 통과.
