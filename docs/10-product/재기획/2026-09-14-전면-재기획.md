### 1-2. 저장소 코드에서 확인한 사실 (`4b0bccb`, `npm run verify` 통과 — 테스트 352개)

- 라우트 20개(`src/app/routes/paths.ts`). 하단 탭 5개 = 홈·지도·기록·홈화면추가·전체. 「고요 속으로」는 **독립 화면이 아니라 홈 섹션**(`TodayQuietSection`)이고 「더보기」가 `/alternatives`(붐빔 피하기)로 간다 → 같은 기능이 두 이름.
- 언어: 6개(`ko en es fr pt it`) 사전 576키 전부 채워짐. **기본 언어는 저장값 없으면 무조건 `ko`**, 브라우저 언어 감지 없음(`SettingsProvider.tsx:23-26`).
- 검색(`searchSites`): 한국어 이름·주소 + 번역 이름·로마자 주소. **교구·시도·지역명은 검색 대상이 아님.** 검색 화면에 AI 질문 버튼·Enter 키가 AI 로 연결됨. 상세 화면에 「이 성지에 대해 묻기」 버튼.
- 지도(`NationalMap`): 배경 없는 SVG 점 지도. 실제 타일 없음.
- 붐빔 지수(`crowding-score.ts`): 축제 50 + 명소 30 + 식음·숙박 20, 포화 곡선. 집중률(`TatsCnctrRateService`) 있으면 60:40 혼합.
  - **인프라 조회 실패 성지가 축제 점수만으로 낮은 점수를 받아 정렬에 그대로 참여** → 실패할수록 "조용" 1위(`quiet-sites.ts:179`).
  - 집중률은 시·군·구 이름 부분일치 후 **날짜 필터 없이 최댓값** 채택(`quiet-sites.ts:48-74`), 화면엔 "실측 집중률 N%" 확정 표기.
  - "실시간 붐빔 정보"(`dictionary.ts:457`), "N점 한적합니다"(`:3634`), 도보 분 = 직선거리÷4.5km/h(`alternatives.ts:82`).
  - 레포츠(28)·쇼핑(38) → "쉼터"(`nearby-facilities.ts:26-33`).
- TourAPI 클라이언트(`tour-api.ts`): **타임아웃 없음**, HTTP 429/5xx/네트워크 미구분(코드 22 만 특별 취급). `VITE_TOUR_PROXY_URL` 은 타입 선언만 있고 미사용. `tour-proxy` Edge Function 은 URL 화이트리스트만 있고 오퍼레이션·파라미터 제한·타임아웃·레이트리밋 없음.
- PWA: `navigateFallback` 미설정. 로그인 화면 약관 링크가 `navigate('/terms')` 라 **폼 상태가 초기화**됨. 약관 페이지는 하드코딩 한국어 3장 12조, 개인정보처리방침 별도 없음. `supabase/config.toml` `enable_confirmations=false`(로컬 기준; 운영 대시보드 값은 확인 못 함).
- `features/rest` 모듈은 화면 연결 없는 죽은 코드. `areaBasedList2`·`TarRlteTarService1`·`LocgoHubTarService1` 호출부 없음.

### 1-3. 제공 문서와 스키마에서 확인한 사실

- **`REFERENCE/` 폴더·`db_scheme.txt`·공고문·OT·OpenAPI 설명회 자료는 저장소에 없다.** 공모전 정보는 `docs/10-product/공모전/*` 의 2차 인용뿐. 스키마는 `supabase/migrations/*.sql` 31개로 대신 확인.
- 심사 배점: 구현성 30 / 기획력 30 / 데이터 활용 20 / 발전성 20 (`2026-08-공모전-출품컨셉.md:107-112`). 배제 조건 "TourAPI 활용 필수 + 개발 완료된 완성 서비스".
- OpenAPI 규칙: 문서상 "서버구축 방식(응답 저장)" 별도 신청 절차가 존재하나 미확정 → 실시간 호출 유지(`출품컨셉.md:293-298`, ADR 0002). 개발계정 1,000건/일.
- 승인 오퍼레이션 13종(`T-020 지시서`): KorService2·FreService2·SpnService2·KorWithService2·TatsCnctrRateService·TarRlteTarService1·LocgoHubTarService1·Odii·Durunubi 등. **EngService2 미신청.** 키 등급(개발/운영) 미확인.
- 마이그레이션: 9/2 까지 17개 적용 기록. **9/5 이후 9개(보안 3개 포함)는 적용 기록 없음.**
- DB 권한(31개 마이그레이션 전수):
  - `profiles`: `role`·`diocese` 는 컬럼 GRANT + 트리거 이중 방어 ✅ (`20260914110000`, `20260914120000`)
  - **`pilgrimage_stamps`: `hidden`·`photo_featured` 보호 없음 ⚠️** — `stamps_update_own` 이 전 열 UPDATE 허용, INSERT 도 컬럼 제한 없음. 일반 회원이 자기 사진을 대표 사진으로 승격하거나 신고 숨김을 해제할 수 있음.
  - `stamp_photos` select 정책 `using(true)` — 숨긴 스탬프의 사진 URL 도 anon 조회 가능.
  - `events` anon INSERT 무제한. storage `pilgrim-photos` update 정책에 `with check` 없음.
  - `site_visit_notes` 뷰는 `hidden=false` 필터 ✅, `directory_public` DML REVOKE ✅.

## 2. 새 서비스 기획서

### 2-1. 서비스 정의

> Visit Holy Korea는 붐비는 유명 관광지 대신 조용히 머물 수 있는 한국 가톨릭 성지와 주변 지역을 발견하고, 실제 방문을 준비하도록 돕는 전국 성지순례 안내 서비스다.

기능의 중심: 성지 발견 · 지역 탐색 · 신뢰할 수 있는 방문 정보 · 실제 이동 준비 · 관광객의 지역 분산 · 한국어/영어 지원.
"마음에 필요한 쉼표" 정서는 문구·톤으로만 남기고, 감정 설문·AI 대화는 중심에서 뺀다.

### 2-2. 사용자

**주요 사용자 — 국내 중장년 순례자** (하루·반나절 순례 준비). 반영 특성: 조작 최소, 위치·방문 가능 여부를 빠르게, 전화·홈페이지·미사·개방·주차·대중교통 정보 우선, 큰 글자·큰 버튼, 비회원 탐색, 가족·모임 공유.
("50대 이상이 많다"는 가설로 두고 통계로 적지 않는다.)

**확장 사용자 — 2027 WYD·DID 를 위해 방한하는 외국인 청년.** 같은 흐름 위에: 영어 성지명·지역명 검색, 로마자 주소 + 한국어 원주소 병기, 외부 지도·대중교통 연결, 현재 지역 주변 성지, 짧고 검증된 역사, 공식 출처, 가벼운 화면, WYD/DID 공식 안내 링크.
**WYD·DID 공식 협력 서비스라고 표현하지 않는다.** 등록·일정·숙박·단체 이동은 공식 채널 링크로만.

### 2-3. 핵심 사용자 여정

**여정 A — 고요 속으로 (공모전 대표 기능)**
관광지·지역 검색 → 관광데이터 기반 예상 붐빔 정도 확인 → 주변의 비교적 한적한 성지 발견 → 추천 근거·직선거리·이동 부담·데이터 한계 확인 → 성지 방문 정보 → 외부 지도로 이동 준비.
분기: 원래 장소가 이미 「조용」 이하 → "이동을 권하지 않음" 안내. 대안 없음/데이터 부족 → 추천하지 않고 이유 표시. TourAPI 실패·일부 실패 → 해당 후보는 「확인 부족」으로 분리, 순위에서 제외.

**여정 B — 성지 찾기**
성지명/영문명/교구/시도/지역명(한·영) 검색 또는 지역 목록 → 결과 → 상세(방문 정보→연락처→주소·지도→교통·주차→역사→주변 관광→기록) → 전화·홈페이지·외부 지도.

**여정 C — 내 기록 (선택, 회원)**
성지 검색으로 장소 선택 → 방문일·짧은 메모 → 비공개 저장 → 수정·삭제.

### 2-4. 완료 기준 (사용자가 화면에서 목표를 끝낸 것을 근거로)

1. 비회원이 한국어·영어로 성지명·지역명을 검색해 상세에서 전화·홈페이지·외부 지도를 연다.
2. 관광지 이름으로 고요 속으로를 실행해 붐빔 정도·대안·근거·한계를 보고 성지 상세로 이어간다.
3. TourAPI 를 끊어도(키 없음·네트워크 차단) 1번이 그대로 되고, 붐빔 영역만 "외부 API 실패"가 뜬다.
4. 390px 에서 가로 넘침 없음, 큰 글자 모드에서 주요 버튼 사용 가능.
5. `npm run verify` 통과.

| 순례 여권·인증서·공유 카드·스탬프 장식 | **축소** | 내 기록은 장소·방문일·메모·비공개·수정·삭제만. 인증서·공유는 더보기 안 「준비 중」 아님 → 화면에서 뺌(코드 유지) |
| 즐겨찾기·여행기 쓰기·관리자 | 유지(제출판 플래그로 숨김 가능) | 기존 `VITE_SUBMISSION_MODE` 그대로 |
| 언어 6개 | **ko·en 만 노출** | es/fr/pt/it 사전은 남기되 선택기에서 숨김. 저장값이 그 언어면 en 으로 |
| 도슨트 오디오 | 유지 | 상세 「역사와 순례 의미」 안 |
| 홈화면 추가 탭 | **하단 탭에서 제거** | 더보기 안으로 |
| Capacitor | 유지(빌드 대상 아님) | 출시 약속 안 함 |


### 4-1. 화면별 요구사항

**홈** (순서 고정)
1. 문제 정의 한 문장 + 서비스 정의 부제
2. 고요 속으로 진입 카드(관광지 검색 입력 포함)
3. 지역별 성지 찾기 — 17개 시·도 칩(한/영), 누르면 `/region/:region`
4. 추천 성지 — 출발지·현재 위치 기준 가까운 순 4~8곳(있을 때만)
5. 처음 방문하기 좋은 성지 — 사진·연락처·좌표가 모두 있는 성지 중 4곳(자체 DB 기준, 임의 큐레이션 아님을 표기)
6. 정보의 출처와 이용 방법 — 자체 데이터/한국관광공사 OpenAPI 실시간 구분 안내
7. 문의와 정보 수정 제안 — 연락 방법(운영자 확정 필요 표기)

**성지 찾기**
- 입력 하나로 성지명·영문명·교구명·시도명·지역명(한/영)·주소 검색.
- 필터: 교구(15) / 행정지역(17 시·도) — 서로 다른 개념임을 라벨로 구분. 방문 목적(감정 태그 5) / 이동 조건(현재 위치 반경·출발 지역).
- 결과 카드: 이름·지역·거리(있을 때, 직선거리 참고값)·전화 아이콘·상세.
- 상태: 조회 중 / 결과 없음 / 자체 데이터 없음 / 다시 시도.

**고요 속으로**
- 1단계 관광지·지역 검색(TourAPI `searchKeyword2`, 지역명이면 시·도 중심).
- 2단계 선택 → 원래 장소의 예상 붐빔(등급 + "관광데이터 기반 예상" 표기) → 대안 성지 최대 3곳(등급·직선거리·근거·한계) / 「확인 부족」 목록 / 이동 불필요 안내 / 대안 없음 안내.
- 금지 표현: 실시간 혼잡도·가장 조용·N점 더 조용·도보 N분·코스.

**성지 상세** (순서 고정)
1. 성지명·지역(교구 + 행정지역) 2. 대표 사진(크기 지정, 출처) 3. 방문 정보(미사 시간·예절·확인되지 않음 표시) 4. 공식 홈페이지·연락처 5. 주소(로마자+한국어)·외부 지도 6. 대중교통·주차(자체 DB 에 없으면 "확인되지 않음 · 성지 사무실 문의") 7. 역사와 순례 의미(+도슨트) 8. 주변 관광 정보(TourAPI, 실패 시 이 영역만 표시) 9. 방문 기록(회원)

**내 기록** — 최소 기능. **더보기** — 위 목록.

## 5. 데이터와 API 구조

```
브라우저 ──(REST, anon key, RLS)──▶ Supabase  holy_sites · holy_site_translations · directory_public · pilgrimage_stamps(본인) · profiles(본인)
브라우저 ──(GET /api/tour?op=…)──▶ Vercel 서버리스 /api/tour ──▶ apis.data.go.kr  (서비스키는 서버 환경 변수 TOUR_API_SERVICE_KEY)
```

`/api/tour` 규칙: 허용 오퍼레이션 목록(`searchKeyword2`·`locationBasedList2`·`searchFestival2`·`areaBasedList2`·`tatsCnctrRatedList`·`storyLocationBasedList`·`courseList`·언어 서비스 3종·무장애) · 허용 파라미터만 전달 · 임의 URL 불가 · 8초 타임아웃 · 429/5xx/타임아웃 구분(`{ error: { kind } }`) · 비밀값 제외 로그 · `Cache-Control: no-store` · 실패해도 앱은 자체 성지 탐색 유지.
로컬 개발: Vite 플러그인이 같은 핸들러를 `/api/tour` 로 띄운다(`TOUR_API_SERVICE_KEY` 는 `.env.local` 의 비-VITE 변수).
캐시: TanStack Query 메모리 1시간 이하, DB·SW·localStorage 저장 없음(ADR 0002). 코드 주석과 설정을 이번에 일치시킨다.

자체 데이터 관리 항목(권장, 이번 마이그레이션에 포함하지 않고 제안만): `site_sources`(있음) + `holy_sites.verified_at`·`verified_by`·`field_checked` 는 운영자 결정 후.

### T-R01 (P0) env 노출 수정 + TourAPI 동일 출처 중계

- 수정 파일: `src/shared/config/env.ts`, `src/shared/api/tour-api.ts`, `api/tour.ts`(신규), `api/_lib/tour-proxy-core.ts`(신규), `vite.config.ts`, `vercel.json`, `.env.example`, `src/shared/types/env.d.ts`

## 9. 미확인 사항과 운영자 확인 항목 (사장님)

1. **환경 변수** — 이 노트북엔 `.env.local` 이 없다. 로컬 확인에 필요한 값: `VITE_SUPABASE_URL`·`VITE_SUPABASE_ANON_KEY`(공개값, 번들에서 복사 가능), **`TOUR_API_SERVICE_KEY`(서버용, 새 이름)**, `SUPABASE_DB_URL`(DB 검사·마이그레이션).
2. **Vercel** — `TOUR_API_SERVICE_KEY` 추가, `VITE_TOUR_API_SERVICE_KEY` **삭제**(노출된 키는 공공데이터포털에서 **재발급 권장**). `VITE_SUBMISSION_MODE` 결정.
3. **운영 DB** — 9/5 이후 마이그레이션 적용 여부, 이번 stamps 보호 마이그레이션 적용 승인.
4. **Supabase Auth** — 이메일 확인 켜짐 여부, Site URL·Redirect URL 운영값.
5. **문의 연락처·개인정보 책임자·보유기간** — 약관·개인정보 안내에 넣을 확정값.
6. **TourAPI 키 등급**과 EngService2 활용신청 여부(영어 주변 관광 정보용).
7. 공고문·OT·OpenAPI 설명회 원문 — 저장소에 없으므로 `docs/10-product/공모전/원본/` 에 넣어 주면 요건을 원문으로 대조한다.
