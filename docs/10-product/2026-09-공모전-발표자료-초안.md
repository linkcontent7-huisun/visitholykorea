# 관광데이터 활용 공모전 발표자료 초안 (2026-09-02 작성)

**심사 10월 · 시상 11월.** 발표 시간은 공고 확정 전이므로 **7분 기준**으로 짜고,
줄여야 하면 6·7번 슬라이드를 먼저 접는다.

> 이 문서는 **말할 것과 보여줄 것**을 정한다. 실제 슬라이드(PPT)는 이 순서
> 그대로 만들면 된다. 숫자는 전부 실측이고 잰 날짜를 함께 적었다 —
> 발표 직전에 `docs/이어서-할-일.md` 로 최신값을 다시 확인할 것.

## 발표의 한 문장

> **"모두가 '어디가 인기 있나'를 물을 때, 우리는 같은 데이터로 '오늘 어디가
> 비어 있나'를 계산합니다."**

이 문장이 8장 전체를 관통한다. 심사위원이 발표 후 한 문장만 기억한다면 이것이어야 한다.

## 슬라이드 구성 (8장 · 7분)

### 1. 표지 (15초)

- **Visit Holy Korea — 오늘 비어 있는 성지를 찾아주는 순례 안내**
- 배포 주소를 크게: `visitholykorea-app.vercel.app`
- 한 줄: 한국 천주교 성지 208곳 · 웹·Android·iOS 단일 코드베이스

> 말하기: "아이디어가 아니라 지금 열어보실 수 있는 서비스입니다."

### 2. 문제 (50초)

**두 개의 빈자리를 나란히 놓는다.**

| 여행 서비스의 문제 | 성지의 문제 |
| --- | --- |
| 전부 **인기순** — 붐비는 곳만 더 붐빈다 | 현장에 **설명이 없다** |
| 조용한 자원은 검색되지 않는다 | 240년 순교 역사가 콘텐츠화되지 않았다 |

- 실측 근거: 자체 수요조사 **n=20 — "성지에 가도 설명이 부족하다" 100% 공감**,
  필요 기능 1위가 '성지 해설'(60%)
- 오버투어리즘 분산은 **한국관광공사의 공식 정책 과제**이기도 하다

> 말하기: "이 두 문제는 사실 하나입니다. 사람이 몰리는 곳에는 설명이 필요 없고,
> 설명이 필요한 곳에는 사람이 오지 않습니다."

### 3. 역발상 — 데이터를 뒤집는다 (80초) ⭐ **핵심 슬라이드**

**같은 TourAPI로 반대 질문을 한다.**

```
인기순 API  →  "오늘 사람이 몰리는 곳"  →  (뒤집기)  →  "오늘 비어 있는 곳"
```

- 전국 축제·행사를 **한 번의 호출로** 받아 성지와의 거리를 직접 계산한다
  → 호출 수가 성지 수(208)에서 **1**로 줄어든다
- 붐빔 지수 **산식을 공개**한다 (숨기면 신뢰가 안 생긴다)
- **추정치는 추정이라고 화면에 적는다**

> 화면 시연: 홈 "오늘 조용한 성지" → `/alternatives` 붐비는 관광지 검색 →
> 대신 갈 조용한 성지 제안
>
> 말하기: "경복궁이 붐빌 때 행주산성을 권하면 안 됩니다 — 둘 다 '매우 붐빔'
> 등급이니까요. 그래서 점수가 아니라 **등급**을 비교하도록 고쳤습니다."

### 4. 차별점 — 크롤링으로 못 베끼는 것 (90초)

**① 오디오 도슨트** (수요조사 니즈 1위)
- 208곳 기본 해설 + 13곳 포인트별 투어(한·영)
- 박물관처럼 **챕터를 골라 듣는다** · 속도 조절 · 해설 전문 표시
- 현장 검증 전 원고에는 **"초안" 배지**를 단다

**② 순례 여권 — 성지 건축이 도장이 된다**
- 명동=고딕 쌍탑 · 약현=벽돌 단탑 · 해미읍성=성곽 · 배론=옹기 토굴
- **건축이 문서로 확인된 13곳만** 매핑, 나머지는 분류 상징으로 폴백
- 잉크 색은 **방문한 날의 전례 시기**가 정한다 → 같은 여권에 같은 도장이 없다

> 화면 시연: 성지 상세 → 스탬프 찍기(건축 도장 등장) → 여권(도장 그리드·별자리)
>
> 말하기: "이 도장은 공공데이터에 없습니다. 저희가 성지의 건축을 조사해서
> 하나씩 그린 것입니다. 크롤링으로는 만들 수 없습니다."

### 5. 접근성과 다국어 (50초)

- **영어 208/208곳 완역** · 6개 언어 UI
- 큰글자 · TTS · 속도 조절 (신자 **65세 이상 28.9%**)
- 방문 에티켓 안내 — 종교 시설이 낯선 사람이 문 앞에서 멈추지 않도록
- **무장애 여행 정보** (한국관광공사 실시간, 활용신청 승인 대기)

> 말하기: "성지는 계단과 언덕이 많습니다. '갈 수 있는가'가 먼저 걸리는데
> 그 정보를 지금 아무도 안내하지 않습니다."

### 6. 시의성 — WYD 2027 (50초)

- **2027.8.3~8.8 서울**, 교구대회 7.29~8.2 전국 15개 교구
- **비그리스도교 국가 최초** WYD → 세계가 한국을 주목한다
- 최대 80만 명, **해외 청년 20~30만 명**
- 수호성인 **성 김대건 안드레아와 동료 순교자**, 공식 일정에 솔뫼·해미
- 앱에는 이미 **WYD 2027 한정 스탬프**가 준비돼 있다 (대회 기간에만 찍히는 금빛 기록)

> 말하기: "한국의 성지가 대회의 무대 그 자체입니다. 그런데 이들을 외국어로
> 안내할 서비스가 없습니다."

### 7. 정직함이 설계다 (40초) ⭐ **차별화의 진짜 축**

| 우리가 숨기지 않는 것 | 어떻게 |
| --- | --- |
| 사진이 없는 성지 | 회색 이모지 대신 **분류별 문양 카드** — 사진인 척하지 않는다 |
| 붐빔은 추정 | "추정치"라고 화면에 적는다 |
| 도슨트 원고가 초안 | **"현장 확인 전"** 배지 |
| AI가 모르는 것 | 검증 자료 밖이면 **"모른다"고 답한다** |
| 학계 논쟁 중인 사실 | 김범우 유배지 — 두 성지의 근거를 **나란히** 싣는다 |

> 말하기: "종교 정보는 틀리면 신뢰가 즉시 무너집니다. 그래서 모르는 것을
> 모른다고 말하는 것이 이 서비스의 기능입니다."

## 시연 시나리오 (발표 중 화면 전환 순서)

**원칙: 로그인 없이 보이는 것부터.** 심사 현장에서 로그인이 막히면 발표가 멈춘다.

1. **홈** — 오늘 조용한 성지 (TourAPI 실시간 호출이 도는 것을 보여준다)
2. **붐빔 피하기** — 유명 관광지 검색 → 조용한 대체 성지
3. **성지 상세** — 오디오 도슨트 재생 (10초만) → 아래로 스크롤해 주변 정보
4. **언어 전환** — 영어로 바꿔 같은 화면 (WYD 대비 증거)
5. **스탬프 찍기** — 건축 도장이 찍히는 순간
6. **여권** — 도장 그리드 · 교구별 진행 · 별자리 카드 생성

> ⚠️ **사전 점검** (발표 전날):
> - 안드로이드·아이폰 실기기에서 위 6단계 전부 통과
> - TourAPI 일일 한도 여유 확인 (`npm run tourapi:check`)
> - 스탬프가 최소 3개는 찍혀 있어야 여권 화면이 비지 않는다 → **베타 테스터
>   데이터가 없으면 발표자 계정으로라도 실제 방문 기록이 있어야 한다**
> - 네트워크가 끊길 때를 대비해 **화면 녹화본**을 준비 (실시간 API 화면 포함)

## 예상 질문과 답

| 질문 | 답 |
| --- | --- |
| "TourAPI 응답을 저장하나요?" | **저장하지 않습니다.** 매 요청 실시간 호출이고 서비스워커 캐시에서도 제외했습니다(ADR 0002). 저장하는 것은 저희가 직접 수집한 성지 208곳 데이터뿐입니다 |
| "사진이 왜 이렇게 적나요?" | 24.5%입니다. 자동 수집 4경로를 모두 소진했고 남은 157곳은 현장 촬영뿐입니다. 그래서 **실방문자가 올린 사진을 대표 사진으로 승격**하는 길을 만들었습니다 |
| "붐빔 지수는 정확한가요?" | 추정입니다. 그래서 화면에 추정이라고 적고, **다녀온 사람의 한 줄 기록**으로 보정합니다 |
| "종교 편향 아닌가요?" | 데이터 모델은 종교 중립적입니다. 사찰·서원·고택 등 '조용한 유산' 전체로 확장 가능하게 설계했습니다 |
| "혼자 만들었나요?" | 1인 창업이고 AI 협업으로 개발했습니다. 외주 없이 배포까지 완주했고, 매 커밋마다 테스트 293개가 돕니다 |
| "수익은 어떻게?" | 앱은 무료로 두고 프로그램 예약 중개·숙박 제휴로 수익화합니다. 현재는 검증 단계라 수익이 없습니다 |
