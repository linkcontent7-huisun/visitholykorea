## 1단계 — 데이터 채우기 (최우선)

기능보다 데이터가 먼저다. 좌표가 없으면 코스 추천이 동작하지 않고, 사진이 없으면 화면이 비어 보인다.

**2026-08-11 실제 DB 조회 결과로 이 절을 고쳐 썼다.** 이전 서술("좌표 미확보 다수")은
`location_retry_summary.md` 를 좌표 조사 기록으로 오해한 것이었다. 그 문서는 **이미지**를
TourAPI 로 찾으려던 기록이다. 실측값은 아래와 같고, **병목은 좌표가 아니라 사진이다.**

| 항목 | 확보 | 미확보 | 상태 |
| --- | --- | --- | --- |
| 좌표 (`lat`/`lng`) | 207 / 208 | 1 | ✅ 사실상 완료 |
| 감정 태그 | 204 / 208 | 4 | ✅ 사실상 완료 |
| 소개글 | 207 / 208 | 1 | ✅ |
| **대표 사진** | **14 / 208** | **194** | 🔴 **여기가 병목** |
| 전화번호 | 115 / 208 | 93 | 🟡 |

- [ ] **대표 사진 194곳 — 직접 촬영** (`docs/30-content-ops/` 매뉴얼대로).
      현장에 가야만 생기므로 [대전 현장검증](../30-content-ops/대전-현장검증-계획.md)이 곧 이 작업이다
- [ ] 감정 태그 4곳 — 수원 화성 순교성지 · 기장 성지 · 울산 장대 순교지 · 울산 죽림굴.
      (수원 화성은 소개글도 함께 비어 있다)
- [ ] 좌표 1곳 — 제주 "산토비아조 순례길". 제주 전역을 도는 **길**이라 점 좌표가 없는 게 맞다.
      채울 값이 아니라 **붐빔 계산 대상에서 뺄지**를 정해야 하는 항목이다
- [ ] TourAPI 유래 이미지 정리 — ADR 0002 의 미해결 항목
- [ ] 전화번호 93곳 — 급하지 않음. 교구 주소록으로 일괄 보완 가능

## 1.2단계 — TourAPI 운영계정 전환 (9월 초 마감, 놓치면 심사 당일 위험)

개발계정 일일 한도는 **1,000건**이고 홈 화면 1회 로드가 **22건**을 쓴다 →
**하루 45번 열면 그날 서비스가 멈춘다.** 운영계정으로 바꾸면 100,000건이 된다.
승인에 약 1주일이 걸리므로 **늦어도 9월 초 신청.** 근거는
[공모전 출품컨셉 10장](2026-08-공모전-출품컨셉.md).

- [x] 홈 화면 동시 호출 제한 — `tour-api.ts` 세마포어 4개 (에러코드 23 회피, 8/12)
- [ ] **배포 URL 확정** (운영계정 신청서에 필요) ← 이것부터
- [ ] 공공데이터포털에서 운영계정 신청 — **9월 초** (승인 1주일)

## 1.5단계 — 미적용 마이그레이션 반영 (완료, 2026-08-12)

마이그레이션 파일 3개가 DB 에 적용된 적이 없어 여행기·번역이 막혀 있었다.
`SUPABASE_DB_URL` 을 넣자 한 번에 풀렸다. 자세한 경위는
[ADR 0006](../20-architecture/adr/0006-db-migration-old-to-new.md).

- [x] `.env.local` 에 `SUPABASE_DB_URL` 넣기 (Session pooler URI)
- [x] `npm run db:migrate` — 8개 전부 적용, 이력 테이블에 기록됨
- [x] 대전 27곳 영어 번역 DB 반영 — `holy_site_translations` 에 27행 (상태 `machine`, 초벌)
- [x] 여행기 기록 화면 동작 확인 — `/records` 정상, 탭 2개(여행기·스탬프) 렌더링

남은 것: 번역 상태가 아직 `machine`(기계 초벌)이다. 심사 전에 사람이 한 번 훑어
`human` 으로 올려야 한다 — 성지명·순교사 용어는 기계번역이 틀리기 쉽다.
