# ADR 0004. AI 가이드 '미카엘'은 Edge Function 을 거치고, 답변 범위를 성지 DB로 제한한다

- 날짜: 2026-08-04
- 상태: 채택

## 맥락

두 가지 문제가 있었다.

**첫째, 키 노출.** 기존 구현은 `vite.config.ts` 의 `define` 으로 `GEMINI_API_KEY` 를
클라이언트 번들에 심었다. 빌드 결과물에서 키를 그대로 꺼낼 수 있고, 남이 우리 할당량을 쓸 수 있다.

**둘째, 환각.** LLM 은 맥락상 그럴듯한 다음 단어를 고를 뿐 사실을 검증하지 않는다.
순교자 이름, 박해 연도, 시복·시성 여부 같은 정보는 틀리면 신뢰가 즉시 무너지는 영역이다.
특히 신자 이용자에게는 사소한 오류도 서비스 전체의 신뢰를 깎는다.

## 결정

Gemini 호출을 Supabase Edge Function `ai-guide` 로 옮긴다.

1. 키는 함수 시크릿(`supabase secrets set GEMINI_API_KEY=...`)으로만 존재한다.
2. 질문이 오면 먼저 `holy_sites` 에서 관련 레코드를 최대 5건 찾아 프롬프트 컨텍스트로 넣는다(간이 RAG).
3. 시스템 프롬프트에 "컨텍스트에 없는 사실은 지어내지 말고 모른다고 답하라"를 명시한다.
   모를 때의 대사까지 고정해 두었다 — "부끄럽지만 저 미카엘 천사도 잘 모르는 부분이에요.
   공식 홈페이지나 성지 사무실을 통해 당일 확인을 부탁드려요."
   페르소나를 지키면서도 "모른다"를 분명히 말하게 하는 장치다.
4. 답변은 마크다운으로 오고, 앱은 `react-markdown` + `remark-gfm` 으로 렌더링한다.
   일정·코스를 물었을 때만 표를 쓰도록 프롬프트에서 분량을 강하게 제한한다.

## 대가

- 응답에 Edge Function 왕복이 한 번 더 붙는다. 체감은 크지 않다.
- 함수가 배포돼 있지 않으면 AI 기능이 동작하지 않는다. 실패 시 앱은 고정 안내 문구로 떨어진다
  (앱 전체가 죽지는 않는다). **배포는 아직 남은 작업이다.**

## 나중에

성지가 200곳 수준이라 지금은 이름·주소·설명 부분 일치 검색으로 충분하다.
성지별 상세 콘텐츠(인터뷰, 성물 기록)가 쌓여 문서 수가 크게 늘면
pgvector 임베딩 검색으로 바꾼다.
