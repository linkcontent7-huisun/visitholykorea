# ADR 0001. 웹 하나로 Android · iOS 까지 — PWA + Capacitor

- 날짜: 2026-08-04
- 상태: 채택

## 맥락

"안드로이드에서도 애플에서도 되게 해달라"는 요구가 있다. 선택지는 세 가지였다.

1. **React Native / Expo 로 다시 만든다** — 네이티브 성능과 느낌은 가장 좋지만,
   이미 만든 React 웹 화면을 전부 다시 써야 한다. 웹 버전은 따로 유지해야 한다.
2. **PWA 만 한다** — 비용이 가장 싸지만 iOS 에서 푸시·설치 경험이 제한적이고,
   앱스토어에 올릴 수 없다.
3. **PWA + Capacitor** — 웹 코드를 그대로 두고 네이티브 웹뷰로 감싼다.
   앱스토어·플레이스토어 배포가 가능하고, 필요할 때만 네이티브 플러그인을 붙인다.

## 결정

**3번을 택한다.** 기존 React/Vite 코드를 살리면서 세 플랫폼을 한 번에 얻는다.

- 웹은 `vite-plugin-pwa` 로 설치 가능한 PWA 로 만든다.
- 네이티브는 `capacitor.config.ts` 기준으로 `npx cap add android|ios` 로 생성한다.
- 생성된 `android/`, `ios/` 는 커밋하지 않는다. 언제든 다시 만들 수 있고,
  커밋하면 두 개의 거대한 생성물이 diff 를 덮어버린다.

## 이 결정이 코드에 남기는 것

- 화면 코드에 플랫폼 분기를 넣지 않는다. 차이는 CSS `safe-area-inset-*` 와
  Supabase 세션 옵션(`detectSessionInUrl: false` — 웹뷰에는 URL 해시 콜백이 없다)에서만 다룬다.
- 라우팅은 `createBrowserRouter` 를 쓴다. SPA 라 웹뷰에서도 실제 파일 요청이 일어나지 않는다.
- 이미지·폰트를 CDN 에 의존하지 않도록 점차 로컬로 옮긴다(오프라인 대응).

## 뒤집어야 한다면

지도 실시간 렌더링이나 백그라운드 위치 추적처럼 웹뷰 성능이 한계에 닿는 기능이 핵심이 되면,
해당 화면만 네이티브로 떼어내거나(하이브리드) React Native 재작성을 다시 검토한다.
지금 시점에는 그런 기능이 로드맵에 없다.
