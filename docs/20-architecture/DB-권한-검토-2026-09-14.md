## 2. profiles — 안전

- 회원이 쓸 수 있는 열은 `name, country_code, companion_count, is_guided_tour, travel_profile_prompted_at` 다섯 개뿐이다. `role`·`diocese`·`email`·`provider`·`id` 는 표 단위 UPDATE 를 걷어낸 뒤 열 단위로 다시 주지 않았다 (`20260914110000:10-12`).
- 트리거 `profiles_protect_role` 이 `current_setting('role', true) in ('anon','authenticated')` 일 때 role·diocese 변경을 42501 로 막는다 (`20260914120000:16-29`). 관리자 지정은 `npm run admin:grant`(postgres 직결, `role` 설정값 없음) 로만 하므로 이 조건이 맞다.
- insert 정책이 없으므로 회원이 `role='admin'` 행을 새로 넣을 수도 없다. 가입 시 행은 definer 트리거 `handle_new_user` 가 만든다 (`20260818020000:29-50`).
- profiles 를 만지는 definer RPC 가 없으므로, 아래 스탬프에서 문제가 된 "definer 함수 안에서도 role 이 authenticated 로 보인다"는 함정에 걸리지 않는다.

## 3. pilgrimage_stamps — 취약 (이번 마이그레이션으로 잠금)

정책은 "본인 행"만 검사하고 열은 보지 않는다. Supabase 기본 권한이 `authenticated` 에 표 전체 INSERT/UPDATE 를 주므로, 앱의 anon 키 + 본인 세션 토큰만으로 아래가 통한다. **실제로 실행하지 않았다** — 코드 읽기로 확인한 재현 시나리오다.

```bash
# (1) 운영자가 숨긴 내 글을 다시 공개 — 신고 3건 자동 숨김(report_visit_note)도 같은 방법으로 무력화
curl -X PATCH "$SUPABASE_URL/rest/v1/pilgrimage_stamps?id=eq.<내 스탬프 id>" \
  -H "apikey: $ANON_KEY" -H "Authorization: Bearer <내 access_token>" \
  -H "Content-Type: application/json" -d '{"hidden": false}'

# (2) 내 사진을 성지 대표 사진으로 승격 — site_featured_photos 뷰(20260903000000:24-36)가 그대로 노출
curl -X PATCH "$SUPABASE_URL/rest/v1/pilgrimage_stamps?id=eq.<내 스탬프 id>" \
  -H "apikey: $ANON_KEY" -H "Authorization: Bearer <내 access_token>" \
  -H "Content-Type: application/json" -d '{"photo_featured": true}'

# (3) 처음부터 승격된 채로 insert
curl -X POST "$SUPABASE_URL/rest/v1/pilgrimage_stamps" \
  -H "apikey: $ANON_KEY" -H "Authorization: Bearer <내 access_token>" \
  -H "Content-Type: application/json" \
  -d '{"user_id":"<내 uid>","site_id":"<성지 id>","photo_url":"https://…","photo_featured":true}'
```

정당한 변경 경로는 셋뿐이고 전부 `security definer` 다: `admin_set_note_hidden` (`20260906000000:230-256`), `admin_set_photo_featured` (최신 정의 `20260913110000:54-64`), `report_visit_note` (`20260901000000:67-87`).

### 마이그레이션 `20260914130000_lock_stamps_admin_fields.sql` 이 하는 일

1. `visited_on date` 열 추가(방문일, `created_at` 과 별개 — 화면 연결은 뒤에).
2. 열 단위 권한: `authenticated` 는 `user_id, site_id, note, photo_url, transport_mode, visited_on` 만 insert, `note, photo_url, transport_mode, visited_on` 만 update. select·delete 는 그대로.
3. 트리거 `stamps_protect_admin_fields` — 앱 역할이 `hidden`·`photo_featured` 를 바꾸면 42501.
4. `stamp_photos_select_public` 을 "숨기지 않은 스탬프의 사진 또는 본인 사진"으로 좁힘. `pilgrimage_stamps` 는 본인 행만 select 되므로 정책에서 직접 서브쿼리하면 anon 에게 사진이 전부 사라진다 — 숨김 판정만 definer 함수 `stamp_is_visible(uuid)` 로 뺐다(boolean 하나만 돌려줌).
5. 스토리지 `pilgrim_photos_update_own` 에 `with check` 추가 — using 만 있으면 내 파일을 남의 uid 폴더 경로로 옮길 수 있었다 (`20260901000000:27-29`).

### 트리거 판단 기준 — 왜 profiles 와 다르게 `current_user` 인가

profiles 트리거처럼 `current_setting('role')` 을 쓰면 관리자 RPC 가 막힌다. PostgREST 는 `set local role authenticated` 로 요청을 실행하고, `security definer` 는 **권한 검사 주체(`current_user`)만 함수 소유자로 바꾸지 `role` 설정값은 건드리지 않는다.** 그래서 `admin_set_note_hidden` 안에서 실행되는 UPDATE 도 `current_setting('role')` = `'authenticated'` 로 보이고, 세 함수 전부 42501 로 실패한다.

반면 PostgreSQL 문서(9.27 세션 정보 함수)는 `current_user` 가 "SECURITY DEFINER 함수 실행 중에는 바뀐다"고 명시한다. 그래서 트리거 함수를 **definer 없이(호출자 권한)** 만들고 `current_user in ('anon','authenticated')` 로 판단했다.

| 경로                                   | `current_user`    | 결과  |
| -------------------------------------- | ----------------- | ----- |
| 앱이 표를 직접 PATCH                   | authenticated     | 42501 |
| definer RPC 3종 안의 UPDATE            | postgres (소유자) | 통과  |
| `npm run admin:grant` 등 직결 스크립트 | postgres          | 통과  |
| Edge Function (service_role 키)        | service_role      | 통과  |

**주의:** 이 트리거 함수에 `security definer` 를 붙이면 `current_user` 가 항상 postgres 가 되어 잠금이 사라진다. 파일 주석에도 적어 두었다. 세 definer 함수는 손대지 않았다(트랜잭션 플래그 `set_config` 방식은 함수마다 플래그를 넣어야 하고, 빠뜨리면 조용히 막히므로 택하지 않았다).

## 4. 검증 절차 (로컬 세션, `.env.local` 의 `SUPABASE_DB_URL` 필요)

1. `npm run db:status` → 미적용 목록에 `20260914130000_lock_stamps_admin_fields.sql` 이 있는지 확인.
2. `npm run db:migrate` → "적용" 한 줄 뒤 PostgREST 스키마 캐시 갱신까지 출력되는지 확인.
3. `npm run db:check-security` → 기대값:
   - `pilgrimage_stamps INSERT/UPDATE 가능 열` 에 `hidden`·`photo_featured` 가 없고 "없음 (정상)" 이 찍힌다.
   - `pilgrimage_stamps 트리거` 에 `stamps_protect_admin_fields` 가 있다.
   - `stamp_photos 정책` 의 `stamp_photos_select_public` using 식에 `stamp_is_visible` 이 보인다.
   - `storage.objects pilgrim-photos 정책` 의 `pilgrim_photos_update_own` 에 `with_check` 가 `-` 가 아니다.
   - `public 뷰` 목록에서 `invoker=false` 인 뷰의 `dml` 이 전부 `(없음)` 이다.
4. **일반 회원 계정으로 42501 확인** — 사장님이 직접 해야 한다.
   - 조건: 관리자가 아닌 계정(`profiles.role` 이 기본값 'member', `20260906000000:29`) 하나, 그 계정으로 찍은 스탬프 하나, 로그인 후 브라우저 개발자 도구에서 `access_token`(Application → Local Storage → `sb-…-auth-token` 의 `access_token`).
   - 위 3절의 curl (2) 를 그 토큰으로 보낸다. 기대 응답: HTTP 401/403 에 `"code":"42501"` — 열 권한(`permission denied for table pilgrimage_stamps`) 또는 트리거 메시지("숨김·대표 사진 여부는 사용자가 바꿀 수 없습니다") 둘 중 하나.
   - 같은 토큰으로 `{"note":"확인"}` 을 PATCH 하면 204 로 성공해야 한다(정상 쓰기는 살아 있음).
   - 관리자 계정으로 앱 관리자 화면의 「숨김」·「대표로」 가 여전히 동작하는지, 회원 계정으로 「신고」 가 오류 없이 도는지 확인.
5. `npm run verify` 는 이 변경과 무관하게 통과해야 한다(DB 접속 없는 검사).

## 5. 함께 확인할 것

- **Storage 정책** — `pilgrim-photos` 는 공개 버킷이라 URL 을 알면 숨긴 사진도 열린다. 숨김은 "목록에서 빠짐"이지 삭제가 아니다. 문제가 되면 운영자 숨김 시 파일도 지우는 후속이 필요하다. `site-photos` 버킷은 `is_editor()` 로 잠겨 있다 (`20260906000000:157-174`).
- **Auth 설정** — `supabase/config.toml` 의 `enable_confirmations = false`(`:225`) 는 **로컬 개발 값**이다. 운영 프로젝트는 대시보드 Authentication → Providers → Email 에서 "Confirm email" 이 켜져 있는지 사장님이 확인해야 한다. 꺼져 있으면 남의 이메일로 가입할 수 있다.
- **공개 뷰의 DML 권한** — 소유자 권한 뷰(`site_visit_notes`·`site_featured_photos`·`directory_public`·`admin_pending_photos`)는 RLS 를 타지 않으므로 앱 역할에 INSERT/UPDATE/DELETE 가 남아 있으면 안 된다. `directory_public` 은 회수했고(`20260914120100:11`), 나머지는 조인·집계 뷰라 자동 갱신이 안 되지만 `db:check-security` 의 뷰 목록으로 매번 확인한다.
- **`events` anon insert** — `visitor_id` 만 비어 있지 않으면 누구나 무제한으로 넣을 수 있다 (`20260913100000:132-134`). 통계 오염·용량 문제이지 개인정보 유출은 아니라 이번엔 두었다. 후속: 함수로 감싸 종류·길이 검증 + 비율 제한, 또는 Edge Function 경유.
- **함수 실행 권한** — `admin_set_*`·`report_visit_note`·`stamp_is_visible` 은 `revoke all from public` 뒤 필요한 역할에만 `grant execute`. `increment_note_reads` 는 anon 도 실행 가능(의도, `20260902000000:46`). 새 함수를 만들 때 `revoke ... from public` 을 빼면 기본으로 PUBLIC 실행 권한이 붙는다.

## 6. 앱 영향

앱(`src/features/passport/api/stamps.repository.ts`)은 `user_id, site_id, note, transport_mode` 로 insert 하고 `note`·`photo_url` 만 update 한다. `hidden`·`photo_featured` 는 보내지 않으므로, **이 마이그레이션이 운영 DB 에 적용되기 전이나 후나 정상 사용은 달라지지 않는다.** 관리자 화면은 RPC 만 쓰므로 그대로다. `visited_on` 은 아직 화면에 없다 — 쓰게 되면 `src/shared/types/database.ts` 의 `PilgrimageStampRow` 에 열을 추가한다.
