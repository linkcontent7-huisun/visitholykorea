## 왜 했나

포크 방식은 **쓰기 권한이 없는 외부 기여자**를 위한 것이다.
권한이 있으면 리모트 두 개(`origin` = 내 포크, `upstream` = 원본)를 관리해야 하는 비용만 남는다.
`upstream` 에서 당겨 `origin` 에 다시 미는 단계가 매번 끼어들고, **그 단계를 건너뛰면
원본에 이미 들어온 수정을 모른 채 작업하게 된다** — 실제로 아래 사고가 났다.

## 앞으로의 흐름

리모트가 하나(`origin` = 원본)로 정리됐으므로 이제부터는:

```bash
git checkout main && git pull      # 최신 받기
git checkout -b <새-브랜치>         # 작업 단위로 브랜치
# 작업 → npm run verify → 커밋 → push
git push -u origin <새-브랜치>      # PR → 검토 → Merge → 브랜치 삭제
```

병합 후 로컬 정리는 `git branch -d <브랜치>` + `git fetch --prune`.
`-D`(대문자)가 아니라 **`-d`(소문자)** — 병합 안 된 브랜치를 실수로 지우는 걸 막아준다.
