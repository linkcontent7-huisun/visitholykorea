## 4. 동작

```text
질문 → ① 단어 추출 (흔한 말 제외: 성지·어디·미사·시간·추천 …)
     → ② DB 검색: 이름 일치 → 주소(지역명) → 소개·역사 순으로 성지 5곳 + 본당 5곳
     → ③ 그 5+5 곳만 [성지 정보]로 프롬프트에 붙여 Gemini 호출
     → ④ 답 (3~5문장, 일정 물을 때만 표, 끝에 한 줄 인사)
        · 컨텍스트에 없으면 → "부끄럽지만 저 미카엘 천사도 잘 모르는 부분이에요…"
        · Gemini 429 → HTTP 429 "지금 질문이 많아 잠시 숨을 고르고 있어요. 1분 뒤에"
        · 그 밖 실패 → HTTP 500 "잠시 자리를 비웠어요"
```

②가 9/17 까지 고장 나 있었다 — 「성지」 같은 흔한 단어가 208곳 전부에 걸려 물어본 성지 대신 아무 5곳이 들어갔고, 그래서 절두산도 "모른다"고 했다. 고침(PR #40).

## 7. 대화 기록 — 사장님 결정 (2026-09-18, 오후 갱신)

**위치 부여**: 미카엘은 핵심 과제(오버투어리즘 해소)와 직접 관련이 크지 않아 **중요도는 비교적 낮다.** 대신 서비스의 **확장 가능성을 설명하기에 좋은 기능**이다 — 발표에서 그렇게 말한다. 심사 시연은 **로그인한 채로** 한다.

| | 로그인 | 비로그인 |
| --- | --- | --- |
| 대화 저장 | **서버 DB 에 저장** — 시트를 닫았다 열어도, 새로고침해도 지난 대화가 그대로 남아 있다 | 브라우저 세션 안에서만. 닫으면 사라짐 |
| 문맥 | 마지막 6턴을 요청에 실어 미카엘이 앞 질문을 잇는다 | 같음 (세션 안에서) |
| 대화 목록 (날짜별 · 골라 열기) | **안 한다 — 오버스펙.** 대화는 한 줄기 하나 | — |
| 지우기 | 「대화 지우기」 버튼 1개 (내 대화 전부 삭제) | — |
| 개인정보 | `/privacy` 에 한 문단: 무엇을(질문 · 답) · 누가(본인만) · 언제까지(지울 때까지) · 어떻게 지우나 | 남기는 것 없음 |

**구현** (하루): `chat_messages` 표(누가 · 역할 · 내용 · 시각, 본인만 읽기 규칙 — `compass_responses` 본뜸) + 마이그레이션 · 타입 · 저장 함수 · 시트에서 답마다 저장, 열 때 최근 30줄 불러오기 · 지우기 버튼 · privacy 문단. 함수는 `history` 6턴을 받아 Gemini `contents` 에 붙인다. 오래된 대화를 통째로 보내지 않는다(토큰 · 한도).

**조건과 순서**: 결제(5절 A) → 폴백(B) → 20문항 확인(6절) **통과한 뒤** 넣는다. 통과 못 하면 제출 후로.

**추후**: 저장된 대화로 사용자 취향을 파악해 **최적의 성지를 추천하는 기능으로 고도화** — 오늘의 성지 일정과 합류.
