## 3. 무엇을 답하고, 무엇은 안 답하나

| 질문 종류 | 답 | 근거 |
| --- | --- | --- |
| 성지 위치 · 가는 법 · 소개 · 역사 | ✅ | `holy_sites` 의 주소 · 소개 · 역사 |
| 본당 · 공소 주소 · 전화 | ✅ | `catholic_directory`(5,918건) 이름 · 주소 · 전화 |
| 근처 다른 성지 | ✅ (같은 지역명 검색) | 주소에 지역명 |
| 미사 시간 · 개방 시간 · 입장료 | ❌ **"모른다 + 성지 사무실 확인"** | DB 에 없음 — 틀리면 신뢰가 무너지는 정보 |
| 순교자 수 · 연도 · 인물 해석 | ❌ DB 소개글에 있는 것만. 없으면 모른다 | 프롬프트 [사실 정보 규칙] |
| 성지 밖 질문(경복궁 · 맛집 · 날씨) | ❌ "성지 안내만 할 수 있어요" | 범위 밖 |
| 신앙 권유 · 나이 · 성별 추측 | ❌ | 프롬프트 [상대에 맞추기] |

## 4. 동작

```text
질문 → ① 단어 추출 (흔한 말 제외: 성지·어디·미사·시간·추천 …)
     → ② DB 검색: 이름 일치 → 주소(지역명) → 소개·역사 순으로 성지 5곳 + 본당 5곳
     → ③ 그 5+5 곳만 [성지 정보]로 프롬프트에 붙여 Gemini 호출
     → ④ 답 (3~5문장, 일정 물을 때만 표, 끝에 한 줄 인사)
        · 컨텍스트에 없으면 → "부끄럽지만 저 미카엘 천사도 잘 모르는 부분이에요…"
        · Gemini 429 → HTTP 429 "지금 질문이 많아 잠시 숨을 고르고 있어요. 1분 뒤에"
        · 그 밖 실패 → HTTP 500 "잠시 자리를 비웠어요"
```

②가 9/17 까지 고장 나 있었다 — 「성지」 같은 흔한 단어가 208곳 전부에 걸려 물어본 성지 대신 아무 5곳이 들어갔고, 그래서 절두산도 "모른다"고 했다. 고침(PR #40).

## 5. 시연에 켜려면 — 남은 것 4가지

| | 무엇 | 크기 | 누가 |
| --- | --- | --- | --- |
| **A** | **Gemini 결제 등록** (Google AI Studio → 결제). 코드 · 시크릿 변경 없음. 없으면 하루 20여 회에 막힘 | 10분 | 키 주인 |
| **B** | **DB 폴백** — Gemini 실패(429 · 500)면 ②에서 찾은 성지의 이름 · 주소 · 전화 · 소개 첫 두 문장을 정해진 틀로 답 (말투 없음, 지어내는 것 없음). 한도가 바닥나도 빈 화면 안 뜸 | 함수 20줄 · 30분 | 개발 |
| **C** | 답 아래 **「참고한 성지: ○○, △△」** 한 줄 — 출처 표시의 최소형 | 함수 5줄 + 시트 5줄 | 개발 |
| **D** | 입구 — 2dion 브랜치 합치기 (헤더 「미카엘 AI」). 상세 「이 성지에 대해 묻기」는 선택 | PR 합침 | 사장님 |

오류 신고는 이번 제출에서 뺀다 — FAQ 의 "AI 답변은 참고용, 중요한 정보는 성지 사무실에" 문구로 갈음.

## 6. 완료 조건 — 질문 20개로 확인 (16개 이상 맞아야 켠다)

| # | 질문 | 기대 |

| 7 | 해미순교성지 역사 | DB 역사 요약 |
| 8 | 천안에 있는 성지 | 주소에 천안 있는 성지 목록 |
| 9 | 병인박해 순교자 수 | DB 에 없으면 모른다 |
| 10 | 경복궁 입장료 | 범위 밖 안내 |
| 11 | 반나절에 갈 수 있는 서울 성지 코스 | 표로 2~3곳 |
| 12 | 무릎이 아픈데 계단 없는 성지 | 모르면 모른다 (계단 정보 DB 에 없음) — 추측 금지 |
| 13 | 아이랑 가기 좋은 성지 | 조건 반영한 제안 또는 되묻기 |

## 7. 대화 기록 — 사장님 결정 (2026-09-18)

**위치 부여**: 미카엘은 핵심 과제(오버투어리즘 해소)와 직접 관련이 크지 않아 **중요도는 비교적 낮다.** 대신 서비스의 **확장 가능성을 설명하기에 좋은 기능**이다 — 발표에서 그렇게 말한다.

| | 지금 (제출판) | 추후 |
| --- | --- | --- |
| 저장 위치 | **브라우저 세션 안에서만** — 시트를 닫거나 새로고침하면 사라짐. 서버 · DB 저장 없음 | 서버 DB 에 대화 저장 |
| 문맥 | 직전 몇 턴을 요청에 같이 실어 보내 미카엘이 앞 질문을 잇게 한다 (저장 아님) | 저장된 대화로 사용자 취향 파악 |
| 목적 | 성지 안내 질문창 | **사용자에게 최적의 성지를 추천하는 기능으로 고도화** — 오늘의 성지 일정과 합류 |
| 개인정보 | 남기는 것 없음 → 안내 불필요 | 저장 시점에 동의 · 삭제 · 보관 기간 정하고 `/privacy` 갱신 |

구현 메모: 헤더 · 홈 카드 두 입구가 **한 대화 상태**를 쓰게 합친다(2dion 9/18 헤더 상태 기준). 함수는 `history` 필드(직전 6턴)를 받아 Gemini `contents` 에 붙인다 — 함수 10줄 · 클라이언트 5줄, DB 없음.
