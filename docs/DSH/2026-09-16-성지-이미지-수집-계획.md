## 3. 계획

> **9/16 저녁 — 0단계·1단계 끝냈다.** 결과·지시서와 달리한 점은 `task_IMAGE.md` 「실행 기록」. 사진 53 → 89. 교구 대표 사진은 저녁에 철회하고 스탬프 도장으로 바꿨다(혼동 우려).

### 0단계 — 포토코리아 34곳 투입 (9/16~17 · 반나절)

이미 골라 둔 것을 넣기만 하면 53 → 87곳(42%). 가장 싸고 확실하다.

- 공공누리 제1유형이므로 **파일을 내려받아 1600px 로 줄여 `public/images/sites/` 에 내장**하고 `/images/sites/…` 경로를 `image_url` 에 넣는다. **관광공사 주소(`tong.visitkorea.or.kr`)를 DB 에 그대로 넣지 않는다**(ADR 0002).
- `image_source` = 「한국관광공사 포토코리아 (촬영자)」, `image_license` = 「공공누리 제1유형」. 사진별 페이지에서 유형을 한 번 더 확인한다(관광정보 API 쪽은 1·3유형 혼재).
- 넣기 전에 **34장 전부 눈으로 연다.** 옆 건물·엉뚱한 피사체가 섞이면 뺀다.
- 넣은 뒤 Range 요청으로 용량 재확인(700KB 넘지 않게).

### 1단계 — 교구 대표 사진 16장으로 임시 이미지 교체 (9/17 오후까지 · 코드 1시간 + 사진 찾기 2시간)

남은 118곳(0단계 뒤)의 빈자리를 교구별 1장으로 채운다. DB 는 안 건드린다.

1. 16개 교구 주교좌성당(또는 교구를 대표하는 성지) 사진을 **위키미디어(CC) → 공공누리 포털** 순으로 찾는다. 없는 교구는 지금 임시 이미지 유지.
2. 1280px 축소판 또는 1600px 내장, 700KB 이하. 출처·라이선스는 `public/placeholders/README.md` 같은 한 곳에 표로 남긴다.
3. 코드: `site-placeholder.ts` 의 키를 이름 해시 → **교구**로, `SiteThumbnail` 에 왼쪽 아래 작은 띠 "○○교구 성지" 겹침(큰 글자 모드에서도 읽히는 최소 크기), alt·출처 줄에 "○○교구 대표 사진 · △△성당". 진짜 사진이 들어오면 그 성지만 자동으로 진짜가 뜬다.
4. 크롬 1280 폭에서 목록·상세 스크린샷으로 확인.

### 2단계 — 공공누리 포털에서 118곳 개별 검색 (9/18~ · 사람 손 3~4시간)

포털이 자바스크립트 화면이라 스크립트(curl)로는 안 된다 — **크롬으로 한 곳씩** 검색한다.

- 검색어는 붙여 쓴 이름 말고 **짧은 고유명사**(「황새바위」 「다락골」 「배티」). 포토코리아 때와 같은 교훈.
- 「원문 공공저작물」 탭만 본다. 「연계 저작물」은 외부 사이트(향토문화전자대전 등)라 유형을 따로 확인해야 한다.
- 결과는 `data/research/kogl_candidates_2026-09-XX.csv` 에 site_id · 검색어 · 저작물 제목 · 제공기관 · 유형 · 주소 · `use` 열로. **사람이 `use=y` 를 찍은 것만** 0단계와 같은 방식으로 내장.
- 예상: 유명 성지(성당 건물이 있는 곳)는 나오고, 터·공소·묘는 대부분 안 나온다. 몇 곳이 나올지는 돌려봐야 안다 — 지금 숫자를 적지 않는다.

### 3단계 — 성지·교구에 사용 허락 요청 (마감 후)

명단: `data/research/photo_missing_sites_2026-09-16_허락요청.csv` (118곳 · 굿뉴스 앨범 링크 · 개별 홈페이지 · 전화 · 교구 연락처).

- 순서: **개별 홈페이지가 있는 성지(58곳)에 직접** → 답 없으면 교구. 교구 대표 이메일이 있는 곳: 대구 · 대전 · 전주 · 부산 · 안동 · 마산 · 광주. 나머지는 전화만 있다.
- 요청문에 넣을 것: 앱 이름과 목적(비영리 순례 안내, 관광공사 공모전 출품) · 쓰려는 사진(굿뉴스 앨범 링크로 가리킴) · 표기 방식(「○○성지 제공」) · 용도 범위(앱 대표 사진 1장).
- 허락받으면 `image_source` = 「○○성지 제공 (허락 YYYY-MM-DD)」, 이메일은 `data/research/permissions/` 에 보관.

## 4. 모든 단계에 걸리는 규칙

- **넣기 전에 이미지를 연다.** 이름만 보고 넣다가 개신교 교회(구산교회)·FBI 경찰관 사진이 들어간 적 있다.
- 700KB 초과 금지, 위키미디어는 1280px 축소판, 그 외는 1600px 내장.
- `image_source` · `image_license` 빈칸 금지.
- TourAPI 응답 주소를 DB 에 저장하지 않는다(ADR 0002). 공공누리 저작물은 내려받아 내장.
- AI 생성 사진 금지. 사진이 없는 편이 가짜보다 낫다.
- 허락 안 받은 교구·굿뉴스·개별 홈페이지 사진은 한 장도 넣지 않는다.

## 5. 사장님이 정할 것

1. 0단계(포토코리아 34곳)를 **지금 넣을지** — 넣으면 53 → 87.
2. 1단계(교구 대표 사진)를 **할지** — 하면 16장 확보 확인부터 시작.
3. 2단계 공공누리 포털 검색을 **마감 전에 할지 뒤로 미룰지** — 크롬으로 손수 돌려야 해서 3~4시간.
4. 3단계 허락 요청 이메일을 **누가 어느 이름으로** 보낼지.

## 6. 부수 발견 (안 고쳤다)

- `catholic_directory` 에 TourAPI 이미지 주소(`tong.visitkorea.or.kr`) 38행이 저장돼 있다. 화면엔 안 쓰이지만 ADR 0002 원칙상 지워야 한다.
- `holy_sites` 에서 **천호성지 교구가 「수원」**으로 돼 있다. 굿뉴스·실제는 전주교구(완주). 확인 후 고칠 것.
- 굿뉴스는 「화현 이벽 성지」를 춘천교구로 분류한다(우리 DB 는 의정부). 포천이 2004년 이전 춘천교구였던 흔적 — 우리 값이 맞다.
