## 1. 관리자 콘솔 (신규)

**왜** — 성지 정보를 고치는 길이 노트북 CLI 스크립트뿐이었다. 그런데 비어 있는
대표 사진 155곳은 결국 현장에서 찍어야 하고, 찍은 사진을 노트북 앞으로 돌아와
올리는 일은 실제로 잘 일어나지 않는다. **휴대폰에서 그 자리에서 바꾸는 것**이
이 화면의 존재 이유다.

| 무엇 | 어디 |
| --- | --- |
| 권한 등급 `member / editor / admin` + RLS | `supabase/migrations/20260906000000_create_admin_console.sql` |
| 관리자 로그인 · 문지기 | `src/features/admin/components/AdminGate.tsx` |
| 「채울 곳」 대기열 + 사진 승인함 | `src/pages/AdminPage.tsx` (`/admin`) |
| 성지 1곳 편집 | `src/pages/AdminSitePage.tsx` (`/admin/sites/:siteId`) |
| 첫 관리자 임명 | `npm run admin:grant -- <이메일>` |

**의도적으로 좁게 둔 것 — 나중에 "빠졌다"고 채우지 말 것**

- **성지 추가·삭제 정책을 만들지 않았다.** update 만 열려 있어 화면에서 무엇을
  눌러도 208곳이 사라지지 않는다.
- **관리자에게 회원 정보를 보여주지 않는다.** 승인함은 `admin_pending_photos`
  뷰만 보고, 그 뷰에 `user_id` 와 이메일이 없다.
- **모든 수정은 `site_revisions` 에 이전 값이 남는다** (DB 트리거). 편집 화면에서
  되돌릴 수 있다. 성지 역사는 틀리면 신뢰가 바로 무너진다.
- **service_role 키를 앱에 넣지 않았다.** `VITE_` 값은 브라우저 번들에 그대로
  들어간다. 권한 판단은 전부 DB 가 한다.
- 화면 문구는 **한국어만**이다. 운영자만 보는 화면이라 사전을 두 배로 만들 이유가 없다.

**운영 DB 실측 (트랜잭션 후 롤백)**: 관리자 계정 update **1행** / 일반 회원 계정
같은 update **0행**(RLS 가 조용히 막음). 저장소 `site-photos` 버킷 생성 확인.
첫 관리자는 `nhuisun@gmail.com`.

## 2. T-007 — 영어 모드에 남아 있던 한국어

도슨트 원고는 7챕터 전부 영어로 나오는데 **그것을 감싼 화면 문구가 한국어**였다.
가장 급했던 것은 이 앱의 핵심 행동 버튼 「순례 스탬프 찍기」.

- 문구 50여 개를 `src/shared/i18n/dictionary.ts` 로 옮기고 6개 국어를 채웠다.
  상수로 두면 언어가 빠져도 타입 검사가 못 잡는다(9/4 도슨트 플레이어에서 같은 사고).
- DB 에 한국어로 저장된 값(성지 분류·감성 태그)은 **저장을 그대로 두고 화면에서만
  옮긴다** — `src/shared/i18n/domain-labels.ts`. 208행과 시드를 안 건드린다.
- 전례 시기 이름에 `labelKey` 를 붙였다. `label` 은 한국어로 남긴다 — 공유 카드·
  인증서를 캔버스로 그리는 코드가 그 값을 쓴다.
- WYD 배지가 영어 외 언어(es·fr·pt·it)에서 한국어로 나오던 것도 고쳤다.

WYD 2027 주최 언어가 스페인어다. 이제 스페인어로 앱을 열면 **모든 성지에서
스페인어 원고가 재생된다**(`chapters.ts` 의 `hasFullTranslation` 조건 충족).

| 차수 | 성지 | 누가 |
| --- | --- | --- |
| T-005 | 명동 · 절두산 · 전동 | Codex |
| T-008 | 서소문 · 새남터 · 해미 | Codex |
| T-009 | 솔뫼 · 배론 · 약현 | Codex (Orca 오케스트레이션) |
| T-010 | 나주 · 배티 · 여우목 · 오륜대 | 지시자 직접 |

**작업 방식 — 다음에도 이렇게 한다.** `json.dump` 로 다시 쓰면 파일이 통째로
재정렬돼 "한국어 원문이 안 바뀌었다"를 눈으로 확인할 수 없다. 텍스트로 `...En`
줄 **바로 뒤에** `...Es` 줄만 끼워 넣으면 diff 가 추가만 남는다.
T-010 네 파일 모두 `22 추가 · 0 삭제`.

`lookFor` 가 `null` 인 지점(볼거리가 원래 없는 자리)에는 **없는 내용을 지어내지
말고** `"lookForEs": null` 을 넣는다. 키를 빼면 개수 검사가 어긋난다.

> **남은 것**: 번역 품질을 스페인어를 아는 사람이 한 번 읽어주면 좋다. 특히
> 나주의 `baekjisahyeong`(백지사형) 설명과 배티의 `mártir blanco`(백색 순교자)가

## 6. 멀티 에이전트 오케스트레이션 — 되는 것과 안 되는 것

**되는 것.** Claude 와 Codex 는 Orca 를 통해 **실제로 대화할 수 있다.** 오래
"통로가 없다"고 알고 있었는데 틀렸다. `orchestration` 스킬이 Claude Code 설치
목록에서만 빠져 있었고, `~/.claude/skills/` 로 복사하니 즉시 인식됐다.

```
orca orchestration run-create / task-create / worker-start / check
orca terminal create / read / close
```

T-009 는 이 방식으로 **사람 손 없이** 끝났다.

**🔴 안 되는 것.** Codex 샌드박스는 리눅스·맥 OS 기능에 기댄다. Windows 에는
그게 없어서 조합이 셋뿐인데 쓸 만한 게 없다.

| 옵션 | 결과 |
| --- | --- |
| `--ask-for-approval on-request` | 울타리는 있으나 **명령마다 사람이 승인 클릭**. Orca 가 에이전트의 대리 클릭을 막는다 |
| `--ask-for-approval never` + workspace-write | **모든 명령이 차단된다** |
| `--dangerously-bypass-approvals-and-sandbox` (Orca 기본) | 클릭 없이 돌지만 **울타리가 없다** |

> ⚠️ **설정 파일만 보고 "안전하다"고 판단하지 말 것.** `~/.codex/config.toml` 에
> `sandbox_mode` 를 넣어도 명령줄 옵션이 덮어쓴다. 실제 실행은 프로세스로 본다:
> `Get-CimInstance Win32_Process -Filter "Name='codex.exe'" | % { $_.CommandLine }`

**사장님 판단으로 9/14 이후로 보류했다.** 재개 순서는
① WSL 안에서 Codex ② worktree 격리 + 키 교체 ③ 맡길 일의 기준 정하기.
자세한 것은 `docs/이어서-할-일.md` 9/7(2) 항목.

**비용 판단**: 도슨트 번역은 애초에 다중 에이전트가 필요한 일이 아니었다.
T-010 네 곳은 지시자가 20분에 끝냈고 diff 도 더 깔끔했다.
멀티 에이전트는 토큰을 약 15배 쓴다 — **결과가 분명히 나아질 때만 쓴다.**
