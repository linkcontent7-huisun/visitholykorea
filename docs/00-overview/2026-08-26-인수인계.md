### 3. 사용자의 로컬 파워셀 트러블슈팅

사용자가 로컬 CLI 창에서 `Login expired · Please run /login` 상태로
멈춰 있는 스크린샷을 보내와, 이 세션이 아니라 **로컬 세션이 정지된
것**임을 짚어줬다 (이 웹 세션이 로컬 파일·DB 를 볼 수 없다는 것과는
별개 문제).

이후 몇 차례 스크린샷을 주고받으며:

- 사용자가 프로젝트 폴더 경로를 몰라서 `cd` 명령이 계속 실패했다
  (`C:\Users\noh hui sun\...` 처럼 띄어쓰기 있는 경로를 따옴표 없이
  입력해서 발생).
- `Get-ChildItem -Recurse -Filter "visitholykorea"` 로 경로를 찾아보게
  했는데, 처음 나온 결과(`...\codyssey\assignments\A2-1-brand-identity\samples\visitholykorea`)는
  **진짜 프로젝트가 아니라 코딧세이 과제 샘플 폴더**였다 — 이름만
  같은 다른 폴더이니 혼동 주의라고 명시적으로 짚었다.
- 진짜 작업 폴더는 이미 로컬 Claude Code CLI 창 헤더에
  `~\visitholykorea app` 로 표시돼 있었다 — 그 창이 이미 올바른
  위치에서 열려 있었으므로 별도로 `cd` 할 필요가 없었다.
- 로컬 CLI 자체도 `Login expired` 상태였는데, `/login` 재실행으로
  해결됨(사용자가 캡처로 "Login successful" 확인).

작업은 새 브랜치로 커밋·푸시하고, 로컬 main 을 원격 최신으로 맞춰라")를

## 이 세션에서 확인한 판단 원칙 (재확인, 새로 만든 건 아님)

- **PR 이 이미 머지된 브랜치는 재사용하지 않고 `main` 에서 다시
  시작한다.** (CLAUDE.md 명시 규칙 — 이번에 실제로 한 번 적용해봄)
- **경로를 추측해서 안내하지 않는다.** 처음에 폴더 경로를 예시로
  지어내 안내했다가(`C:\Users\noh hui sun\visitholykorea app\...`)

- **로컬 세션이 스스로 처리한 병합 작업도, 웹 세션이 그 결과물을
  다시 확인하고 나서 사람에게 보고한다.** recap 한 줄만 믿지 않고
  `git diff --stat` 로 실제 diff 를 봤다 — 34개 파일 중에 뭐가
  들어왔는지 사람이 알아야 머지 여부를 판단할 수 있다.
