# Visit Holy Korea 프로젝트 분석 보고서

분석일: 2026-09-10

## 결론

현재 프로젝트는 한국 가톨릭 성지 순례 웹앱이며, 웹·Android·iOS에서 같은 코드베이스를 사용한다. 기능 범위는 넓지만, 아래 세 기능을 제품의 최우선 기능으로 두는 것이 맞다.

| 우선순위 | 기능 | 현재 상태 | 핵심 문제 |
| --- | --- | --- | --- |
| 1 | 한국어에서 영어로의 전면 번역 | 부분 구현 | 성지 상세에는 DB 번역을 적용하지만, 홈·목록·지도 등에는 한국어 원문과 고정 한국어 문구가 남아 있다. 따라서 현재 상태는 전체 영어 서비스가 아니다. |
| 2 | 한국어·영어 오디오 도슨트 | 구현됨, 현장 검증 필요 | 음성 파일이 아니라 브라우저/휴대폰 내장 TTS를 사용한다. 기기의 음성 설치 상태와 인앱 브라우저 지원 여부에 따라 품질이 달라질 수 있다. |
| 3 | 현재 위치 기반 성지·성당 추천 및 네이버지도 연결 | 부분 구현 | 실제 GPS를 읽지 않고 사용자가 선택한 출발 지역의 중심좌표를 사용한다. 네이버지도는 장소명 검색 링크이며, 현재 위치에서 목적지까지의 길찾기나 주변 탐색은 아니다. |

## 현재 구조

### 화면 계층

- `src/pages`: 홈, 검색, 성지 상세, 지도, 탐색, 나침반, 기록, 축제, 로그인 등 화면
- `src/app`: 라우팅, 앱 레이아웃, 상단 메뉴와 모바일 하단 탭
- `src/shared`: 공용 API, 타입, 다국어 사전, 지도 링크, 거리 계산, UI 컴포넌트

### 주요 기능 계층

| 경로 | 역할 |
| --- | --- |
| `src/features/sites` | 성지·성당/공소 검색, 성지 번역 조회, 거리 계산, 주변 성당 조회, 길찾기 |
| `src/features/docent` | 오디오 도슨트 챕터, TTS 재생, 이어폰 안내, 현장조사 원고 로딩 |
| `src/features/courses` | 감정 기반 순례 코스 추천, 마음 나침반 |
| `src/features/quiet` | TourAPI 기반 혼잡도 및 대체 성지 추천 |
| `src/features/map` | 전국 성지 조망 지도, 방문 진행도 |
| `src/features/passport` | 스탬프, 순례 여권, 공유 카드 |
| `src/features/records` | 방문 기록과 여행기 |
| `src/features/favorites` | 즐겨찾기 |
| `src/features/ai-guide` | 성지 DB 범위 안에서 답하도록 설계된 AI 안내 |
| `supabase/functions` | AI 가이드 및 네이버 로그인용 서버 함수 |

### 핵심 3기능의 실제 동작

#### 1. 번역

- UI 공통 문구는 `src/shared/i18n/dictionary.ts`에서 여러 언어로 제공한다.
- 성지 상세는 `holy_site_translations` 테이블을 조회하여 번역된 이름·소개·역사를 보여준다.
- 요청 언어의 번역이 없으면 영어를 거쳐 한국어 원문으로 폴백한다.
- 그러나 홈 카드, 지도 목록, 일부 버튼·안내문은 원본 성지명 또는 한국어 고정 문구를 쓴다.

#### 2. 오디오 도슨트

- `src/features/docent`가 브라우저의 `speechSynthesis` API로 본문을 읽는다.
- 현장조사 원고가 있는 성지는 입구·포인트·마무리 형태의 챕터형 도슨트를 제공한다.
- 원고가 없는 성지는 성지의 실제 소개·역사 텍스트를 챕터로 구성한다.
- 원고는 `data/docent/*.json`에 있으며, 초안 원고에는 화면상 초안 표시가 붙는다.
- 완전한 영어 원고가 없을 경우 영어 성지 소개·역사 텍스트로 폴백한다.

#### 3. 위치·성당 추천·네이버지도

- `sortByDistance`와 홈 화면의 거리 정렬은 출발지 좌표에서 성지까지의 직선거리를 계산한다.
- 현재 코드에 `navigator.geolocation`, `getCurrentPosition`, `watchPosition` 사용은 없다. 따라서 실제 현재 위치 기반 기능은 미구현이다.
- `catholic_directory`에서 본당·공소·피정의집을 반경 검색하여 거리순으로 보여준다.
- 네이버지도는 `https://map.naver.com/p/search/장소명` 검색 링크로 연결된다.
- 한국어 화면에서는 카카오맵 → 티맵 → 네이버지도 → 구글 지도 → 애플 지도의 순서로 노출한다.

## 발견된 문제와 위험도

### 높음

1. 실제 GPS 기반 추천이 없다.
   - 요구한 “내가 있는 위치”가 아니라 선택한 지역의 중심좌표를 쓴다.

2. 네이버지도는 지도 검색 연결만 제공한다.
   - 현 위치 출발 경로, 네이버 지도 SDK, 네이버 지도에서의 주변 성지/성당 검색은 구현되지 않았다.

3. 영어 전면화가 완료되지 않았다.
   - 성지 상세의 번역 데이터와 UI 다국어 사전은 구현됐지만, 모든 화면과 성지 카드에 일관되게 적용되지 않았다.

### 중간

4. 오디오 도슨트는 기기 내장 TTS에 의존한다.
   - 기기에 한국어 또는 영어 음성이 없거나, 특정 인앱 브라우저가 음성 합성을 제한하면 재생이 불안정할 수 있다.

5. AI 가이드 서버 함수의 배포 문제가 기록돼 있다.
   - 인수인계 문서에 따르면 `ai-guide` Edge Function이 운영 서버에 배포되지 않아, AI 가이드가 폴백 안내만 보일 수 있다.

6. 일부 부가 기능은 운영 DB 마이그레이션 적용 여부에 따라 제한될 수 있다.
   - 즐겨찾기, 스탬프 한 줄 기록, 나침반 응답 저장 등이 해당한다.

## 불필요 파일 정리 후보

이번 분석에서는 내용을 보존하라는 요청과 프로젝트 규칙을 따라 파일을 삭제하거나 이동하지 않았다. 아래는 실행에 직접 필요하지 않을 가능성이 높아, 별도 보관 후 정리 여부를 결정할 후보이다.

| 후보 | 판단 |
| --- | --- |
| `supabase/visitholykorea_버전보관/` | 구버전 앱 사본과 중첩 의존성 폴더로 기록돼 있다. 프로젝트 밖 보관 후 정리 검토 대상이다. |
| `visitholykorea-학습자료/` | 학습 PDF·이미지·아이디어 자료다. 앱 런타임에는 불필요할 수 있으나 기획 자료이므로 보관이 먼저다. |
| `dist/` | 빌드로 다시 만들 수 있는 결과물이다. |
| `node_modules/` | 다시 설치할 수 있는 의존성 폴더다. |
| 미추적 PDF 3개 및 문서 1개 | 사용자가 추가한 자료일 수 있어 삭제 대상이 아니다. |

## 테스트 결과

분석 중 코드와 기능은 변경하지 않았으며, 현재 활성화된 코드 상태에서 검증했다.

| 검사 | 결과 |
| --- | --- |
| 타입 검사 (`npm run typecheck`) | 통과 |
| 린트 (`npm run lint`) | 오류 0건, 경고 2건 |
| 자동 테스트 (`npm run test -- --reporter=dot`) | 42개 테스트 파일, 349개 테스트 전체 통과 |

린트 경고는 `src/app/routes/router.tsx`의 Fast Refresh 규칙 관련 2건이다. 빌드 또는 동작을 막는 오류는 아니다.

기능을 잠시 중지한 버전의 테스트는 실행하지 않았다. 기능 중지는 코드 변경이 필요하고, 이번 요청의 “내용은 그대로” 원칙을 우선했기 때문이다.

## 다음 우선 작업 제안

1. GPS 권한을 받아 실제 현재 위치를 출발점으로 사용한다.
2. 현재 위치를 기준으로 성지와 본당·공소를 거리·개인 조건으로 정렬한다.
3. 추천 카드에서 네이버지도 목적지 길찾기를 제공한다.
4. 성지명·주소·카드·지도·고정 문구까지 영어 적용 범위를 통일한다.
5. 도슨트의 영어 음성 재생을 실제 Android·iOS 기기에서 확인한다.
