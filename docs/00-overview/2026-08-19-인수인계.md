## 세션 두 종류 — 오늘 가장 크게 헷갈린 부분

같은 Claude 라도 **어디서 도느냐에 따라 할 수 있는 일이 다르다.**
이걸 모르면 "왜 내 파일을 못 보지" 로 시간을 버린다.

|                              | 노트북 파일 | 외부 인터넷 | DB 접속 |
| ---------------------------- | ----------- | ----------- | ------- |
| **로컬** (CLI · 데스크톱 앱) | 볼 수 있음  | 됨          | 됨      |
| **웹** (claude.ai/code)      | **못 봄**   | 막혀 있음   | 안 됨   |

웹 세션은 GitHub 저장소만 복제해온 클라우드 컨테이너에서 돈다.
OneDrive 든 `.env.local` 이든 노트북 안의 것은 **구조적으로** 접근이 안 된다.
설정으로 바꿀 수 있는 문제가 아니다.

**그래서 이렇게 나눈다.**

- DB 작업, OneDrive 자료 정리, 배포 확인, 실제 데이터 확인 → **로컬**
- 저장소 안에서 끝나는 코드·문서 작업, 검증(`npm run verify`) → **웹도 가능**

터미널 화면이 불편하면 Windows 데스크톱 앱을 쓰면 된다. 로컬에서 도니까
파일 접근은 그대로 되고 화면만 낫다.

## 막힌 것 — 웹 세션의 푸시 권한

이 세션의 토큰에 `linkcontent7-huisun/visitholykorea` **쓰기 권한이 없다.**
`git push` 도 GitHub API 브랜치 생성도 403 (`Resource not accessible by integration`).
프록시 로그에 실패 기록이 없으니 네트워크가 아니라 GitHub 의 권한 거부다.
다섯 번 시도했고 전부 같았다.

- 오늘 만든 커밋 `b441e9f` (이어서-할-일.md 재작성) 은 **웹 세션 로컬에만 있고 원격에 못 올라갔다**
- 브랜치 `claude/status-check-0ptb3t` 는 원격에 존재하지 않는다
- 문서 내용 자체는 사용자에게 파일로 전달했으므로 유실되지 않았다

**푸는 방법 두 가지.**

1. 로컬 세션에서 파일을 반영하고 커밋·푸시한다 (바로 됨)
2. <https://claude.ai/admin-settings/claude-tag> 에서 이 저장소에 쓰기 권한을 준다
   — 이후로는 웹 세션에서도 직접 커밋·푸시가 된다

## 다음 세션이 이어서 할 일

`docs/이어서-할-일.md` 에 우선순위대로 있다. 여기서는 **확인이 필요한 두 가지**만 짚는다.
둘 다 DB 를 봐야 해서 **로컬 세션에서만** 된다.

```bash
npm run translate:status
```

서울 25곳 + 대전 27곳 = 52곳의 번역 파일은 완성돼 있다
(`name`·`description`·`history`·`addressRomanized` 전부). **DB 에 import 됐는지가 미확인이다.**
안 들어갔으면 `npm run translate:import -- data/translations/en-서울.todo.json` 식으로 넣는다.
빈 칸을 건드리지 않으므로 여러 번 돌려도 안전하다.

```sql
select count(*) filter (where image_url is not null) as 사진있음,
       count(*) as 전체
from holy_sites;
```

사진 커버리지의 **현재 값을 아무도 모른다.** `data/research/image_sourcing_summary.md`
의 숫자는 195곳 기준의 옛 집계라 쓰면 안 된다.

**코드 쪽에 실제로 남은 작업은 하나뿐이다** — 대체 추천 기능(붐비는 관광지 → 조용한 성지)이
어느 페이지에도 연결돼 있지 않다. `useAlternatives`·`useAttractionSearch`·`AlternativesList`
는 있는데 아무도 import 하지 않고 `app/routes/paths.ts` 에 경로도 없다.
UI 디자인 결정이 막고 있다.
