# 다국어 번역 작업 지침

2026-09-21 새벽, T-030 → T-031 → T-032 로 앱 글 전부를 6개 국어(ko·en·es·fr·pt·it)로 맞추면서 굳은 절차다.
다음에 성지가 늘거나 문구가 바뀌어 번역을 다시 해야 할 때 **이 문서만 보고** 같은 방식으로 한다.

## 1. 글이 어디에 있는가 — 세 층

앱의 글은 세 곳에 나뉘어 있고, 지구본 버튼이 바꾸는 `language` 값 하나를 세 층이 같이 본다.
**순서가 아니라 언어 코드(es·fr…)로 짝을 맞춘다.** 엑셀 열 순서와 화면 순서가 달라도 상관없다.

| 층 | 무엇 | 어디 | 어떻게 고치나 |
| --- | --- | --- | --- |
| ① 화면 문구 사전 | 버튼·제목·안내문 (약 700키) | `src/shared/i18n/dictionary.ts` | 키 하나에 `{ ko, en, es, fr, pt, it }` 여섯 줄. 직접 고친다 |
| ② 긴 본문 | FAQ·약관·개인정보 | `src/pages/content/{faq,terms,privacy}.ts` | `Record<Language, …>`. **한 언어만 고치지 말고 여섯 언어 같이** |
| ③ DB 번역 | 성지 이름·소개·역사 | `holy_site_translations` 표 | `data/translations/<lang>-*.todo.json` → `translate:import` |
| ③′ DB 원고 | 성지 이야기(intro)·오디오 가이드 지점(point) | `docent_scripts` 표 | `data/docent/<성지>.json` 의 `narrationEs` 등 → `npm run docent:load` |

분류·감정 태그처럼 DB 값 자체가 한국어인 것은 `src/shared/i18n/domain-labels.ts` 대응표로 화면에서만 옮긴다.

## 2. 새 성지가 들어왔을 때 (③·③′)

1. `data/docent/<성지>.json` 에 한국어 원고 + `narrationEn`… 여섯 언어를 채운다 → `npm run docent:check` → `npm run docent:load -- <성지>`.
2. 이름·소개·역사는 `npm run translate:export -- --lang es` (fr·pt·it 도) 로 빈 칸 파일을 뽑는다.
   파일에 `sourceEn`(검수된 영어)을 붙여 두면 번역 기준이 된다 — T-032 때 그렇게 했다.
3. `target` 을 채운다. **영어를 기준**으로 옮기고 애매하면 한국어 원문을 본다.
4. `npm run translate:check -- data/translations/es-all.todo.json` → **문제 0** 이어야 다음으로.
5. `npm run translate:import -- <파일>` (사람이 감수했으면 `--reviewed`). 앱은 DB 를 실시간으로 읽으므로 배포 없이 바로 반영된다.
6. 브라우저에서 그 언어로 성지 상세를 열어 이름·인용문을 **눈으로** 본다. 여기까지 해야 "됐다"다.

## 3. 번역 기준 (지시서에 그대로 넣을 것)

- 고유명사 로마자 표기는 **영어 검수본 그대로** (Galmaemot, Kim Taegon, Daveluy, Byeongin…). 언어마다 바꾸지 않는다.
- 성인 세례명만 각 언어 관용 표기: Andrew→Andrés/André/André/Andrea, Paul→Pablo/Paul/Paulo/Paolo, Luke→Lucas/Luc/Lucas/Luca, Peter→Pedro/Pierre/Pedro/Pietro, John→Juan/Jean/João/Giovanni, Thomas→Tomás/Thomas/Tomás/Tommaso, Joseph→José/Joseph/José/Giuseppe, Francis→Francisco/François/Francisco/Francesco, James→Santiago/Jacques/Tiago/Giacomo, Augustine→Agustín/Augustin/Agostinho/Agostino.
- 연도·날짜·숫자는 하나도 빠뜨리지 않는다(검사기가 연도를 대조한다).
- 주소(`addressRomanized`)는 번역하지 않고 영어 값을 복사한다 — 택시 기사에게 통해야 한다.
- 문체: 순례자에게 읽어 주는 안내문. 영어 문장 구조를 억지로 따르지 말고 그 언어답게.
- 미카엘 이름: es·pt Miguel, fr Michel, it Michele.

## 4. 검사기 — `npm run translate:check`

`scripts/translation-check.ts`. 넣기 전에 반드시 통과시킨다. 잡는 것:

| 표시 | 뜻 | 조치 |
| --- | --- | --- |
| `[빈 이름]` | 아직 안 한 곳 | 채운다 |
| `[영어 그대로]` | 영어를 복사만 해 둔 칸 | 번역한다 (고유명사만인 이름은 통과) |
| `[한글 섞임]` | 로마자로 써야 할 지명·인명이 한글 | 고친다 |
| `[연도 누락]` | 영어 원문의 연도가 번역에 없음 | 사실 누락 — 반드시 고친다 |
| `[언어 의심 en]` | 영어 문장이 통째로 들어옴 | 번역한다 |

**못 잡는 것:** 어색한 문장, 잘못된 용어. 이건 사람이 표본을 읽어야 한다. DB 의 `translation_status` 가 `machine` 이면 아직 사람 감수 전이라는 뜻이다.

같은 종류의 검사가 사전에도 있다 — `src/shared/i18n/dictionary.test.ts` 는 **빈 칸만** 잡는다. es 칸에 영어를 복사해 두면 통과하니, 사전을 손댄 뒤에는 T-030 검사 1 의 명령(`paste … | awk '$1==$2'`)으로 영어 그대로인 줄을 한 번 센다.

## 5. 절대 하지 말 것 (실제로 났던 사고)

- **번역 칸에 영어를 복사해 두고 넘어가기.** 5곳 지점 원고가 그 상태로 DB 까지 가서 스페인어로 들으면 영어가 나왔다(9/21 발견). 검사기가 생긴 이유.
- **"됐다"를 코드만 보고 말하기.** 8/29 에도 폴백을 만들고 훅에 안 붙여 스페인어 화면에 한국어가 나왔다. 브라우저에서 눌러 본 뒤에만 됐다고 쓴다.
- **한 파일을 두 창이 동시에 고치기.** 9/21 밤 두 세션이 `dictionary.ts` 의 같은 키를 동시에 번역해 충돌·중복 키(`TS1117`)가 났다. 번역처럼 한 파일에 몰리는 일은 한 창에만.

## 6. Codex 에게 시킬 때

T-032 실측(2026-09-21): Codex 는 es 106곳, Claude 가 나머지 718곳. 시키려면 지시서 「범위 밖」에 아래를 넣는다.
