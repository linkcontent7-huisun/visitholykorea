직결로 옮겼다. JWT 를 안 거치므로 키가 상해도 돈다. 마이그레이션이 같은 사고에도
멀쩡히 돌던 것과 같은 이유다.

## 3. 오늘 발견한 문제 — 사람이 판단해야 한다

### ① 김범우 유배지가 두 곳으로 적혀 있다 🔴

DB 에 김범우 토마스의 유배·선종지가 **두 개** 있고, 서로 아니라고 말한다.

- `단양 김범우 순교 성지`(원주) — "다블뤼 주교는 유배지가 「충청도 동쪽 끝의
  단양」이라고 기록했다… 1787년 유배지에서 숨졌다"
- `김범우 순교자 성지`(부산·밀양) — "오랫동안 유배지는 충청도 단양으로 알려져
  왔지만, 후손과 연구자들의 노력으로 실제로는 이곳 밀양이었음이 밝혀졌다"

한 사람의 유배지가 두 곳일 수 없다. 이제 영어로도 나가므로 **앱이 두 언어로
자기를 반박한다.** 번역은 원문을 그대로 옮겼으니, 교구에 확인해 한국어를 고치면
영어도 같이 고쳐야 한다.
(같은 단양 항목은 선포 연도도 소개글 2021년 / 역사 2026년으로 어긋나 있다.)

### ④ AI 로 성지 사진을 만들지 않는다

사용자가 "인스타 사진을 보고 저작권 문제되면 AI 로 다시 생성해서 넣어달라"고
요청했고, 하지 않기로 했다. 두 가지 이유다.

- 2차적저작물이라 저작권이 안 풀린다
- **AI 가 그린 배티 순교성지는 배티 순교성지가 아니다.** 실제 순교지 자리에
  지어낸 그림을 올리는 것은 CLAUDE.md 의 "더미 데이터를 화면에 남기지 않는다"에
  정면으로 걸린다. 심사위원이 아는 성지 하나만 알아봐도 신뢰가 통째로 무너진다.
  **사진이 없는 편이 가짜 사진보다 낫다.**

인스타 사진을 쓰려면 게시자에게 DM 으로 사용 허락을 받는 것이 유일하게 안전한
길이다. 사용자가 수동으로 진행하기로 했다.

## 5. 🔴 웹 전용으로 옮길 때 — 무엇이 막히는가

사용자가 **웹 브라우저 클로드만 쓰고 싶다**고 했다. 결론부터: **지금 그대로는
안 된다.** 남은 일의 핵심이 전부 로컬 전용이기 때문이다.

웹 세션은 GitHub 저장소만 복제해 온 클라우드 컨테이너에서 돈다. 노트북 파일과
`.env.local` 을 구조적으로 못 보고, 따라서 **DB 도 못 본다.**

| 남은 일 | 웹에서 |
| --- | --- |
| 사진 DB 에 넣기 | ❌ |
| 실사용자 수 재기 (`usage-check.ts`) | ❌ |
| 마이그레이션 적용 | ❌ |
| 번역 import·export | ❌ |
| AI 가이드 Edge Function 배포 | ❌ |
| 지도 카카오 키 도메인 등록 확인 | ❌ |
| 배포 사이트 실제 확인 | ❌ (vercel·TourAPI 차단) |
| OneDrive·학습자료 열람 | ❌ |
| 코드 수정 · 문서 · 기획 · PR | ✅ |

**오늘 한 일 중 웹에서 가능했던 것은 하나도 없다.** 번역 208곳도, 마이그레이션도,
사진 검증도 전부 DB 나 노트북 파일이 필요했다.

### 그래서 이렇게 권한다

**웹을 기본으로 쓰고, DB 작업이 생길 때만 로컬 창을 잠깐 연다.**
로컬 창은 "DB 에 반영하는 순간"에만 필요하다 — 한 번에 몇 분이면 끝난다.

세션끼리는 서로의 대화를 모른다. `ListAgents` 는 "No reachable agents" 를 준다
(2026-08-27 실측). 자동 전달 통로가 없다. **연락 수단은 GitHub 저장소와
`docs/이어서-할-일.md` 뿐이다.**

지켜야 할 세 줄:

1. 창을 옮기기 전에 → 쓰던 쪽에서 **푸시**
2. 창을 열자마자 → **`git pull`**
3. 같은 파일을 양쪽에서 동시에 고치지 않기 (오늘 `이어서-할-일.md` 에서 실제로 부딪혔다)
