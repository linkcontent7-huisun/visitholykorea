**사용자가 실제로 조작하는 화면은 전부 끝났다.** 사전 키 177개.

이어서 언어를 늘리거나 화면을 추가할 때의 절차:
사전에 키 추가 → `npx vitest run src/shared/i18n/dictionary` 로 6개 언어 누락
자동 검사 → 화면의 하드코딩을 `t()` 로 교체 → 화면에서 언어 바꿔 확인.

**설계상 알아둘 것 두 가지**

1. `fillPlaceholders(t('키'), { n, total })` — 숫자가 섞인 문장은 언어마다
   어순이 달라("208곳 가운데 0곳" vs "0 of 208") 조각을 이어 붙이면 번역이
   불가능하다. 문장 전체를 사전에 두고 값만 끼워 넣는다.
2. **나침반은 한국어 문자열을 타입·Record 키로도 쓴다**(Concern·TimeBudget 등).
   내부 값을 건드리면 저장된 나침반 응답과 타입이 깨지므로, 내부 키는 한국어로
   두고 **표시 문자열만** 사전 키로 바꿨다(`Record<Concern, TranslationKey>`).
   덕분에 없는 사전 키를 가리키면 TypeScript 가 컴파일 때 잡아준다.

> ✅ 나침반 검증 완료 (2026-08-31). 실브라우저 실클릭으로 4문항까지 확인

> (인트로→8문항→결과 도달·응답 저장 payload 검증, `HealingQuiz.test.tsx`).
>
> **"단계 전환이 안 됐다"의 원인을 특정했다** — 앱 버그가 아니라 자동화
> 브라우저가 백그라운드로 가면 rAF 가 멈춰 `mode="wait"` 퇴장 애니메이션이
