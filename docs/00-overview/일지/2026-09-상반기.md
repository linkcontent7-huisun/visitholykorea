## 9/11(5) — (해결됨 → 9/11(7)) AI 가이드 배포 준비

9/9 발견·9/10 재확인된 「ai-guide Edge Function 미배포」를 **9/11 21:40 curl 로 다시
확인 — 여전히 `NOT_FOUND`.** 배포 서버에 함수가 없어 앱의 「AI 가이드」 버튼이
지금도 답을 못 한다. 9/14 동결 전 **1순위**.

**이 세션에서 한 것**

- `npx supabase init` → `supabase/config.toml` 생성·커밋 (비밀값 없음). 이게 없어서
  `functions deploy` 가 안 됐다
- 함수가 요구하는 비밀값 확인: **`GEMINI_API_KEY` 하나**. `SUPABASE_URL`·
  `SUPABASE_ANON_KEY` 는 Supabase 가 함수에 자동 주입한다. `GEMINI_MODEL` 은 선택
- 앱은 `supabase.functions.invoke('ai-guide')` 로 부른다 → 기본 `verify_jwt=true` 와 맞음
- **사업계획서·아이템개요·표6 PNG 에 「AI 가이드 ✅ 배포」라고 적혀 있던 것을
  「🚧 서버 배포 대기」로 고쳤다.** 심사 자료에 거짓이 들어갈 뻔했다

**사장님이 할 것 — 값 2개를 `.env.local` 에 넣는다 (대화창에 붙이지 말 것)**

| 값                    | 어디서                                                             | `.env.local` 에                                                                                                 |
| --------------------- | ------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------- |
| Supabase Access Token | https://supabase.com/dashboard/account/tokens → Generate new token | `SUPABASE_ACCESS_TOKEN=sbp_…`                                                                                   |
| Gemini API Key        | https://aistudio.google.com/apikey → Create API key                | Supabase 대시보드 → Edge Functions → **Secrets** → `GEMINI_API_KEY` 로 직접 등록 (터미널에 안 남기는 편이 안전) |

**그다음 지시자가 할 것** (토큰이 `.env.local` 에 있으면 바로)

```bash
export SUPABASE_ACCESS_TOKEN=$(grep ^SUPABASE_ACCESS_TOKEN= .env.local | cut -d= -f2-)
npx supabase functions deploy ai-guide --project-ref kaahuoqzkgshihypzzyh
# 확인 — NOT_FOUND 대신 {"text": "..."} 가 와야 끝
curl -X POST https://kaahuoqzkgshihypzzyh.supabase.co/functions/v1/ai-guide   -H "Content-Type: application/json" -H "apikey: <anon>" -H "Authorization: Bearer <anon>"   -d '{"question":"명동성당 역사 알려줘"}'
```

`naver-auth` 함수도 같은 상태(미배포)로 보인다 — 네이버 로그인 버튼이 있다면 같이 배포.

## 9/11(3) — 영어 전면화 2차: 지역명·코스카드·붐빔피하기·여권미리보기까지 확장

사장님이 "다국어는 우선 영어라도 확실하게"라고 범위를 좁혀 지시. 9/11(2)에서 놓친
곳을 이어서 찾아 고쳤다. **범위가 넓어 페이지 단위로 쭉 훑는 방식으로 진행** —
발견 즉시 그 자리에서 고치고 다음 화면으로 넘어갔다.

### 1. 시·도·교구명 다국어 인프라 신설

`REGIONS`(17개 시·도)와 `holy_sites.region`(교구명)이 전부 한국어 문자열이라
"Within 서울"처럼 영어 문장 안에 한국어가 섞여 나오고 있었다. 지명은 언어마다
따로 옮기지 않고 로마자 표기를 국제 공통으로 쓰는 게 관행이라, 6개 국어 사전 대신
**`localizeRegionName(value, language)`** 로마자 매핑 하나를 새로 만들어
(`domain-labels.ts`) 아래 화면 전부에 적용했다: 메뉴(출발지 select) · 홈(히어로
캡션·"Shrines near {region}") · 탐색(교구 그리드) · 성지 상세(태그·"같은 교구
추천") · 지역 랜딩(문장 전체) · 지도(교구 필터·진행률) · 나침반(출발지 select) ·
축제(지역 칩) · 코스 카드(태그).

### 2. 코스 카드 제목·부제 — "문장 자체"를 언어별로 다시 짬

`course-matching.ts`의 `buildCard()`가 **API 함수 안에서 완성된 한국어 문장**을
합성하고 있었다("위로가 필요한 날, 서울 명동대성당 걷기 코스" 등) — 단순 치환이
아니라 문장 구조 자체가 언어별로 다르다. `getRecommendedCourses(...language)` 로
언어를 받아, 감정 힌트 5개·제목 템플릿·페어링 부제 템플릿을 전부 사전 키로
옮기고, 성지 이름도 카드 수만큼이 아니라 배치 조회 한 번으로 번역해 붙였다.

### 3. 붐빔 피하기(`AlternativesPage`) 전체

이 화면 전체가 다국어 사전을 아예 안 쓰고 있었다. `alternatives.ts`의
`buildAlternativeReason`(추천 이유 문장)·`estimateTravel`(도보 라벨)도
course-matching 과 같은 문제라 `language` 파라미터를 추가해 다시 짰다.
`AlternativesPage`·`AlternativesList` 의 모든 하드코딩 문구를 사전으로 옮겼다.

### 4. 붐빔 등급("아주 조용"·"매우 붐빔" 등) — 번역 인프라 자체가 없었다

`CrowdingBadge`가 `CrowdingLevel` 값을 그대로 렌더링해서, 홈의 "오늘의 쉼표"
섹션이 영어 모드에서도 등급만 한국어로 남아 있었다. `localizeCrowdingLevel()`
을 새로 만들어 적용.

### 5. 실제로 겪은 사고 — react-query 캐시가 번역 전 이름을 붙들고 있었다

홈 화면을 다 고쳤는데 "오늘의 쉼표" 카드만 성지 이름이 한국어로 남았다. 원인은
`useQuietSites`의 캐시 키가 **날짜·개수뿐**이라, `sites` 배열의 내용(번역 여부)이
나중에 바뀌어도 이미 한 번 캐시된 결과를 다시 계산하지 않는 것이었다 — 번역 쿼리가
비동기로 늦게 도착하는 경쟁 상태. `TodayQuietSection` 안에서 계산 결과의 `site`를
**한 번 더** `useLocalizedSites`로 감싸 이름을 덧씌우는 방식으로 고쳤다(원인이 된
캐시 키 자체는 건드리지 않았다 — 다른 곳에서도 같은 패턴을 쓸 때 참고할 것).

### 확인한 것

`npm run verify` 통과(타입·린트 0 신규 에러 — 기존 Fast Refresh 경고 2건만 유지,

## 9/11 — GPS 현재 위치 기반 정렬 추가 (분석 보고서 1순위 항목)

9/10 분석 보고서(`docs/00-overview/현황판/2026-09-10-핵심기능-구조-테스트-분석.md`)가 지적한
"실제 GPS 를 안 읽고 선택한 지역의 중심좌표만 쓴다"를 고쳤다. **기존 출발지(시·도)
선택 기능은 그대로 두고, 그 위에 "현재 위치 사용"을 추가**하는 방식으로 갔다 —
지역 선택이 이미 여러 화면(홈·탐색·여권 미리보기)의 거리 정렬 기준이라, 갈아엎기보다
얹는 쪽이 안전하다.

| 한 일                                                                                                                          | 파일                                                          |
| ------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------- |
| GPS 상태(`gpsLocation`·`gpsStatus`)와 요청/해제 함수를 설정 컨텍스트에 추가                                                    | `settings-context.ts`, `SettingsProvider.tsx`                 |
| `navigator.geolocation.getCurrentPosition` 래핑 — 미지원·거부·오류 상태 구분                                                   | `SettingsProvider.tsx`                                        |
| 메뉴 화면에 "현재 위치 사용" 항목 추가(출발지 select 바로 위, 켜지면 select 비활성화)                                          | `MenuPage.tsx`                                                |
| 홈·탐색·여권 미리보기의 거리 정렬 — `regionCoords(origin)` 단독 사용을 `gpsLocation ?? regionCoords(origin)` 로 교체(GPS 우선) | `HomePage.tsx`, `ExplorePage.tsx`, `EmptyPassportPreview.tsx` |
| 번역 키 7개(6개 국어) — 버튼·상태 문구                                                                                         | `dictionary.ts`                                               |

**의도적으로 안 한 것** — GPS 좌표를 저장(localStorage)하지 않는다. 위치는 이동하는
값이라 세션마다 새로 물어보는 게 정확하고, 오래된 좌표를 들고 있다가 엉뚱한 곳을
"내 주변"이라고 보여주는 사고를 막는다. 꺼졌다 켜지면(새로고침) 다시 물어본다.

**확인한 것** — `npm run verify` 통과(타입·린트 0 신규 에러, 테스트 353/353).
로컬 dev 서버 브라우저 프리뷰로 실측:

- 메뉴 화면에서 "현재 위치 사용" 클릭 → 프리뷰 샌드박스가 위치 권한을 자동 거부하는
  환경이라 "위치 권한이 거부되었습니다" 안내가 정확히 뜨는 것을 확인(에러 처리 검증됨).
  **실제 기기에서 권한을 허용했을 때의 성공 경로(좌표 획득 → 정렬 반영)는 이번
  세션에서 못 봤다** — 다음 세션이 실기기나 실제 브라우저 권한 허용 환경에서 확인할 것.
- 출발지를 "서울"로 선택 → 기존 지역 기반 정렬 회귀 없음 확인(서울 소재 성지가
  먼저 노출: 우포도청 터·김범우의 집터 등).
- 콘솔에 `ERR_NAME_NOT_RESOLVED`/`ERR_NETWORK_IO_SUSPENDED` 에러가 있었으나
  Supabase/외부 리소스 접근이 막힌 프리뷰 샌드박스 환경 탓으로 보인다(우리 코드가
  아니라 HMR 웹소켓·외부 이미지 호출) — React 렌더링 에러는 없었다.

**다음에 하면 좋은 것** — 현재는 메뉴 화면에만 GPS 버튼이 있다. 분석 보고서가
지적한 "추천 카드에서 목적지 길찾기"까지 이어가려면, 흠 화면이나 나침반 결과에도
GPS 버튼을 노출하는 게 자연스럽다. 또한 `distance-label.ts`(`distanceLabel` 함수)는
아직 한국어 하드코딩이라 "현재 위치 안에 있어요" 문구가 다른 언어 모드에서도
한국어로 나온다 — 이어지는 영어 전면화 작업에서 같이 처리 대상.

`supabase/functions/ai-guide/` 코드는 저장소에 있지만 Supabase 프로젝트에

정상 작동해서 완전히 막막하진 않지만, **핵심 기능 하나가 통째로 죽어 있다.**

**막힌 것** — 배포하려면 `supabase login`(Supabase 접속 토큰)이 필요한데
이 세션엔 그 권한이 없다(`npx supabase projects list` → 인증 필요 에러).

| 필요한 값                      | 어디서 발급                                                          | 무엇에 쓰나                                  |

### 🔴 오늘 발견한 사고 — 검증 방법 자체의 결함

`npm run test 2>&1 | tail -N` 로 백그라운드 실행한 뒤 **셸의 `$?`(종료 코드)를

**🔴 다음부터 지킬 것** — `| tail`/`| head` 로 파이프한 명령의 종료 코드는
믿지 않는다. 파일로 리다이렉트한 뒤 `; echo $?` 로 실제 종료 코드를 따로
확인하거나, `set -o pipefail` 을 쓴다.

## 9/7(2) — 멀티 에이전트 오케스트레이션: 되는 것과 안 되는 것 (실측)

**결론부터: 배관은 작동한다. 막힌 것은 Windows 의 격리 기능이다.**
다음에 이 벽에 다시 부딪히지 않도록 실측만 적는다.

### 되는 것 — Orca orchestration

Claude 와 Codex 는 **Orca 를 통해 실제로 대화할 수 있다.** 오래 "통로가 없다"고
알고 있었는데 틀렸다. `~/.agents/skills/orchestration` 스킬이 설치돼 있었고,
Claude Code 만 설치 목록에서 빠져 있었을 뿐이다. `~/.claude/skills/` 로 복사하면
즉시 인식된다.

```
orca orchestration run-create   → Run 생성, 지시자 결속
orca orchestration task-create  → 작업 정의
orca orchestration worker-start → Codex 기동 + 작업 주입
orca orchestration check        → worker_done 수신
orca terminal create/read/close → 터미널 직접 제어
```

**T-009(솔뫼·배론·약현 스페인어)를 이 방식으로 끝냈다.** 사람이 지시서를
붙여넣는 단계가 없었다. 커밋 `fce1671`.

### 🔴 안 되는 것 — Windows 에서는 「울타리 + 안 묻기」가 성립하지 않는다

Codex 샌드박스는 리눅스·맥의 OS 기능에 기댄다. Windows 에는 그 기능이 없다.
그래서 조합이 둘뿐이다.

| 실행 옵션                                                 | 결과                                                                                                         |
| --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `--sandbox workspace-write --ask-for-approval on-request` | 울타리는 있으나 **명령마다 사람이 승인 클릭**. Orca 가 에이전트의 대리 클릭을 막는다(`agent_prompt_blocked`) |
| `--sandbox workspace-write --ask-for-approval never`      | **모든 명령이 차단된다.** Codex 가 "환경이 모든 터미널 명령 실행을 정책상 차단"이라며 아무 일도 못 한다      |
| `--dangerously-bypass-approvals-and-sandbox` (Orca 기본)  | 클릭 없이 돌지만 **울타리가 없다** — 노트북 전체와 인터넷이 열린다                                           |

**Orca 가 Windows 에서 YOLO 를 기본값으로 쓰는 이유가 이것이다.**
T-005·T-008·T-009 는 전부 YOLO 로 돌았다.

> ⚠️ **설정 파일만 보고 "안전하다"고 판단하지 말 것.** `~/.codex/config.toml` 에
> `sandbox_mode`·`approval_policy` 를 넣어도 명령줄 옵션이 덮어쓴다. 실제 실행
> 상태는 프로세스로 확인한다:
> `Get-CimInstance Win32_Process -Filter "Name='codex.exe'" | % { $_.CommandLine }`

또 하나: Orca 는 Codex 를 **자기 전용 CODEX_HOME** 으로 돌린다
(`AppData\Roaming\orca\codex-accounts\<id>\home`). 다만 `~/.codex/config.toml`
의 내용을 복사해 가므로 그쪽을 고치면 반영은 된다(2026-09-07 확인).

### 다음에 시도할 것 — 우선순위 순

1. **별도 worktree 에서 돌리기** (`worker-start --worktree new-child`).
   git 이 추적하는 파일만 있는 새 체크아웃을 준다 → **`.env.local` 이 그 폴더에
   아예 없다.** 규칙으로 부탁하는 대신 물리적으로 없앤다. Windows 에서도 된다.
2. **WSL 안에서 Codex 실행.** 리눅스 샌드박스가 살아나 「울타리 + 안 묻기」가
   동시에 된다. Orca 도 managed WSL 세션을 지원한다(스킬 문서에 `ORCA_CLI_COMMAND` 언급).
3. **`.env.local` 의 키 교체.** 걱정의 실체는 그 파일 하나다. 배포까지 손대야
   하므로 9/14 이후.

### 비용에 대한 판단

**도슨트 번역은 애초에 다중 에이전트가 필요한 일이 아니었다.** JSON 몇 개에
