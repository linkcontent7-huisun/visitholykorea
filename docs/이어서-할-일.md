## 🔴 가장 먼저 — Supabase SQL Editor 에서 마이그레이션 적용

**마이그레이션 3개가 DB 에 적용된 적이 없다.** 파일만 있고 실제 테이블이 없다.
번역만의 문제가 아니라 순례 기록·쉼터 기능도 지금 DB 에 테이블이 없는 상태다.

| 테이블 | 상태 |
| --- | --- |
| `holy_sites` | 있음 (208행) |
| `catholic_directory` | 있음 (5,918행) |
| `pilgrimage_stamps` | 있음 |
| `pilgrimage_logs` | **없음** |
| `rest_places` / `rest_spots` | **없음** |
| `holy_site_translations` | **없음** |

세 마이그레이션을 순서대로 SQL Editor 에 붙여넣고 Run 한다.
전부 `if not exists` 라 여러 번 돌려도 안전하다.

1. `supabase/migrations/20260804090200_create_pilgrimage_logs.sql`
2. `supabase/migrations/20260805100000_create_rest_spots.sql`
3. `supabase/migrations/20260805110000_create_holy_site_translations.sql`

마지막에 **반드시** 이 한 줄을 실행한다. 없으면 테이블을 만들어도
PostgREST 가 한동안 못 본다(스키마 캐시).

```sql
notify pgrst, 'reload schema';
```

확인:

```bash
npm run translate:status
```

> **함정** — `select('*', { head: true })` 는 테이블이 없어도 통과한다.
> 테이블 존재 확인은 반드시 컬럼을 지정해서 조회해야 한다.

## 다음에 할 일 — 우선순위 순

### 1. 영어 번역 206곳 ← 진행 중

**파이프라인은 완성됐다.** 교구 단위로 내보내고 → 채우고 → 넣는다.

```bash
npm run translate:status                                    # 진행률
npm run translate:export -- --diocese 대전                   # 대상 뽑기
npm run translate:import -- data/translations/en-대전.todo.json
```

내보내기는 이미 번역된 곳을 뺀다. 넣기는 빈 칸을 건드리지 않아서,
소개글 먼저 넣고 역사를 나중에 넣어도 앞 값이 지워지지 않는다.
사람이 감수한 뒤에는 `--reviewed` 를 붙여 넣으면 `translation_status` 가 바뀐다.

| 교구 | 곳 | 상태 |
| --- | --- | --- |
| 서울 | 25 | **번역 완료** — `data/translations/en-서울.todo.json`. 마이그레이션 적용 후 import 만 하면 된다 |
