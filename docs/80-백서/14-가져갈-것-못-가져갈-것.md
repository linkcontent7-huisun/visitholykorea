# 14장. 성지웹에서 가져갈 것 / 못 가져갈 것

> **"지난 프로젝트 코드를 복사해 오면 되지 않나"** 에 대한 답이다.
>
> 결론부터: **설정과 규칙은 복사하고, 기능 코드는 복사하지 않는다.**
> 복사한 기능 코드는 "왜 이렇게 됐는지"를 모르는 채 따라오고, 그게 4장의 낭비를 그대로 옮겨 온다.

---

## 14-1. 한눈에

| | 가져갈 것 | 못 가져갈 것 |
| --- | --- | --- |
| **설정** | 빌드·린트·테스트 설정, `verify`, CI | — |
| **규칙** | `CLAUDE.md` 구조 규칙, ADR 양식, 문서 폴더 | 도메인 제약 (TourAPI 저장 금지 등) |
| **패턴** | repository, query-keys, paths, i18n, machine/reviewed | — |
| **코드** | `shared/` 의 일부 도구 함수 | `features/` 전부, `pages/` 전부 |
| **데이터** | — | 성지 206곳, 도슨트 원고, 사진 |
| **도구** | 스크립트 구조(export/import/status/check) | 성지 전용 스크립트 |
| **판단** | 3·4장의 사건과 낭비 목록 | 50대 사용자 전제, 6개 언어 |

## 14-2. 그대로 복사하는 것 — 파일 단위

### 설정 파일

| 파일 | 그대로? | 비고 |
| --- | --- | --- |
| `tsconfig.json` | ✅ 그대로 | |
| `eslint.config.js` | ✅ 그대로 | |
| `vitest.config.ts` | ✅ 그대로 | |
| `.prettierrc` | ✅ 그대로 | |
| `package.json` 의 `scripts` | ✅ **`verify` 줄은 반드시** | 나머지는 골라서 |
| `.gitignore` | ✅ + 5장 5-3 의 비밀 차단 줄 추가 | |
| `vercel.json` | ✅ + **`ignoreCommand` 추가** | 사건 8 재발 방지 |
| `.github/workflows/` | ✅ 구조만 | 내용은 프로젝트에 맞게 |

### 의존성 — 필요한 것만

라디오작가에 **필요한 것**:

```
react, react-dom, react-router-dom
@tanstack/react-query
@supabase/supabase-js
tailwindcss
vitest, eslint, prettier, typescript
(AI SDK — 쓰는 모델에 맞게)
```

**필요 없는 것**: `@capacitor/*`(모바일 앱 포장), `jspdf`, `motion`, `figma-squircle`,
지도 관련 전부. `[package.json 대조, 2026-09-23]`

> **의존성은 적을수록 좋다.** 성지웹은 모바일 앱을 만들어야 해서 Capacitor 가 필요했다.
> 라디오작가는 작가 몇 명이 PC 로 쓰는 웹이다 `[확인 필요]`. **안 쓸 것을 먼저 빼고 시작한다.**

## 14-3. 패턴으로 가져가는 것 — 복사 말고 **다시 쓰되 같은 모양으로**

| 패턴 | 성지웹 파일 | 라디오작가에서 |
| --- | --- | --- |
| **repository 계층** | `features/sites/api/sites.repository.ts` | `features/scripts/api/scripts.repository.ts` |
| **캐시 키 한 곳** | `shared/api/query-keys.ts` | 그대로 새로 |
| **주소 한 곳** | `app/routes/paths.ts` | 그대로 새로 |
| **문구 사전** | `shared/i18n/dictionary.ts` | 그대로 새로 (한국어만이어도) |
| **AI 상태 구분** | `translation_status` + `reviewed_by/at` | `status` + `edited_by/at` → [13장 13-6](13-라디오작가-적용.md) |
| **AI 컨텍스트 제한** | `supabase/functions/ai-guide/index.ts` | **이건 읽어볼 값어치가 있다** |
| **스크립트 4종** | `*-status` `*-check` `*-export` `*-import` | `draft:status` `draft:check` … |

> **왜 복사가 아니라 "다시 쓰되 같은 모양"인가**: 성지웹의 repository 는 성지 컬럼에 맞춰져 있다.
> 복사하면 안 쓰는 필드가 따라오고, 그걸 지우는 데 드는 시간이 새로 쓰는 시간보다 길다.
> **모양(어디에 무엇을 두는가)만 같으면 된다.**

## 14-4. 읽어볼 값어치가 있는 파일 5개

라디오작가를 시작하기 전에 **이 다섯 개는 열어본다.**

| 파일 | 왜 |
| --- | --- |
| `supabase/migrations/20260805110000_create_holy_site_translations.sql` | **원본/파생 분리 + machine/reviewed** 의 교과서. 주석이 설계 설명서다 |
| `supabase/functions/ai-guide/index.ts` | AI 컨텍스트 제한, "모르면 모른다" 문장, 모델 대체 경로 |
| `supabase/migrations/20260804090000_create_holy_sites.sql` | 표 설계 6요소 (7장 7-3) |
| `CLAUDE.md` | 프로젝트 헌법의 실물 |
| `scripts/translation-status.ts` | 진행률 집계 스크립트의 모양 |

## 14-5. 절대 못 가져가는 것 — 그리고 그 이유

### ① 도메인 데이터

성지 206곳, 도슨트 원고 108곳, 사진, 교구 정보. 당연하다.

### ② 도메인 제약

| 성지웹 제약 | 라디오작가에는 |
| --- | --- |
| TourAPI 응답 저장 금지 (공모전 실격 위험) | **해당 없음.** 대신 **저작권 있는 자료의 저장 가능 여부**를 새로 정해야 함 `[확인 필요]` |
| AI 답변을 성지 DB 안으로 제한 | **모양은 같지만 자료가 다르다.** 무엇을 컨텍스트로 넣을지 새로 정함 |
| 관광공사 공모전 일정 | 방송 마감 주기 `[확인 필요]` |

> **제약을 복사하면 안 된다.** "TourAPI 저장 금지" 를 라디오작가 `CLAUDE.md` 에 복사해 넣으면
> 다음 세션이 존재하지 않는 규칙을 지키느라 이상한 설계를 한다.

### ③ 사용자 전제

| 성지웹 | 왜 라디오작가엔 안 맞나 |
| --- | --- |
| 50대 이상 85% → 큰 글자, 단순 동선 | **작가는 전문 사용자다.** 정보 밀도가 높아도 된다 `[확인 필요]` |
| 6개 언어 | 한국어만 |
| 익명 사용자 수천 명 | **로그인한 몇 명.** 권한 설계가 완전히 다르다 |
| 모바일 우선 | **PC 우선** — 원고를 길게 쓰고 고치는 화면 `[확인 필요]` |

> **접근성 규칙(rem 기반)은 그래도 가져간다.** 이건 사용자가 누구든 손해가 없다.

### ④ 화면 구조

하단 탭 5개(홈·성지 찾기·고요 속으로·내 기록·더보기)는 성지웹의 답이다.
라디오작가는 **화면이 5~7개**면 되고, 하단 탭이 아니라 **상단 메뉴 또는 좌측 목록**이 맞을 수 있다 `[확인 필요]`.

## 14-6. 판단을 가져간다 — 이게 가장 값나간다

코드보다 값나가는 것은 **3장의 사건 8개와 4장의 낭비 5유형**이다.

### 새 기능 앞에서 묻는 5개 (4장 4-5)

1. 이 기능의 결과를 **누가 어느 화면에서** 보나?
2. 필요한 **데이터를 실제로 한 번 받아봤나?**
3. 데이터가 **없을 때 화면은 어떻게** 되나?
4. 이미 **비슷한 화면이 있나?**
5. 이걸 **안 만들면 무엇이 안 되나?**

### 매주 돌리는 3줄 (2장 2-1, 12장 12-3)

```bash
git log --since="1 week ago" --format= --name-only -- src | sort | uniq -c | sort -rn | head -10
npm run verify > verify.log 2>&1; echo "exit=$?"
# 튀어 오르는 파일이 지금 잘못 설계돼 있는 파일이다
```

### "됐다"고 말해도 되는 5조건 (11장 11-7)

1. `verify` 가 실제로 통과 (종료 코드 확인)
2. 브라우저에서 핵심 동작을 끝까지
3. 배포 주소에서 같은 확인
4. 번들에 비밀 문자열 없음
5. `이어서-할-일.md` 를 그 자리에서 갱신

## 14-7. 물리적으로 옮기는 방법

**저장소를 통째로 복제(fork)하지 않는다.** 성지웹 206곳 데이터와 218개 문서가 따라온다.

```bash
# ① 새 빈 저장소로 시작
mkdir C:\dev\radio-writer && cd C:\dev\radio-writer && git init

# ② 설정 파일만 골라서 복사
#    tsconfig.json, eslint.config.js, vitest.config.ts, .prettierrc, .gitignore

# ③ 백서만 참고용으로 복사하거나, 성지웹 저장소를 옆에 열어둔다
#    (복사하면 성지웹 쪽 갱신이 반영 안 되므로 옆에 열어두는 쪽을 권장)
```

> **백서를 새 프로젝트에 복사할 때**: 이 문서들은 성지웹의 숫자와 커밋 해시를 근거로 인용한다.
> 복사하면 **어느 저장소의 커밋인지 모르게 된다.**
> 새 프로젝트의 `CLAUDE.md` 에 한 줄만 쓰는 것이 낫다:
>
> ```markdown
> ## 참고
> 지난 프로젝트(VisitHolyKorea)의 개발 백서: <저장소 주소>/docs/80-백서/
> 새 기능을 만들기 전에 4장(낭비 목록)과 6장(기획)을 읽는다.
> ```

## 14-8. 마지막 — 이 백서를 어떻게 갱신하나

이 백서는 **「결정」 층 문서**다 (12장 12-6). 사건과 교훈은 안 바뀐다.

| 갱신해야 하는 곳 | 언제 |
| --- | --- |
| 1장 실측 숫자 | 크게 바뀌면. **잰 날짜를 같이 고칠 것** |
| 12-4 미결 목록 | 미결이 해결되면 |
| 13장 `[확인 필요]` 항목 | 라디오작가 기획이 정해지면 |
| **3·4장** | **안 고친다.** 지나간 사건은 안 바뀐다 |

라디오작가를 만들고 나면 **그 프로젝트의 3·4장을 새로 쓴다.**
이번에 겪은 사건 8개가 몇 개로 줄었는지가 이 백서가 실제로 도움이 됐는지의 답이다.
