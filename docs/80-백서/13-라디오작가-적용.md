# 13장. 라디오작가 에이전트에 적용하면

> **이 백서를 덮고 바로 시작할 수 있게 쓴 장이다.**
>
> 아는 것: 대전가톨릭평화방송의 **라디오 원고를 AI 가 초안으로 쓰고,
> 실제 라디오작가가 그것을 보고 다듬어 최종 원고를 제출하는 웹.**
> 나머지는 전부 `[확인 필요]` 로 표시했다 — 제작자만 아는 것이다.

---

## 13-1. 이 프로젝트가 성지웹과 다른 점

| | 성지웹 | 라디오작가 |
| --- | --- | --- |
| 성격 | **읽는 앱** — DB → 화면 | **만드는 앱** — 초안 → 검수 → 제출 |
| 사용자 | 순례자 수천 명 (익명) | **작가 몇 명** (로그인 필수) |
| 핵심 데이터 | 성지 206곳 (고정) | **회차 원고** (계속 쌓임) |
| AI 역할 | 질문에 답함 (부가) | **원고를 씀 (본체)** |
| 실패의 대가 | 정보가 틀림 | **방송에 틀린 원고가 나감** |
| 화면 수 | 21개 | **적어도 됨** — 아마 5~7개 `[확인 필요]` |

> **가장 중요한 차이**: 성지웹에서 AI 는 **부가 기능**이었다. 라디오작가에서 AI 는 **제품 그 자체**다.
> 그래서 7장 7-5(AI 가 만든 것 / 사람이 고친 것 구분)가 **설계의 중심**이 된다.

## 13-2. 성지웹이 이미 답을 가진 것 — 그대로 가져온다

| 성지웹에 있는 것 | 라디오작가에서 |
| --- | --- |
| `translation_status` 의 `machine` / `reviewed` + `reviewed_by` + `reviewed_at` | **초안 상태 관리의 완성형.** 이름만 바꿔 쓴다 |
| "컨텍스트에 없으면 모른다고 답하라" 시스템 프롬프트 | 원고에 **없는 사실을 지어내지 않게** 하는 장치 |
| 모델 이름 CI 자동 갱신 | 모델 폐기에 안 죽게 |
| Gemini 실패 시 Claude 로 대체 (같은 제약 유지) | AI 장애에 안 죽게 |
| `translate:export` / `translate:import` (파일로 빼고 넣기) | **작가가 워드로 받아 고치고 되넣기** |
| `translate:status` (진행률 집계) | 회차별 진행 현황판 |
| repository 계층, 의존 방향, `verify` | 뼈대 그대로 |

## 13-4. `CLAUDE.md` 초안 — 그대로 쓰고 채우면 된다

```markdown
# CLAUDE.md

## 작업을 시작하기 전에
`docs/이어서-할-일.md` 부터 읽는다. 작업이 끝나면 그 자리에서 고친다.

## 이 프로젝트가 무엇인가
대전가톨릭평화방송 라디오 원고를 AI 가 초안으로 쓰고,
라디오작가가 다듬어 최종 원고를 제출하는 웹.

## 반드시 지킬 것
- **AI 초안은 그대로 제출되지 않는다.** 사람이 본 기록(누가·언제)이 없는 원고는
  제출 상태가 될 수 없다. 이 장치를 걷어내지 말 것.
- **AI 가 자료에 없는 사실을 지어내지 않게 한다.** 교회 관련 정보는 틀리면
  신뢰가 바로 무너진다. 컨텍스트 밖은 "확인 필요"로 표시하게 시스템 프롬프트에 못 박는다.
- **비밀 키를 클라이언트에 두지 않는다.** VITE_ 접두사가 붙은 값은 브라우저에 그대로 들어간다.
- **원고 원문은 지우지 않는다.** AI 초안과 작가 수정본을 둘 다 남긴다.
- (저작권 있는 외부 자료의 저장 가능 여부)   ← [확인 필요]

## 코드 구조 규칙
- 의존성 방향: pages → features → shared. 역방향 import 금지.
- DB 행(snake_case) ↔ 도메인 타입(camelCase) 변환은 api/*.repository.ts 안에서만.
- 서버 상태는 TanStack Query, 캐시 키는 shared/api/query-keys.ts 한 곳에서.
- 라우트 경로는 app/routes/paths.ts 에서만.
- 새 테이블 = 마이그레이션 + shared/types/database.ts 를 함께.

## 스타일
- 주석과 UI 문구는 한국어. "무엇을"보다 "왜"를 남긴다.
- 화면 문구는 처음부터 사전(shared/i18n)에. 코드에 한국어를 박지 않는다.
- 커밋 전 `npm run verify` 통과.
- 여러 창을 쓸 때는 `git commit -- <경로>` 로만. `git add .` 금지.
```

## 13-5. 1단계에서 AI 에게 받을 질문 목록

기획 대화를 시작할 때 이 프롬프트를 쓴다:

```
대전가톨릭평화방송 라디오작가 에이전트를 만들려고 해.
docs/80-백서/ 를 먼저 읽고, 바로 만들지 말고
내 의도를 파악하기 위한 질문을 3개씩 물어봐.
```

AI 가 물어야 할 것들 — **미리 알고 있으면 답이 빨라진다**:

### 사람과 흐름

1. 작가는 몇 명인가? 서로의 원고를 보나, 자기 것만 보나?
2. 원고는 누가 **최종 승인**하나? 작가가 곧 승인자인가, PD 가 따로 있나?
3. "제출"은 **어디로** 가는가? 파일 다운로드? 메일? 방송 시스템 연동?
4. 작가는 이 웹에서 고치나, **워드로 받아 고치고 되넣나?**
5. 마감은 언제인가? 회차 주기는? (매일? 주 1회?)

### 원고

6. 한 회차 원고의 **구조**는? (코너·꼭지·시간 배분·큐시트)
7. 분량은? 글자 수 제한이 있나?
8. **금칙어·표기 규칙**이 있나? (교회 용어 표기, 존칭)
9. AI 가 참고할 **자료**는 무엇인가? (성경 구절·교회력·지난 회차·보도자료)
10. 지난 회차를 AI 가 참고해야 하나? (반복 방지)

### 품질과 책임

11. AI 초안이 **얼마나 쓸 만해야** 쓸 만한 건가? (다 갈아엎으면 실패)
12. 잘못된 원고가 방송에 나가면 **누구 책임**인가? 기록을 어디까지 남겨야 하나?
13. AI 가 썼다는 사실을 **어딘가에 표시**해야 하나?

### 범위

14. **이번에 안 만들 것**은? (음성 합성? 편성표? 청취자 사연?)
15. 1차 완성 조건은? 무엇이 되면 끝인가?

> **13·14번이 4장의 낭비를 막는 질문이다.** 안 만들 것을 먼저 적는다.

## 13-6. 표 설계 초안 — 2단계에서 다듬는다

> **7장 7-4·7-5 의 원칙을 그대로 적용한 것이다.** 실제 원고를 본 뒤 고친다.

```sql
-- 프로그램. 갱신 주기가 다른 것(프로그램 설정 vs 회차 원고)은 표를 나눈다.
create table programs (
  id uuid primary key default gen_random_uuid(),
  name text not null,                 -- 예: 아침 프로그램 이름
  -- AI 에게 매번 주는 지침. 말투·분량·금칙어. 프로그램마다 다르다.
  style_guide text,
  created_at timestamptz not null default now()
);

-- 회차. 한 방송분.
create table episodes (
  id uuid primary key default gen_random_uuid(),
  program_id uuid not null references programs(id) on delete cascade,
  air_date date not null,             -- 방송일
  title text,
  -- 같은 프로그램의 같은 날짜가 두 번 들어가는 사고를 막는다.
  unique (program_id, air_date)
);

-- 원고. 이 표가 서비스의 심장이다.
-- 성지웹 holy_site_translations 의 machine/reviewed 구조를 그대로 가져왔다.
create table scripts (
  id uuid primary key default gen_random_uuid(),
  episode_id uuid not null references episodes(id) on delete cascade,

  -- 원문은 지우지 않는다. AI 초안과 수정본을 둘 다 남긴다.
  ai_draft text not null,             -- AI 가 쓴 것 — 절대 덮어쓰지 않는다
  edited_text text,                   -- 작가가 고친 것. 없으면 초안으로 폴백

  -- AI 가 만든 것과 사람이 고친 것을 숨기지 않는다.
  -- 틀린 원고가 방송에 나가면 누가 언제 봤는지가 유일한 근거가 된다.
  status text not null default 'ai'
    check (status in ('ai', 'editing', 'reviewed', 'submitted')),
  edited_by text,
  edited_at timestamptz,
  submitted_at timestamptz,

  -- 어떤 모델이 어떤 프롬프트로 썼나.
  -- 품질이 갑자기 나빠졌을 때 원인을 찾는 유일한 길이다.
  model_name text,
  prompt_version text,

  created_at timestamptz not null default now()
);

-- 작가만 접근한다. 처음부터 켠다 (나중에 붙이면 늦는다).
alter table scripts enable row level security;
```

### 이 설계가 지키는 것

| 규칙 | 어떻게 |
| --- | --- |
| AI 초안은 그대로 제출 안 됨 | `submitted` 가 되려면 `edited_by` 가 있어야 함 (앱·DB 양쪽에서 막음) |
| 원문 보존 | `ai_draft` 는 덮어쓰지 않음 |
| 폴백 | `edited_text` 가 없으면 `ai_draft` 를 보여줌 |
| 품질 추적 | `model_name` + `prompt_version` |
| 진행률 집계 | `status` 로 한 번에 셈 → `npm run draft:status` |

## 13-7. 화면 목록 초안 — 1단계에서 확정한다

| 화면 | 주소 | 무엇 | 필요한 데이터 |
| --- | --- | --- | --- |
| 로그인 | `/login` | 작가만 | — |
| 회차 목록 | `/` | 이번 주 회차와 상태 | episodes + scripts.status |
| **원고 편집** | `/episodes/:id` | **AI 초안 ↔ 수정본 나란히**, 고치고 저장 | script 1건 |
| 초안 생성 | `/episodes/:id/generate` | 자료 고르고 생성 | programs.style_guide + 자료 |
| 제출 | 편집 화면 안 | 최종 확인 후 제출 | — |
| 프로그램 설정 | `/programs/:id` | 말투·분량·금칙어 | programs |

**핵심 동작 한 개 = 「원고 편집」 화면.** 이게 되기 전에 나머지를 만들지 않는다.

> **4장 유형 2 방지**: 「초안 생성」이 별도 화면인지 편집 화면 안의 단추인지를
> **지금** 정한다. 나중에 정하면 같은 기능에 이름이 둘 생긴다.

## 13-8. 예상되는 함정 — 성지웹 사건의 재현 예보

| 성지웹 사건 | 라디오작가에서 어떻게 나타날까 | 막는 법 |
| --- | --- | --- |
| 사건 3 키 노출 | AI 키가 브라우저에 | Edge Function + 배포 번들 검색 |
| 사건 4 작동 안 한 기능 | **AI 초안이 쓸 만하지 않은데 화면은 멀쩡** | 10편 생성해 "몇 편이 쓸 만한가" 실측 |
| 사건 5 뒤늦은 재기획 | 작가가 "이렇게 쓰는 게 아닌데" | **실제 원고 한 편을 먼저 본다** |
| 사건 6 사전 104회 | 화면 문구를 나중에 정리 | 처음부터 사전에 |
| 사건 8 배포 한도 | 마감일에 배포 막힘 | `ignoreCommand` 를 첫날 |
| 낭비 유형 1 | **통계 화면 없는데 데이터부터 모음** | "누가 어느 화면에서 보나" |

> **가장 큰 위험은 사건 4다.** AI 원고의 품질은 화면을 봐서는 모른다.
> **작가가 실제로 써보고 "이거 쓸 만하다"고 해야** 작동하는 것이다.
> 그 확인을 **1주차에** 한다 — 두 달 뒤가 아니라.

## 13-9. 첫 주 일정표

> "쓸 만하다"면 나머지는 성지웹에서 배운 대로 만들면 된다.
