> **이 장이 가장 많은 사고를 낳았다.** 3장 사건 3(키 노출)·4(작동 안 한 기능)·8(배포 한도)이 전부 여기다.

## 10-1. 비밀 키를 브라우저에 두지 않는다

> **3장 사건 3**: TourAPI 인증키가 **한 달 동안 브라우저 번들에 노출**돼 있었다.

### 왜 새어 나갔나

```ts
// ❌ 이렇게 쓰면 env 전체가 번들에 인라인된다
const env = import.meta.env          // 객체 자체를 읽음
```

원인은 `src/shared/config/env.ts:16` 이 `import.meta.env` **객체 자체**를 읽은 것.
Vite 가 env 전체를 번들에 박아버려서 `VITE_VERCEL_BRANCH_URL` 같은 시스템 변수까지 노출됐다
`[2026-09-14-전면-재기획.md §1-1]`.

```ts
// ✅ 필요한 값만 하나씩 이름으로 읽는다
const supabaseUrl = import.meta.env.VITE_SUPABASE_URL
```

### 규칙: `VITE_` 가 붙으면 **공개된다**

| 접두사 | 어디까지 가나 | 넣어도 되는 것 |
| --- | --- | --- |
| `VITE_...` | **브라우저 번들에 그대로** | 공개용 ID, 공개 URL, anon 키 |
| 접두사 없음 | 서버·빌드에만 | 비밀 키 전부 |

**감춰야 하는 값은 서버 함수(Edge Function)의 시크릿으로 넣고, 앱은 함수를 부른다** `[CLAUDE.md]`.

```
브라우저  →  Edge Function (키를 여기에 보관)  →  외부 API
```

성지웹 Edge Function 5개 `[ls supabase/functions, 2026-09-23]`:
`ai-guide`(AI 키) · `tour-proxy`(TourAPI 키) · `kakao-auth` · `naver-auth` · `delete-account`

### 배포할 때마다 확인한다

```bash
# 배포된 번들에 비밀 문자열이 있는지 검색
curl -s https://<도메인>/assets/index-*.js | grep -o "SERVICE_KEY[^,]*" | head
```

> **3장 사건 3이 한 달 걸린 이유**: 아무도 번들을 안 열어봤다. → [11장 6단계](11-6단계-검증배포.md)

## 10-2. 만든 것과 **실제로 쓰이는 것**을 대조한다

9/14 점검에서 나온 세 가지 `[2026-09-14-전면-재기획.md §1-1]`:

| 만든 것 | 실제 | |
| --- | --- | --- |
| `tour-proxy` Edge Function | 번들에 `tour-proxy` 문자열 **없음**. 브라우저가 공공데이터포털을 직접 호출 | ❌ |
| `VITE_TOUR_PROXY_URL` | 타입 선언만 있고 **미사용** | ❌ |
| `naver-auth` Edge Function | **404 — 배포조차 안 됨** | ❌ |

> **교훈**: *"코드에 있다 ≠ 쓰인다 ≠ 배포됐다."*
> 세 가지는 각각 따로 확인해야 한다.

```bash
# ① 코드에 있나        → grep
# ② 실제로 불리나      → 배포 번들 검색 / 브라우저 네트워크 탭
# ③ 서버에 배포됐나    → curl 로 직접 호출 (404 인지 401 인지)
```

## 10-3. 외부 API 를 부르는 규칙

### (1) 저장해도 되는지 먼저 정한다

성지웹의 제약: **TourAPI 응답을 저장하지 않는다.** DB·서비스워커 캐시 금지. 매 요청 실시간 호출 `[ADR 0002]`.
반면 `holy_sites` 는 자체 데이터라 자유. **이 구분을 흐리지 않는다.**

> 라디오작가에도 같은 축이 있다 — 저작권 있는 외부 자료 vs 우리가 쓴 원고.

### (2) 타임아웃을 반드시 건다

> **성지웹 문제**: *"TourAPI 클라이언트: **타임아웃 없음**, HTTP 429/5xx/네트워크 미구분"* `[2026-09-14-전면-재기획.md §1-2]`.
> 외부가 느리면 우리 화면이 같이 멈춘다.

```ts
const res = await fetch(url, { signal: AbortSignal.timeout(5000) })
```

### (3) 실패 종류를 구분한다

| 상황 | 화면 | |
| --- | --- | --- |
| 데이터 없음 (정상 응답, 0건) | "주변 정보가 없어요" | 조용히 |
| 429 (너무 많이 부름) | 잠시 후 재시도 | |
| 5xx / 타임아웃 | "불러오지 못했어요" | 없음과 **구분** |

### (4) 없을 때가 얼마나 흔한지 센다

> **성지웹 실측**: 집중률 등재 **32/206곳**. 시골 성지는 주변 볼거리가 1건뿐이고 식당은 0건이다
> `[이어서-할-일.md 9/21 실측]`.
>
> **즉 이 기능은 대부분의 경우 아무것도 못 보여준다.** 만들기 전에 셌어야 했다. → [7장 7-2](07-2단계-데이터.md)

### (5) 프록시에 제한을 건다

성지웹의 `tour-proxy` 는 초기에 *"URL 화이트리스트만 있고 오퍼레이션·파라미터 제한·타임아웃·레이트리밋 없음"* 이었다 `[§1-2]`.
프록시를 열어두면 **남이 우리 키로 API 를 쓴다.**

| 걸어야 할 것 | |
| --- | --- |
| 허용 URL 목록 | ✅ |
| 허용 오퍼레이션·파라미터 | 필요 |
| 타임아웃 | 필요 |
| 호출 횟수 제한 | 필요 |
| 허용 출처(Origin) | 필요 |

## 10-4. AI 를 붙일 때 — 성지웹이 실제로 한 것

> **원칙**: *"AI 답변은 성지 DB 안으로 제한한다. 종교 성지의 역사·전례 정보는 틀리면 신뢰가 바로 무너진다"* `[CLAUDE.md]`.

### (1) 질문과 관련된 자료를 찾아 **컨텍스트로 넣는다** (간이 RAG)

```
사용자 질문
  → 질문과 관련된 성지 레코드를 DB 에서 뽑는다
  → 그 레코드를 프롬프트에 [성지 정보] 로 붙인다
  → AI 는 그 안에서만 답한다
```

`[supabase/functions/ai-guide/index.ts:341 "질문과 관련된 성지 레코드를 뽑아 프롬프트 컨텍스트로 만든다(간이 RAG)"]`

### (2) "모르면 모른다"를 시스템 프롬프트에 못 박는다

실제 문장 `[ai-guide/index.ts:97-98]`:

```
- 아래 [성지 정보] 컨텍스트에 있는 사실만 근거로 답하세요.
- 컨텍스트에 없는 내용은 절대 지어내지 말고,
  "부끄럽지만 저 미카엘 천사도 잘 모르는 부분이에요.
   공식 홈페이지나 성지 사무실을 통해 당일 확인을 부탁드려요." 라고 안내하세요.
```

> **모른다고 말하는 문장을 미리 써 준다.** "지어내지 마"만 쓰면 AI 는 얼버무린다.

### (3) 컨텍스트가 제대로 들어갔는지 **실측한다**

> 성지웹은 *"물어본 성지 대신 아무 5곳이 컨텍스트에 들어갔다 (2026-09-17 실측: **10문 중 6문 "모른다"**)"*
> 를 코드 주석에 남겼다 `[index.ts:414]`.
>
> **AI 가 "모른다"를 자주 하면 프롬프트 문제가 아니라 컨텍스트 선택 문제다.**
> 10문을 던져 몇 문에 답하는지 세는 게 유일한 확인법이다.

### (4) 모델 이름을 코드·시크릿에 고정하지 않는다

모델은 자주 바뀌고 사라진다. 성지웹은 **CI 가 매일 모델 목록을 갱신**하게 만들었다
`[2c52849 "Gemini 모델 목록을 CI 가 매일 갱신 — 시크릿 고정 대신 models.json + ListModels 자가 복구"]`.

### (5) 한 모델이 죽으면 다른 모델로 넘어가게 한다

> *"Gemini 가 끝내 못 답하면 Claude 로 넘어간다. **같은 시스템 프롬프트·같은 컨텍스트·같은 대화 이력을
> 그대로 보내므로** '컨텍스트 밖은 모른다' 규칙은 그대로 지켜진다"* `[ai-guide/index.ts:20-21]`.
>
> **대체 경로에도 같은 제약을 걸어야 한다.** 안 그러면 우회로로 규칙이 샌다.

### (6) 입력 길이를 제한한다

`[index.ts:61 "질문 길이 상한"]` — 비용과 프롬프트 주입을 같이 막는다.

## 10-5. 소셜 로그인 — 일정에 여유를 둔다

> **3장 사건 8과 겹치는 실패**: 네이버 로그인이 제출 당일까지 안 됐다.

원인은 코드가 아니었다 `[이어서-할-일.md 9/21 11:10 실측]`:
- 리디렉션·state 쿠키·네이버 로그인 화면까지 **전부 정상**
- 실패 원인: **네이버 개발자센터의 「서비스 URL」이 옛 주소**(vercel.app)
- 앱 상태가 「개발 중」이면 **테스터로 등록된 아이디만** 로그인된다
- 검수는 **며칠 걸린다**

| 확인할 것 | |
| --- | --- |
| 서비스 URL 이 **현재 도메인**인가 | 도메인을 바꿨으면 여기도 바꾼다 |
| Callback URL 이 맞나 | Edge Function 주소 |
| 앱 상태가 「개발 중」인가 | 그러면 테스터 등록 필요 |
| 검수 신청했나 | **며칠 걸림** |

> **도메인을 바꾸면 소셜 로그인·지도·메일 설정을 전부 다시 확인한다.**
> 한 곳만 옛 주소로 남아도 그 기능만 조용히 죽는다.

## 10-6. 외부가 죽어도 앱은 살아 있게

| 외부 | 죽으면 | 설계 |
| --- | --- | --- |
| TourAPI | 성지 상세 하단만 빔 | 나머지 화면은 정상 |
| AI | AI 답변만 안 됨 | 다른 화면 영향 없음 |
| 소셜 로그인 | 그 버튼만 실패 | 이메일 로그인은 됨. **실패하면 안내 띠** `[9/20 배포]` |
| 지도 | 지도만 안 나옴 | 목록으로 볼 수 있음 |
| **Supabase** | **앱 전체가 안 뜸** | 유일한 단일 장애점 |

> **외부 하나가 앱 전체를 죽이면 설계가 잘못된 것이다.**
> 성지웹에서 앱 전체를 죽이는 건 Supabase 뿐이다. 나머지는 부분 실패로 격리돼 있다.

## 10-7. 5단계 완료 체크리스트

- [ ] `VITE_` 가 붙은 값에 **비밀이 없다**
- [ ] `import.meta.env` **객체 자체를 읽는 코드가 없다**
- [ ] 비밀 키는 **Edge Function 시크릿**에 있다
- [ ] **배포 번들을 검색해** 비밀 문자열이 없음을 확인했다
- [ ] 만든 프록시·함수가 **실제로 불리고 배포됐는지** 셋 다 확인했다
- [ ] 외부 호출에 **타임아웃**이 있다
- [ ] **없음 / 실패**를 구분해 화면에 표시한다
- [ ] 데이터가 **없는 경우가 얼마나 흔한지 세어봤다**
- [ ] AI 에 **컨텍스트 제한**과 "모르면 모른다" 문장을 넣었다
- [ ] AI 컨텍스트가 맞게 들어가는지 **10문 실측**했다
- [ ] 모델 이름을 고정하지 않았다 / 대체 경로에도 같은 제약을 걸었다
- [ ] 소셜 로그인 **서비스 URL·Callback·앱 상태**를 확인했다
- [ ] 외부 하나가 죽어도 **앱 전체가 죽지 않는다**
