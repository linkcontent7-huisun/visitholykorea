# 3장. 결정적 사건 8개와 그때 배운 것

## 사건 1. 로컬 폴더를 날려먹었다 (2026-07-31)

**사실.** 커밋 메시지에 그대로 남아 있다 — `"Restore full project after local folder loss; rebuild from Claude Code file-history and reconstruct AIGuide/MapTab"` `[git log, 첫 3개 커밋 중 하나]`.
1월에 올린 뒤 6개월 공백이 있었고 `[월별 집계: 2~6월 커밋 0개]`, 그 사이 로컬 폴더가 사라졌다.

**원인.** 작업물이 **내 컴퓨터에만** 있었다. GitHub 에 밀어두지 않았다.

**대가.** AIGuide·MapTab 을 Claude Code 파일 이력에서 되살려야 했다. 복구는 됐지만 그 시간은 온전히 손해다.

**무엇이 바뀌었나.** `ADR 0005 — 코드는 GitHub 저장소가 기준` 이 생겼다. OneDrive 안의 앱 소스 사본과 zip 은 구버전이니 쓰지 말라는 규칙이 `CLAUDE.md` 에 못 박혔다.

> **다음에 할 일** → 첫날 30분 안에 GitHub 저장소를 만들고, 그날부터 매일 푸시한다. → [5장 0단계 준비](05-0단계-준비.md)

## 사건 2. 구조를 늦게 정해서 한 번에 갈아엎었다 (2026-08-04)

**사실.** 커밋 `5879fe4` 하나가 `App.tsx`·`components/tabs/`·`services/`·`contexts/` 등 **구 파일 19개를 지우고** 41개를 새 구조로 옮겼다 `[git log --diff-filter=D]`. 커밋 메시지: *"기능은 그대로 두고 구조만 바꿨다."*

바뀐 내용 네 가지 `[5879fe4 커밋 본문]`:
- `src/{app,pages,features,shared}` 로 재편, 의존 방향을 `pages → features → shared` 한쪽으로 고정
- 탭 state 라우팅 → React Router (화면마다 주소가 생겨 링크 공유·딥링크 가능)
- 화면마다 흩어진 `useEffect` 데이터 요청 → TanStack Query + repository 계층
- DB 행(snake_case) ↔ 도메인 타입(camelCase) 변환을 repository 한 곳으로

**원인.** 처음에 "일단 화면부터" 만들었다. 구조 규칙이 없으니 화면마다 제 방식으로 데이터를 불렀다.

**대가.** 기능이 하나도 안 늘어난 커밋 하나에 41개 파일 이관. 이관 누락을 막으려고 점검표 문서까지 따로 써야 했다 `[docs/00-overview/이관-점검표.md]`.

**무엇이 바뀌었나.** 이 네 규칙이 `CLAUDE.md` 의 「코드 구조 규칙」이 되어 이후 7주를 버텼다.

> **다음에 할 일** → 폴더 구조와 의존 방향을 **첫 화면을 만들기 전에** 정한다. → [8장 3단계 뼈대](08-3단계-뼈대.md)

## 사건 3. 비밀 키가 한 달 동안 브라우저에 노출돼 있었다 (~2026-09-14 발견)

**사실.** 9/14 재기획 점검에서 배포 번들을 직접 열어보니 **TourAPI 인증키가 실제 값 그대로 들어 있었다** `[docs/10-product/재기획/2026-09-14-전면-재기획.md §1-1]`.
원인은 `src/shared/config/env.ts:16` 이 `import.meta.env` **객체 자체**를 읽은 것. Vite 가 env 전체를 번들에 인라인해버려서 `VITE_VERCEL_BRANCH_URL` 같은 시스템 변수까지 같이 노출됐다.

같은 점검에서 또 나온 것:
- 브라우저가 공공데이터포털을 **직접** 부르고 있었다 (프록시를 만들어 뒀는데 안 쓰고 있었음 — `VITE_TOUR_PROXY_URL` 은 타입 선언만 있고 미사용)
- `naver-auth` Edge Function 은 **배포조차 안 돼 있었다** (404)

**원인.** 만든 것과 실제로 쓰이는 것을 **아무도 대조하지 않았다.** 코드에 프록시가 있으니 프록시를 쓰는 줄 알았다.

**대가.** 한 달간 키 노출. 공모전 심사 전에 발견한 게 다행이다.

**무엇이 바뀌었나.** `CLAUDE.md` 에 「비밀 키를 클라이언트에 두지 않는다 — `VITE_` 접두사가 붙은 값은 브라우저 번들에 그대로 들어간다」가 명시됐다. AI 키는 Edge Function 시크릿으로 옮겼다.

> **다음에 할 일** → 배포할 때마다 **번들을 열어 비밀 문자열을 검색**하는 절차를 넣는다. → [11장 6단계 검증·배포](11-6단계-검증배포.md)

## 사건 4. 만든 기능이 한 달 동안 한 번도 작동하지 않았다 (2026-09-16 발견)

**사실.** 커밋 `615642e` 본문 — *"집중률 호출에 `signguCd` 가 없어 **한 번도 데이터를 받은 적이 없었다**"*.
게다가 응답에서 "최신 날짜"를 `max` 로 고르던 버그로 **30일 뒤 예측을 오늘 값으로** 쓰고 있었다.
그런데 화면에는 "실측 집중률 N%" 라고 **확정된 사실처럼** 표시하고 있었다 `[2026-09-14-전면-재기획.md §1-2]`.

더 나쁜 것: 붐빔 점수 계산에서 **인프라 조회에 실패한 성지가 낮은 점수를 받아** 정렬에 그대로 참여했다. 즉 **데이터를 못 받을수록 "조용한 성지" 1위**가 됐다 `[quiet-sites.ts:179 인용]`.

**원인.** 화면에 그럴듯한 숫자가 나오니 작동한다고 믿었다. **값이 어디서 왔는지 한 번도 확인 안 했다.**

**대가.** 기능 하나를 통째로 다시 설계 (사건 5로 이어짐).

**무엇이 바뀌었나.** 재설계 후 규칙: **집중률 없는 시군구는 등급을 내지 않는다** (축제 0건 ≠ 조용). 값이 없으면 안 그린다. 숫자를 표시하지 않고 "조용/보통/붐빔" 문장 하나만.

> **다음에 할 일** → 외부 데이터를 쓰는 기능은 **"데이터를 못 받았을 때 화면이 어떻게 되는가"를 먼저** 정한다. 빈 값이 0점이 되면 안 된다. → [10장 5단계 외부 연동](10-5단계-외부연동.md)

## 사건 5. 전면 재기획 — 전체 커밋의 58%가 그 이후에 나왔다 (2026-09-14)

**사실.** 9/14 「전면 재기획」 이후 커밋이 **457개**, 전체 787개의 **58%** `[git log --since=2026-09-14]`.
재기획 문서는 현재 상태 점검 → 새 기획서 → **유지·제거·통합 기능 목록** → 새 정보구조 → 화면별 요구사항 → 데이터·API 구조 → DB 권한 → 구현 계획 순으로 썼다 `[2026-09-14-전면-재기획.md 목차]`.

점검에서 드러난 구조 문제 하나: *"「고요 속으로」는 독립 화면이 아니라 홈 섹션이고 「더보기」가 `/alternatives`(붐빔 피하기)로 간다 → **같은 기능이 두 이름**"*.

**원인.** 8월에 기능을 **넓게** 만들었다. 무엇이 핵심인지 정하지 않은 채 아이디어를 하나씩 화면으로 만들었다. 그 결과 같은 일을 하는 화면이 둘, 이름이 둘이 됐다.

**대가.** 두 달 작업의 절반 이상을 다시 만들었다. **다만 이건 순수한 손해가 아니다** — 재기획 없이 제출했다면 심사에서 "무슨 서비스인지 모르겠다"는 평을 받았을 것이다.

**무엇이 바뀌었나.** 정보 구조가 하단 탭 5개로 정리됐고, AI·나침반 같은 "입구가 여럿"이던 기능이 하나로 모였다.

> **다음에 할 일** → 재기획을 두 달 뒤에 하지 말고 **첫 주에 한다.** 기획 단계에서 "이 서비스는 한 문장으로 무엇인가"와 "하단 탭 5개는 무엇인가"를 먼저 정한다. → [6장 1단계 기획](06-1단계-기획.md)

## 사건 6. 다국어 사전 한 파일을 104번 고쳤다

**사실.** `src/shared/i18n/dictionary.ts` 수정 **104회** — 8월 10회, **9월 98회** `[git log 집계]`.
다국어 구조는 8/4부터 있었다 `[src/shared/i18n 첫 커밋]`. 없어서 고친 게 아니다.

**원인.** **화면을 먼저 만들고 문구를 나중에 사전으로 옮기는 일을 98번 반복**했다.
9/14 재기획 때 언어를 ko·en 2개로 줄였다가 `[ffbc836]`, 나중에 다시 6개로 늘렸다 `[T-031]`. 그때마다 사전을 다시 만졌다.

**대가.** 한 파일에 104번. 병합 충돌과 미번역 누락이 반복됐다. 결국 **미번역을 잡는 검사기를 따로 만들어야** 했다 `[2d9d68e: "미번역 잡는 검사 4개"]`.

**무엇이 바뀌었나.** 번역 작업 지침 문서가 생기고 `[84428ed]`, `npm run translate:check` 로 CI 에서 미번역을 막게 됐다.

> **다음에 할 일** → 다국어를 쓸 거면 **첫 화면부터 문구를 사전에 넣는다.** "일단 한국어로 만들고 나중에 번역"은 그 나중이 98번이다. → [9장 4단계 화면](09-4단계-화면.md)

## 사건 7. 두 세션이 같은 일을 각각 했다 (2026-09-21)

**사실.** 로컬 창 두 개가 같은 작업(T-031)을 동시에 진행했다 `[이어서-할-일.md 기록]`.
AI 세션끼리는 서로의 대화를 모른다. 연락 수단은 GitHub 저장소뿐이다 `[CLAUDE.md]`.

같은 날 또 하나: Codex 에게 맡긴 번역 작업이 인터넷 끊김으로 **4시간 돌다 결과 0** 으로 취소됐다 `[이어서-할-일.md]`.

**원인.** 작업 시작을 **어디에도 알리지 않았다.** 그리고 오래 걸리는 위임 작업의 **중간 확인이 없었다.**

**대가.** 같은 일 두 번 + 4시간 공전.

**무엇이 바뀌었나.** 규칙: **작업 시작 전에 `이어서-할-일.md` 맨 위에 "지금 ○○ 하는 중(브랜치)" 한 줄을 푸시**한다.

> **다음에 할 일** → 창을 여러 개 쓸 거면 **작업 현황판 파일 한 개**를 만들고, 시작할 때 쓰고 끝낼 때 지운다. → [5장 0단계 준비](05-0단계-준비.md)

## 사건 8. 마감 사흘 전에 배포가 막혔다 (2026-09-21)

**사실.** Vercel 무료 플랜의 **배포 생성 100회 / 24시간** 한도를 초과. 실측 114건 `[이어서-할-일.md 11:30]`.
제출 당일 오전, 코드 수정이 필요해도 배포할 수 없는 상태가 됐다.

문서만 바뀐 커밋도 전부 빌드·배포를 유발한 게 원인. 9월 하루 평균 27커밋이면 금방 찬다.

**원인.** **문서 커밋과 코드 커밋을 구분하지 않았다.**

**대가.** 제출 전 화면 수정 포기. 네이버 로그인 버튼을 숨기는 한 줄짜리 수정도 못 했다.

**무엇이 바뀌었나.** 재발 방지 후보로 `vercel.json` 의 `ignoreCommand` (docs·data 만 바뀐 커밋은 빌드 건너뛰기)가 기록됐다. **아직 적용 안 함** `[확인 필요 — 2026-09-23 현재 미적용]`.

> **다음에 할 일** → 프로젝트 시작 때 **무료 플랜 한도를 먼저 읽고**, 문서 커밋이 배포를 안 부르게 설정한다. → [11장 6단계 검증·배포](11-6단계-검증배포.md)
