# 12장. 7단계 운영·유지보수 — 1차 완료 이후

> 1차 개발이 끝나면 일의 성격이 바뀐다. **만드는 일**에서 **안 썩게 하는 일**로.
> 이 장은 성지웹을 유지보수하는 법이자, 라디오작가를 만들 때 **미리 준비해 둘 것**의 목록이다.

---

## 12-1. 유지보수는 여섯 종류밖에 없다

| 종류 | 무엇 | 성지웹 사례 | 주기 |
| --- | --- | --- | --- |
| **① 콘텐츠 갱신** | 우리 데이터가 늘거나 바뀜 | 성지 추가, 도슨트 원고, 사진 | 계속 |
| **② 번역·검수** | AI 초안을 사람이 확인 | es·fr·pt·it 206곳 기계 번역 상태 | 계속 |
| **③ 외부 변경** | 남의 API·정책이 바뀜 | TourAPI 키 만료, 모델 폐기, 도메인 변경 | 불시 |
| **④ 의존성·보안** | 패키지 업데이트, 권한 점검 | Supabase 린트, RLS 검토 | 월 1회 |
| **⑤ 사용자 발견 버그** | 실제로 써보니 안 됨 | 사진 확대 동작, 통계 불일치 | 불시 |
| **⑥ 미결 항목** | 1차에서 못 끝낸 것 | 아래 12-4 | 계획적 |

> **①②는 코드가 아니라 사람 시간**이다. 라디오작가는 ②가 서비스의 본체다 — 미리 도구를 만들어 둬야 한다.

## 12-2. 운영 도구를 미리 만들어 둔다

성지웹은 운영 스크립트 **42개**를 만들었다 `[ls scripts, 2026-09-23]`. 이게 유지보수를 가능하게 한다.

| 목적 | 명령 | 하는 일 |
| --- | --- | --- |
| **현황 파악** | `npm run content` | 성지별 좌표·소개글 상태, 교구별 진행률 |
| | `npm run translate:status` | 언어별 번역 진행률, 감수 완료 수 |
| | `npm run docent:status` | 원고·지점 수 |
| **품질 검사** | `npm run translate:check` | 미번역 문구 검출 |
| | `npm run docent:check` | 원고 형식 오류 |
| | `npm run db:check-security` | DB 권한 구멍 |
| **작업** | `npm run translate:export/import` | 번역을 파일로 빼고 넣기 |
| | `npm run photo:pending/feature` | 사진 승인·대표 지정 |
| | `npm run admin:grant/revoke` | 관리자 권한 |
| **점검** | `npm run tourapi:check` | 외부 API 살아 있나 |
| | `npm run db:status` | 마이그레이션 적용 상태 |

> **원칙**: *숫자를 손으로 세지 않는다.* 세어야 할 것이 생기면 **명령을 만든다.**
> 이 백서의 모든 숫자가 명령 한 줄로 다시 확인되는 이유다.

### 라디오작가에 필요할 명령 (미리 계획)

| 명령 | 하는 일 |
| --- | --- |
| `npm run draft:status` | 회차별 초안·검수·제출 상태 집계 |
| `npm run draft:check` | 원고 형식·금칙어·분량 검사 |
| `npm run draft:export/import` | 작가가 워드로 받아 고치고 되넣기 |

## 12-5. 세션·창 사이의 인수인계

> **3장 사건 7**: 창 두 개가 같은 작업을 각각 했다.

AI 세션끼리는 서로의 대화를 모른다. **연락 수단은 저장소뿐이다.**

| 언제 | 무엇 |
| --- | --- |
| 창을 **열자마자** | `git pull` |
| 작업을 **시작할 때** | `이어서-할-일.md` 맨 위에 `🔨 지금 ○○ 하는 중(브랜치, 시각)` → **푸시** |
| 작업이 **끝나면** | 그 줄을 `✅ 끝남` 으로 바꾸고 결과 한 문단 → **푸시** |
| 창을 **옮기기 전에** | 푸시 |
| **커밋할 때** | `git commit -- <경로>` (다른 창 작업이 섞이지 않게) |

### 웹 세션과 로컬 세션은 할 수 있는 일이 다르다

| | 웹 세션 (claude.ai/code) | 로컬 세션 (CLI·앱) |
| --- | --- | --- |
| 저장소 코드·문서 | ✅ | ✅ |
| `npm run verify` | ✅ (`npm ci` 먼저) | ✅ |
| **DB 조회** | ❌ (`.env.local` 을 못 봄) | ✅ |
| 배포 확인 | ❌ (supabase·vercel 차단) | ✅ |
| 로컬 자료(OneDrive) | ❌ | ✅ |

`[CLAUDE.md, 2026-08-19 실측]`

> **DB·배포·실제 데이터가 필요한 일은 로컬 세션에서만 된다.** 웹 세션에 시키면 추측으로 답한다.

## 12-6. 문서를 안 썩게 하는 법

218개 문서 중 상당수가 이미 낡았다. 규칙 세 개면 막을 수 있다.

### ① 숫자에는 **언제 잰 값인지** 붙인다

```markdown
성지 206곳 [npm run content, 2026-09-23]
```

> 성지웹은 이걸 안 해서 문서마다 195곳/206곳이 섞였다 `[CLAUDE.md 에 경고로 남음]`.

### ② 확인 못 한 것은 **"확인 못 했다"** 고 적는다

추측을 사실처럼 쓰지 않는다. 기획서에도 「미확인 사항」 칸을 둔다 (6장 6-4).

### ③ 상태 문서는 **그 자리에서** 고친다

작업이 끝난 그 순간에 `이어서-할-일.md` 를 고친다. 나중에 몰아서 하면 안 한다.

### 문서의 세 층

| 층 | 수명 | 예 |
| --- | --- | --- |
| **현황** | 며칠 | `이어서-할-일.md` — 자주 바뀜 |
| **결정** | 영구 | ADR — 한 번 쓰면 안 고침. 뒤집히면 새 ADR |
| **설명** | 몇 달 | 구조·규칙 문서 — 바뀌면 고침 |

**이 백서는 「결정」 층이다.** 사건과 교훈은 안 바뀐다. 12-4 의 미결 목록만 날짜와 함께 낡는다.
