# 2장. git 이 말하는 사건표

> **이 장에는 내 의견이 한 줄도 없다.** 전부 git 에서 뽑은 측정값이다.
> 해석은 3장에서 한다. 여기서는 "무슨 일이 언제 있었나"만 본다.
>
> 뽑은 방법도 적어둔다. 다음 프로젝트에서 똑같이 돌려보면 된다.

## 2-1. 뽑는 방법 (다음 프로젝트에서 그대로 쓸 것)

```bash
# ① 가장 많이 갈아엎은 파일 — 재작업이 몰린 곳
git log --format= --name-only -- src | grep -v '^$' | sort | uniq -c | sort -rn | head -30

# ② 만들었다 지운 파일 — 낭비 후보
git log --diff-filter=D --format="%ad|%h" --date=short --name-only -- src

# ③ 되돌림·복구·사고 커밋
git log --format="%ad %h %s" --date=short --grep='revert\|되돌\|복구\|롤백\|실수\|사고' -i

# ④ 월별 커밋 밀도 — 언제 몰아쳤나
git log --format=%ad --date=format:%Y-%m | sort | uniq -c

# ⑤ 기능이 처음 등장한 날
git log --reverse --format="%ad" --date=short -- src/features/<이름> | head -1
```

> **교훈 하나**: 이 명령들은 **프로젝트가 끝난 뒤가 아니라 매주 돌려야** 한다.
> ①에서 어떤 파일이 튀어 오르면, 그 파일은 지금 잘못 설계돼 있다는 뜻이다.
