# 백서 — 웹 하나를 만드는 순서

> 이 문서 묶음은 **성지순례 웹(VisitHolyKorea)을 만든 기록**이면서,
> 동시에 **다음 웹을 만들 때 그대로 따라 하는 교과서**다.
>
> 쓴 이유: 첫 번째 웹을 만들며 겪은 헛수고를 두 번째 웹(대전가톨릭평화방송 라디오작가 에이전트)에서 반복하지 않기 위해.
> 작성 2026-09-23. 모든 숫자에 **언제 어디서 잰 값인지**를 대괄호로 붙였다. 확인 못 한 것은 `[확인 못 함]` 이라고 적었다.

## 누가 읽는가

비개발자인 제작자 본인과, 다음 프로젝트를 돕는 AI 세션.
AI 세션은 이전 대화를 기억하지 못하므로, **"왜 이렇게 했나"를 아는 유일한 통로가 이 문서**다.

## 어떻게 읽는가

| 급할 때 | 읽을 곳 |
| --- | --- |
| 지금 당장 새 프로젝트를 시작한다 | **5장(0단계 준비)** → **6장(1단계 기획)** 두 장만 |
| 무엇을 안 만들어도 되는지 알고 싶다 | **4장(낭비 목록)** |
| 같은 사고를 피하고 싶다 | **3장(결정적 사건 8개)** |
| 라디오작가를 바로 시작한다 | **13장** → 거기서 5~12장으로 돌아옴 |
| 성지웹을 유지보수한다 | **1장(현재 상태)** → **12장(운영)** |

## 이 백서를 검사하는 법

모든 사실 문장 끝에 근거가 붙어 있다. 예: `성지 206곳 [npm run content, 2026-09-23]`.

**근거 태그가 없는 문장은 내 의견이거나 추측이다.** 그것만 찾아 읽으면 검사가 끝난다.
아무 근거 태그나 3개 찍어 "이거 어디서 나온 숫자냐"고 물으면, 그 자리에서 같은 명령을 돌려 보일 수 있다.
