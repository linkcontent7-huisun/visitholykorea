# 6장. 1단계 기획 — 만들기 전에 정하는 7가지

> **이 장이 전체에서 가장 중요하다.**
> 3장 사건 5: 두 달 만든 뒤 전면 재기획을 했고, **전체 커밋의 58%가 그 이후에 나왔다.**
> 그 재기획을 **첫 주에** 했다면 457커밋이 아니라 100커밋으로 끝났을 것이다.
>
> 걸리는 시간: **2~4일.** 코드는 여전히 한 줄도 안 쓴다.

---

## 6-1. 왜 기획을 먼저 해야 하는가 — 숫자로

성지웹에서 **기획을 안 하고 만들어서 생긴 비용**:

| 낭비 | 크기 | 근거 |
| --- | --- | --- |
| 전면 재기획 이후 재작업 | 457커밋 (전체의 58%) | `git log --since=2026-09-14` |
| 만들었다 지운 기능 | 10개, 파일 25개 | 4장 |
| 같은 기능 두 이름 | 「고요 속으로」 / 「붐빔 피하기」 | `2026-09-14-전면-재기획.md` |
| 사전 파일 재작업 | 104회 | `git log --name-only` |

**기획 2~4일 vs 재작업 457커밋.** 계산이 필요 없다.

## 6-2. AI 와 기획하는 대화법

기획은 혼자 쓰는 게 아니라 **AI 와 문답으로 만든다.** 방법은 세 가지다.

### 방법 A — AI 에게 질문을 시킨다 (권장)

```
이번에 ○○ 를 만들려고 해. 바로 만들지 말고,
내 의도를 파악하기 위해 필요한 질문을 3개씩 물어봐.
내가 답하면 다음 3개를 물어. 충분해지면 기획서를 써줘.
```

> **왜 이게 좋은가**: 내가 미처 생각 못 한 구멍을 AI 가 질문으로 드러낸다.
> 이 백서 자체도 이 방식으로 만들어졌다.

### 방법 B — 선택지를 표로 받는다

```
이건 A로 할지 B로 할지 모르겠어. 선택지를 표로 정리하고
권장안을 먼저 놓고, 각각 나중에 무엇이 어려워지는지 알려줘.
```

### 방법 C — 나를 몰아붙이게 한다

```
내 기획을 믿지 말고 반박해줘. 이게 실패한다면 어디서 실패할까?
```

### 이 단계에서 AI 에게 **시키면 안 되는 것**

**코드를 쓰게 하면 안 된다.** 코드가 나오는 순간 그 코드에 끌려간다.
기획 단계의 산출물은 **문서뿐**이다.

## 6-3. 정해야 하는 7가지

### ① 한 문장 정의 — "누구를 위해 무엇을 하는 물건인가"

주어·대상·행동이 다 들어간 한 문장.

> 성지웹: *"한국 가톨릭 성지 206곳을 6개 언어로 안내하고, 순례 일정을 짜주고, 방문 기록을 남기는 웹앱."*

**이 문장이 안 써지면 아직 기획이 안 된 것이다.**
성지웹은 9/14 점검에서 *"`<title>` 과 description 이 새 정의와 다르다"* 는 지적을 받았다 `[2026-09-14-전면-재기획.md §1-1]`.
즉 **두 달 동안 한 문장이 정해지지 않은 채** 만들고 있었다.

### ② 사용자 — 한 명을 구체적으로

"모두"는 사용자가 아니다. 성지웹은 두 종류를 정했다:
- **50대 이상 한국인 순례자** (수요조사 n=23 기준 85%) → 큰 글자·단순한 동선
- **WYD 해외 방문객** → 다국어·로마자 주소

> 이 정의가 **접근성 규칙**(고정 px 금지, rem 기반)과 **6개 언어**를 낳았다 `[CLAUDE.md]`.

### ③ 핵심 동작 한 개 — "이게 안 되면 서비스가 아니다"

기능 목록을 쓰기 전에 **하나만** 고른다.
성지웹: *성지를 찾아 상세를 보는 것.* 나머지(일정·기록·AI)는 다 부가다.

> **핵심 하나를 안 정하면** 8월처럼 기능이 넓게 퍼지고, 9월에 재기획으로 잘라내게 된다.

### ④ 하단 탭 5개 — 정보 구조

앱의 뼈대는 **하단 탭 5개**다. 이걸 먼저 정하면 "이 화면은 어디 아래 붙나"가 자동으로 풀린다.

> 성지웹 9/14 확정: **홈 · 성지 찾기 · 고요 속으로 · 내 기록 · 더보기** `[ffbc836]`
> 그 전에는 탭이 **홈·지도·기록·홈화면추가·전체** 였고 "홈화면추가"가 탭을 차지하고 있었다.

**규칙**: 탭은 5개를 넘지 않는다. 6번째가 필요하면 무언가가 탭이 아니다.

### ⑤ 화면 목록 — 전체를 한 장에

**모든 화면을 한 표에 적는다.** 여기서 중복이 드러난다.

| 화면 | 주소 | 어느 탭 아래 | 무엇을 보여주나 | 어떤 데이터가 필요한가 |
| --- | --- | --- | --- | --- |
| 홈 | `/` | 홈 | 오늘 볼 것 | 성지 목록 |
| 성지 상세 | `/sites/:id` | 성지 찾기 | 한 곳의 모든 것 | 성지 1건 + 사진 + 도슨트 |
| … | | | | |

> **4장 유형 2(같은 일에 이름 둘)를 막는 것이 이 표다.**
> 「고요 속으로」와 「붐빔 피하기」를 이 표에 나란히 적었으면 그날 알아챘을 것이다.

### ⑥ 안 만들 것 — 범위 밖 목록

**만들 것보다 안 만들 것을 적는 게 더 중요하다.**

```markdown
## 이번에 안 만드는 것
- 결제
- 알림(푸시)
- 사용자끼리 소통(댓글·팔로우)
- 통계 대시보드   ← 여행 프로필이 여기서 걸렸어야 했다
```

> **4장 유형 1(소비자 없는 생산)**: 여행 프로필은 "통계를 나중에 보여주려고" 만든 수집 기능이었다.
> **통계 화면이 범위 밖이었다면** 수집도 안 만들었을 것이다.

### ⑦ 완료 조건 — "무엇이 되면 1차 완성인가"

측정 가능하게 쓴다. "잘 작동한다"는 완료 조건이 아니다.

```markdown
## 1차 완성 조건
- [ ] 원고 206건이 DB에 들어 있다        ← 숫자
- [ ] 초안 생성 → 검수 → 제출이 한 번에 된다  ← 동선
- [ ] 검수자가 고친 내용이 저장된다        ← 동작
- [ ] `npm run verify` 통과              ← 기계 검증
- [ ] 배포 주소에서 위 4개가 다 된다        ← 실물 확인
```

## 6-4. 기획서 양식

성지웹의 전면 재기획 문서가 실제로 쓴 구조다 `[2026-09-14-전면-재기획.md 목차]`. 그대로 쓰면 된다.

```markdown
# ○○ 기획 (YYYY-MM-DD)

작성: (누가·어느 세션). 숫자는 모두 YYYY-MM-DD 실측값이다.
확인하지 못한 것은 "확인 못 함"으로 적었다.

## 1. 현재 상태 점검          ← 새 프로젝트면 "참고할 기존 서비스"
## 2. 서비스 정의             ← 위 ①②③
## 3. 유지·제거·통합 기능 목록  ← 위 ⑥
## 4. 정보 구조와 사용자 흐름   ← 위 ④
## 5. 화면별 요구사항          ← 위 ⑤
## 6. 데이터와 API 구조        ← 7장에서 채움
## 7. 권한 검토               ← 누가 무엇을 볼 수 있나
## 8. 구현 계획 (작업 단위)     ← 아래 6-5
## 9. 미확인 사항과 확인해야 할 것  ← 중요
```

> **9번 「미확인 사항」을 반드시 둔다.** 추측을 사실처럼 쓰지 않기 위한 칸이다.
> 성지웹 기획서는 첫 줄에 *"확인하지 못한 것은 '확인 못 함'으로 적었다"* 를 선언했다.

## 6-5. 작업 순서를 정한다 — 무엇부터 만드나

기획서 8번에 들어가는 내용이다. **순서에는 이유가 있다.**

| 순서 | 무엇 | 왜 이 순서인가 |
| --- | --- | --- |
| 1 | **데이터 확보** | 화면은 데이터 모양을 따라간다. 반대는 안 된다 → [7장](07-2단계-데이터.md) |
| 2 | **뼈대·규칙** | 나중에 바꾸면 41개 파일 이관 → [8장](08-3단계-뼈대.md) |
| 3 | **핵심 동작 한 개** | ③에서 고른 그것. 끝까지 되게 만든다 |
| 4 | 나머지 화면 | 핵심이 돌아간 뒤에 → [9장](09-4단계-화면.md) |
| 5 | 외부 연동 | 없어도 앱이 돌아가게 → [10장](10-5단계-외부연동.md) |
| 6 | 다듬기·접근성 | |

> **성지웹이 실제로 한 순서**: 데이터·뼈대·핵심이 8/4 재구축 때 한꺼번에 왔고 `[5879fe4]`,
> 그 전 3개월은 순서 없이 만든 것을 버렸다.

## 6-6. 이 단계에서 AI 가 저지르는 실수 — 미리 알아둘 것

| AI 가 하는 일 | 왜 문제인가 | 막는 법 |
| --- | --- | --- |
| 묻지도 않았는데 코드를 쓰기 시작 | 코드가 나오면 기획이 코드에 끌려감 | *"지금은 문서만. 코드 쓰지 마"* 를 명시 |
| 그럴듯한 숫자를 지어냄 | 3장 사건 3·4의 원인 | *"확인 안 된 건 '확인 못 함'이라고 써"* |
| 기능을 자꾸 늘림 | 범위가 퍼짐 | ⑥ 「안 만들 것」을 먼저 쓰게 함 |
| 낡은 문서를 사실로 인용 | 성지웹 8/19 사고 | *"문서 말고 코드·DB를 직접 조회해서 확인해"* |

## 6-7. 1단계 완료 체크리스트

- [ ] 한 문장 정의를 썼다
- [ ] 사용자를 구체적으로 한두 종류 정했다
- [ ] **핵심 동작 한 개**를 골랐다
- [ ] 하단 탭 5개를 정했다
- [ ] **화면 전체 목록을 한 표**에 적었고 중복이 없다
- [ ] **안 만들 것 목록**을 적었다
- [ ] 완료 조건을 측정 가능하게 적었다
- [ ] 기획서를 `docs/10-product/` 에 저장하고 **커밋·푸시**했다
- [ ] 「미확인 사항」 칸에 모르는 것을 정직하게 적었다
