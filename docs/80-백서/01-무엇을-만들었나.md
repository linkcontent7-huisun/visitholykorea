# 1장. 성지웹은 무엇이고 무엇이 완성됐나

> 이 장의 목적은 자랑이 아니라 **규모 감각**이다.
> "이 정도 물건을 만드는 데 무엇이 얼마나 들었나"를 알아야 다음 프로젝트의 일정을 짤 수 있다.

## 1-1. 한 문장

한국 가톨릭 성지 206곳을 6개 언어로 안내하고, 순례 일정을 짜주고, 방문 기록을 남기는 웹앱.
웹·Android·iOS 를 **코드 한 벌**로 지원한다. 2026 한국관광공사 관광데이터 활용 공모전 제출작.

## 1-3. 무엇으로 만들었나

| 층 | 무엇 | 왜 이것인가 |
| --- | --- | --- |
| 화면 | React 19 + TypeScript + Vite | 웹 표준. 모바일 앱도 같은 코드로 감쌀 수 있음 |
| 스타일 | Tailwind CSS | 클래스 이름으로 디자인. 큰 글자 모드 대응이 쉬움 |
| 라우팅(주소) | React Router 7 | 화면마다 고유 주소 → 링크 공유·딥링크 가능 |
| 서버 데이터 | TanStack Query | 화면이 데이터를 "요청"만 하면 캐시·재시도·로딩을 알아서 |
| DB·인증·파일 | Supabase (PostgreSQL) | 서버를 직접 안 만들어도 DB·로그인·파일저장이 다 됨 |
| 비밀이 필요한 서버 일 | Supabase Edge Function | AI 키·소셜 로그인 비밀키를 브라우저에 안 두려고 |
| 앱 포장 | Capacitor 7 | 웹 코드를 Android/iOS 앱으로 감쌈 |
| 배포 | Vercel (main 푸시 = 즉시 배포) | 설정 없이 자동 배포 |
| AI | Google Gemini (`@google/genai`) | 성지 안내 챗봇 |

## 1-4. 외부에 무엇을 기대고 있나

여기가 **가장 잘 깨지는 곳**이다. 우리 코드가 멀쩡해도 여기가 바뀌면 화면이 죽는다.

| 외부 | 쓰는 곳 | 끊기면 생기는 일 |
| --- | --- | --- |
| 한국관광공사 TourAPI (6종) | 주변 볼거리·식당, 집중률 예측, 축제, 걷기길 | 성지 상세 하단·일정 결과가 빔 |
| Supabase | 전부 | 앱이 안 뜸 |
| Google Gemini | AI 성지 안내 | AI 답변만 안 됨 |
| 카카오 / 네이버 로그인 | 소셜 로그인 | 그 버튼만 실패 |
| 네이버 지도 | 지도 화면 | 지도만 안 나옴 |
| Vercel | 배포 | 새 배포 못 함 |
| Resend (SMTP) | 인증 메일 | 가입 메일 안 감 |

`[출처: .env.local 키 목록 + supabase/functions, 2026-09-23]`

> **TourAPI 는 응답을 저장하면 안 된다** (공모전 실격 위험). DB·서비스워커 캐시 금지.
> 반면 `holy_sites` 는 우리가 직접 모은 자체 데이터라 마음껏 저장·캐시해도 된다.
> 이 구분이 설계 전체에 영향을 준다 `[ADR 0002]`.

## 1-5. 완성됐다고 말할 수 있는 것 / 아닌 것

### 됐다

- 성지 206곳 조회·검색·지도·상세
- 6개 언어 화면 전환
- 오늘의 성지 일정(질문 6개 → 후보 3장 → 하루 일정)
- 오디오 도슨트 108곳
- 로그인, 순례 기록(스탬프·사진), 즐겨찾기
- AI 성지 안내 (DB 범위 제한)
- 관리자 콘솔(사진·글 수정)
- 테스트 450개 통과, 배포 운영 중 `[visitholykorea.com]`
