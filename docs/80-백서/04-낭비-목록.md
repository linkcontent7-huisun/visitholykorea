## 4-2. 낭비의 네 가지 유형

지워진 10개를 원인으로 묶으면 네 가지밖에 없다.

### 유형 1. 소비자 없는 생산 — "데이터는 모으는데 아무도 안 읽음"

**사례**: 여행 프로필(6번).
커밋 본문이 정확하다 — *"`profiles.country_code`/`companion_count`/`is_guided_tour` 를 읽는 화면·관리자 콘솔·스크립트가 앱 전체에 하나도 없었다. 공모전 통계 공백을 메우려던 수집 전용 기능이었고, **아직 어디에도 시각화되지 않은 채였다**"* `[db57075]`.

가입 직후 사용자에게 3문항을 물었고, 그 답은 14일 동안 아무도 안 봤다.

> **예방 질문**: *"이 데이터를 **누가 어느 화면에서** 보나?"*
> 답이 "나중에"면 **지금 만들지 않는다.**

### 유형 2. 같은 일에 이름 둘 — "정보 구조를 안 정하고 화면부터"

**사례**: 붐빔 피하기(2번) vs 고요 속으로.
9/14 점검 기록: *"「고요 속으로」는 독립 화면이 아니라 홈 섹션이고 「더보기」가 `/alternatives`(붐빔 피하기)로 간다 → **같은 기능이 두 이름**"* `[2026-09-14-전면-재기획.md §1-2]`.

같은 기능에 두 입구와 두 이름이 생기면, 고칠 때마다 두 곳을 고쳐야 한다.

> **예방 질문**: *"이 화면은 **하단 탭 어디** 아래에 붙나? 이미 비슷한 화면이 있나?"*
> 새 화면을 만들기 전에 **전체 화면 목록을 한 장에 그려놓고** 본다.

### 유형 3. 데이터를 확인 안 하고 만든 기능

**사례**: 조용한 성지(3번).
집중률 API 호출에 시군구 코드가 빠져 **한 달 넘게 한 번도 데이터를 받지 못했다** `[615642e]`. 그런데 화면에는 "실측 집중률 N%" 가 떴다. 실패한 성지가 낮은 점수를 받아 **못 받을수록 조용 1위**가 되는 구조였다 `[quiet-sites.ts:179]`.

> **예방 질문**: *"이 API 를 **실제로 한 번 호출해서 응답을 눈으로 봤나?**"*
> 화면을 만들기 전에 응답 한 건을 파일로 저장해 보관한다. → [7장 2단계 데이터](07-2단계-데이터.md)

### 유형 4. 확인 없이 바꾼 UI — 당일 만들고 당일 삭제

**사례**: 사진뷰어(10번). 9/21 오전 도입, 같은 날 삭제. *"장소 상세 페이지와 동작이 달라 혼란스러웠다"* `[cd6715c]`.

> **예방 질문**: *"같은 동작이 **다른 화면에 이미 있나?** 있으면 그걸 쓴다."*

## 4-3. 낭비가 아니었던 것 — 오해하지 말 것

지웠다고 다 낭비는 아니다.

| 지운 것 | 왜 낭비가 아닌가 |
| --- | --- |
| 구 구조 19파일 (08-04) | 갈아엎은 덕에 이후 7주가 버텼다. **늦게 한 게 문제이지 한 게 문제가 아니다** |
| 마음 나침반 (1번) | 아이디어 자체는 살아남아 「오늘의 성지 일정」이 됐다 |
| 조용한 성지 산식 | 버린 산식 덕에 "데이터 없으면 등급을 안 낸다"는 원칙을 얻었다 |

**즉 낭비의 정의**: *만들고 나서 아무것도 배우지 못한 것.*
여행 프로필(6번)과 카드 3종(5번)이 여기 해당한다 — 지울 때까지 **아무도 쓰지 않았고 아무것도 알려주지 않았다.**

## 4-5. 다음 프로젝트에서 쓰는 체크리스트

새 기능을 만들자는 말이 나오면 이 5개를 묻는다. **하나라도 "나중에"면 만들지 않는다.**

1. 이 기능의 결과를 **누가 어느 화면에서** 보나?
2. 필요한 **데이터를 실제로 한 번 받아봤나?** 응답을 파일로 저장했나?
3. 데이터가 **없을 때 화면은 어떻게** 되나? (비어 보이나? 0점이 되나?)
4. 이미 **비슷한 화면이 있나?** 있으면 왜 따로 만드나?
5. 이걸 **안 만들면 무엇이 안 되나?** 한 문장으로 답할 수 있나?
