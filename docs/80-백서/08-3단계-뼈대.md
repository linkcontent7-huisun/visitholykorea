## 8-1. 폴더 네 개로 시작한다

성지웹이 7주를 버틴 구조다 `[5879fe4 이후 현재까지 유지]`.

```
src/
  app/        앱을 조립하는 곳 — 주소·레이아웃·전역 설정
  pages/      화면 한 장 = 파일 한 개
  features/   기능 묶음 — 성지·지도·도슨트·인증…
  shared/     어디서나 쓰는 것 — 버튼·번역·타입·DB클라이언트
```

### 각 폴더가 하는 일

| 폴더 | 무엇이 들어가나 | 성지웹 실제 |
| --- | --- | --- |
| `app/` | 주소 목록, 상하단 네비, 전역 Provider | `routes/paths.ts`, `layouts/`, `providers/` (9개 파일) |
| `pages/` | 화면. **조립만 하고 로직은 안 넣는다** | 21개 화면 |
| `features/` | 한 기능의 api·컴포넌트·훅·lib | 12개 묶음 |
| `shared/` | api·components·config·hooks·i18n·lib·styles·types | 8개 폴더 |

`[ls src, 2026-09-23]`

### `features/` 안은 이렇게 생겼다

```
src/features/sites/          ← 가장 큰 기능 (38개 파일)
  api/
    sites.repository.ts      DB 행 ↔ 도메인 타입 변환. supabase 를 여기서만 부른다
    use-site.ts              TanStack Query 훅
  components/
    SiteGridCard.tsx
    SiteListItem.tsx
  lib/
    mass-info-localize.ts    순수 함수 (테스트하기 쉬움)
```

**기능 하나가 한 폴더 안에서 끝난다.** 성지 관련 무언가를 고치려면 `features/sites/` 만 열면 된다.

## 8-2. 의존 방향을 한쪽으로 고정한다

> **이 규칙 하나가 뼈대의 전부다.**

```
pages  →  features  →  shared
```

**화살표를 거슬러 import 하지 않는다.** 즉:

| 되는 것 | 안 되는 것 |
| --- | --- |
| 화면이 기능을 쓴다 | **기능이 화면을 쓴다** ❌ |
| 기능이 공용을 쓴다 | **공용이 기능을 쓴다** ❌ |
| 화면이 공용을 쓴다 | |

> **왜**: 화살표가 양방향이 되면 **무엇을 고쳐도 어디가 깨질지 모른다.**
> 한쪽 방향이면 "아래를 고치면 위가 영향받는다"만 생각하면 된다.

### 기능끼리 서로 쓰고 싶을 때는?

`shared/` 로 올린다. 성지웹 실제 사례 — 혼잡도 재설계 때
*"`externalErrorKey` 를 `shared/i18n` 으로 공용화"* 했다 `[615642e]`.

## 8-3. 첫날 정하는 규칙 6개

이걸 `CLAUDE.md` 의 「코드 구조 규칙」에 적는다. 성지웹의 실제 문장이다.

```markdown
## 코드 구조 규칙
- 의존성 방향: pages → features → shared. 역방향 import 금지.
- DB 행(snake_case) ↔ 도메인 타입(camelCase) 변환은 각 feature 의
  api/*.repository.ts 안에서만 한다. 화면 컴포넌트가 supabase 클라이언트를
  직접 부르지 않는다.
- 서버 상태는 TanStack Query 로 다루고, 캐시 키는 shared/api/query-keys.ts
  한 곳에서 만든다.
- 라우트 경로 문자열은 app/routes/paths.ts 에서만 정의한다.
- 새 테이블을 추가하면 supabase/migrations 마이그레이션과
  shared/types/database.ts 를 함께 고친다.
```

| # | 규칙 | 안 지키면 |
| --- | --- | --- |
| 1 | 의존 방향 한쪽 | 고칠 때마다 전체를 봐야 함 |
| 2 | supabase 는 repository 에서만 | DB 컬럼 바뀌면 21개 화면을 뒤짐 |
| 3 | 캐시 키는 한 파일에서 | 캐시가 안 지워지거나 두 번 지워짐 |
| 4 | 주소 문자열은 한 파일에서 | 오타 난 링크가 조용히 404 |
| 5 | 표 추가 = 마이그레이션 + 타입 같이 | 코드와 DB 가 어긋남 |
| 6 | 문구는 사전에 (9장) | **사전 104회 재작업** |

## 8-4. 주소(라우트)를 한 파일에 모은다

```
src/app/routes/paths.ts      ← 주소 문자열은 여기서만 정의
src/app/routes/router.tsx    ← 어느 주소에 어느 화면
```

```ts
// paths.ts — 이렇게
export const paths = {
  home: '/',
  siteDetail: (id: string) => `/sites/${id}`,
  records: '/records',
} as const
```

> **왜 중요한가**: 주소를 바꿀 때 한 곳만 고치면 된다.
> 성지웹은 재기획 때 화면 구조를 통째로 바꿨는데 `[ffbc836]`, 이 파일이 있어서 링크가 안 깨졌다.
> `paths.ts` 는 12번 수정됐다 — 구조가 12번 바뀌었지만 **화면 코드는 안 건드렸다**는 뜻이다.

## 8-5. 화면은 "조립만" 한다

**화면 파일에 로직을 넣지 않는다.** 이걸 어기면 이렇게 된다:

> `SiteDetailPage.tsx` — **72번 수정** `[git log 집계]`.
> 9/17 커밋 하나에서만 14개 항목을 고쳤다 `[4de41d5]`.
> 방문정보·도슨트·주변정보·후기가 전부 이 한 파일에 붙어 있었다.

**한 화면이 200줄을 넘으면 자른다.** 잘라낸 조각은 `features/<기능>/components/` 로 보낸다.

```tsx
// 좋은 화면 — 조립만 한다
export function SiteDetailPage() {
  const { id } = useParams()
  const { data: site } = useSite(id)     // 데이터는 훅이
  if (!site) return <Loading />
  return (
    <>
      <SiteHero site={site} />           {/* 조각은 feature 가 */}
      <DocentPlayer siteId={site.id} />
      <NearbyPlaces siteId={site.id} />
    </>
  )
}
```

## 8-6. 검증 명령을 첫날 만든다

`package.json` 에 이 한 줄을 넣는다. **커밋 전에 항상 돌린다.**

```json
"verify": "npm run typecheck && npm run lint && npm run test"
```

| 검사 | 무엇을 잡나 |
| --- | --- |
| `typecheck` | 타입이 안 맞는 곳 (이름 오타, 빠진 값) |
| `lint` | 규칙 위반, 안 쓰는 변수 |
| `test` | 동작이 깨진 곳 |

> **성지웹 실측**: 450개 테스트 / 62파일, 52초 `[npx vitest run, 2026-09-23]`.
> 52초로 7주치 작업이 안 깨졌는지 확인한다.

### 규칙 위반을 기계가 막게 한다

테스트로 **구조 규칙 자체**를 검사할 수 있다. 성지웹은 번역 누락을 잡는 검사를 4개 만들었다 `[2d9d68e]`.

```
npm run translate:check   ← 미번역 문구가 있으면 CI 실패
```

> **사람이 지키는 규칙은 언젠가 깨진다. 기계가 지키는 규칙만 남는다.**

## 8-7. 뼈대가 잡혔는지 확인하는 법

새 화면 하나를 **처음부터 끝까지** 만들어 본다. 그러면 뼈대의 구멍이 드러난다.

```
① paths.ts 에 주소 추가
② router.tsx 에 화면 연결
③ pages/NewPage.tsx 만들기 (조립만)
④ features/<기능>/api/*.repository.ts 에서 데이터 가져오기
⑤ features/<기능>/api/use-*.ts 훅으로 감싸기
⑥ query-keys.ts 에 캐시 키 추가
⑦ 문구를 dictionary 에 넣기
⑧ npm run verify
```

**이 8단계가 막힘없이 되면 뼈대가 된 것이다.** 어딘가 어색하면 지금 고친다 — 화면 20개 만든 뒤가 아니라.
