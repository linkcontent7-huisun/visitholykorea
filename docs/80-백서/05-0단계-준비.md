# 5장. 0단계 준비 — 시작하기 전에 갖춰 둘 것

> **이 장은 코드를 한 줄도 안 쓴다.** 그런데 여기를 건너뛰면 3장의 사건 1·7·8 이 그대로 재현된다.
> 걸리는 시간: **처음이면 2~3시간, 두 번째부터는 40분.**
>
> 순서대로 따라 하면 된다. 이미 해본 것은 건너뛴다.

## 5-1. 폴더를 만든다

**OneDrive 안에 만들지 않는다.** OneDrive 가 동기화하는 도중에 빌드가 돌면 파일이 깨진다.
성지웹은 OneDrive 안에 있어서 지금도 그 위험을 안고 있다 `[현재 경로: C:\Users\...\visitholykorea app]`.

권장 위치 — 한글·공백이 없는 짧은 경로:

```
C:\dev\radio-writer
```

> **경로에 한글과 공백이 없으면 나중에 명령어가 훨씬 편해진다.**
> 성지웹 경로에는 공백이 있어(`visitholykorea app`) 모든 명령에 따옴표를 붙여야 한다. 작은 불편이 7주 내내 따라다녔다.

Windows 탐색기에서 폴더를 만들고, **주소창을 클릭해 경로를 복사**한다 (`Ctrl+L` → `Ctrl+C`).

## 5-2. GitHub 저장소를 만들고 첫날 연결한다

> **3장 사건 1**: 로컬 폴더가 사라져 복구에 매달렸다. 원인은 GitHub 에 밀어두지 않은 것.

1. github.com 에서 **Private** 저장소를 만든다 (이름: `radio-writer`)
2. 터미널에서:

```bash
cd /c/dev/radio-writer
git init
git remote add origin https://github.com/<내계정>/radio-writer.git
git branch -M main
```

3. **첫 커밋을 그날 안에 푸시한다.** 내용이 README 한 줄뿐이어도 된다.

```bash
echo "# 라디오작가 에이전트" > README.md
git add README.md
git commit -m "첫 커밋"
git push -u origin main
```

> **원칙**: *내 컴퓨터는 백업이 아니다.* 하루 일을 끝내면 푸시하고 닫는다.

## 5-3. 비밀 파일을 먼저 차단한다

**코드를 쓰기 전에** `.gitignore` 를 만든다. 나중에 만들면 이미 올라간 뒤다.

```bash
cat > .gitignore <<'END'
# 설치 파일
node_modules/
dist/
build/

# 비밀 — 절대 올리지 않는다
.env
.env.local
.env.*.local
!.env.example
*.key
*token*.txt
*key*.txt
*비번*.txt

# 편집기·OS
.DS_Store
Thumbs.db
.idea/
END
git add .gitignore && git commit -m "비밀 파일 차단" && git push
```

> **성지웹의 실제 문제** `[2026-09-23 확인]`: 저장소 최상위에 `cf-token.txt`, `kakao-js-key.txt`,
> `googleconsole.txt`, `nas-비번.txt.txt` 가 놓여 있다. 커밋은 안 됐지만 **`git add .` 한 번이면 올라간다.**
> 위 `.gitignore` 의 `*token*.txt` 같은 줄이 이걸 막는다.

**비밀 값은 `.env.local` 한 파일에만 둔다.** 그리고 `.env.example` 에는 **키 이름만** 적어 커밋한다 —
다음 사람(또는 다음 AI 세션)이 무엇이 필요한지 알 수 있게.

## 5-4. AI 에게 폴더를 읽힌다

터미널에서 그 폴더로 들어가 Claude Code 를 연다. 그러면 **그 폴더가 작업 기준**이 된다.

```bash
cd /c/dev/radio-writer
claude
```

또는 데스크톱 앱이면 폴더 경로를 붙여넣어 연다.

**파일 하나를 읽히고 싶을 때**는 탐색기에서 파일 우클릭 → `경로로 복사` 한 뒤 대화창에 붙여넣는다.
그냥 파일 이름만 말하면 AI 가 엉뚱한 파일을 찾는다.

> **터미널에서 직접 명령을 돌려야 할 때** (예: 로그인 같은 대화형 명령)는
> 대화창에 `!` 를 앞에 붙여 입력하면 그 자리에서 실행되고 결과가 대화에 남는다.
> 예: `! gh auth login`

## 5-5. `CLAUDE.md` 를 쓴다 — 이 파일이 프로젝트의 헌법이다

**AI 세션은 이전 대화를 기억하지 못한다.** 매번 처음부터 시작한다.
`CLAUDE.md` 는 새 세션이 열릴 때마다 자동으로 읽히는 파일이다. 여기 적힌 것만 지켜진다.

프로젝트 최상위에 `CLAUDE.md` 를 만들고 **이 다섯 가지**를 적는다.

```markdown
# CLAUDE.md

## 작업을 시작하기 전에
`docs/이어서-할-일.md` 부터 읽는다. 지금 무엇이 끝났고 무엇이 남았는지가 거기 있다.
작업이 끝나면 그 파일을 그 자리에서 고친다. 나중에 몰아서 하지 않는다.

## 이 프로젝트가 무엇인가
(한 문장. 누구를 위해 무엇을 하는 물건인가)

## 반드시 지킬 것
- 비밀 키를 클라이언트에 두지 않는다
- (도메인 고유 제약 — 예: "AI 원고는 반드시 사람 검수를 거친다")

## 코드 구조 규칙
- 의존성 방향: pages → features → shared. 역방향 import 금지
- (나머지는 8장에서)

## 스타일
- 주석과 UI 문구는 한국어. "무엇을"보다 "왜"를 남긴다
- 커밋 전 `npm run verify` 를 통과시킨다
```

> **성지웹의 `CLAUDE.md` 가 실제로 한 일**: 7주 동안 여러 세션·여러 창이 같은 규칙을 지켰다.
> "TourAPI 응답을 저장하지 않는다", "AI 답변은 성지 DB 안으로 제한한다" 같은 규칙이 여기 있었기 때문에
> **한 번도 어겨지지 않았다.** 대화로만 말했으면 다음 세션이 몰랐을 것이다.

### `CLAUDE.md` 에 넣으면 안 되는 것

- 오늘의 할 일 (→ `이어서-할-일.md`)
- 긴 설명이나 배경 (→ `docs/`)
- 지나간 결정의 경위 (→ ADR)

**매 세션 읽히는 파일이라 길면 길수록 손해다.** 한 화면 분량을 넘기지 않는다.

## 5-6. 현황판 파일을 만든다 — `docs/이어서-할-일.md`

> **3장 사건 7**: 창 두 개가 같은 작업을 각각 했다.

이 파일 하나가 세션 간 유일한 연락 수단이다. 규칙은 두 줄이다.

- **작업을 시작할 때**: 맨 위에 `🔨 지금 ○○ 하는 중 (브랜치명, 시각)` 한 줄을 쓰고 **바로 푸시**
- **작업이 끝나면**: 그 줄을 `✅ 끝남` 으로 바꾸고 결과를 한 문단으로. **그 자리에서** 고친다

```markdown
# 이어서 할 일

> 🔨 **지금 하는 중(01:30, 로컬 세션 A):** 원고 초안 생성 화면 — `feature/draft-editor`

## 끝난 것
...

## 다음에 할 것
...
```

> **왜 몰아서 쓰면 안 되나**: 성지웹에서 이 문서가 열흘 방치돼
> **"이미 끝난 일을 다시 하려던" 사고**가 있었다 `[CLAUDE.md 에 기록된 2026-08-19 사고]`.

## 5-7. 문서 폴더 뼈대를 만든다

나중에 218개가 돼도 찾을 수 있게, **번호를 붙인 폴더**로 시작한다.

```
docs/
  이어서-할-일.md        ← 현황판 (제일 자주 열림)
  00-overview/           개요·인수인계·일지
  10-product/            기획·로드맵·요구사항
  20-architecture/       설계·ERD·ADR(결정 기록)
  30-content-ops/        콘텐츠 만드는 법
  70-workspace/          작업 지시서·보고
```

`[성지웹의 실제 구조를 그대로 옮긴 것]`

**ADR(Architecture Decision Record)** 은 "왜 이렇게 정했나"를 한 장씩 남기는 문서다.
성지웹은 6개를 썼고 `[docs/20-architecture/adr/]`, 그 덕에 7주 뒤에도 이유를 알 수 있다.

```markdown
# ADR 0001 — (결정 제목)
## 맥락 (무슨 문제가 있었나)
## 결정 (무엇으로 정했나)
## 이유 (왜 다른 걸 안 했나)
## 결과 (이 결정 때문에 생기는 제약)
```

## 5-8. 계정과 키를 미리 준비한다

**나중에 막히는 것은 코드가 아니라 승인 대기다.**
성지웹에서 네이버 로그인은 제출 당일까지 못 고쳤다 — 개발자센터 등록이 안 돼 있어서였고, 검수는 며칠 걸린다 `[이어서-할-일.md 2026-09-21]`.

시작할 때 **승인에 시간이 걸리는 것부터** 신청한다.

| 종류 | 예 | 걸리는 시간 |
| --- | --- | --- |
| **공공 API 키** | 공공데이터포털 (활용신청 → 승인) | 몇 시간~며칠 |
| **소셜 로그인** | 카카오·네이버 개발자센터 등록, 검수 | **며칠** |
| DB·인증 | Supabase 프로젝트 | 즉시 |
| AI | Google AI Studio / Anthropic 키 | 즉시 |
| 배포 | Vercel (GitHub 연결) | 즉시 |
| 도메인 | 구입 + DNS 연결 | 하루 |

### 무료 플랜의 한도를 **지금** 읽는다

> **3장 사건 8**: 제출 사흘 전 Vercel 배포 한도(100회/24시간)에 걸려 코드를 못 고쳤다.

| 서비스 | 확인할 한도 |
| --- | --- |
| Vercel Hobby | **배포 생성 100회 / 24시간** (빌드가 아니라 배포 건수) |
| Supabase Free | DB 용량, 월 요청 수, 프로젝트 일시정지 조건 |
| AI API | 분당 요청 수, 일일 토큰 |

그리고 **문서만 바뀐 커밋이 배포를 부르지 않게** 설정해 둔다 (`vercel.json` 의 `ignoreCommand`).
