# 문서 안내

정리 2026-09-12 · 번호는 "성격"이다. 처음 오는 사람은 `이어서-할-일.md` → `00-overview/프로젝트-개요.md` → `10-product/로드맵.md` 순.
**각 폴더의 README 에 "무엇을 확인하려면 어느 파일" 표가 있다** — 요구사항이 지켜졌는지는 그 표로 바로 찾는다.

| 폴더 | 담는 것 | 이런 질문에 답한다 |
| --- | --- | --- |
| `이어서-할-일.md` | 지금 상태와 다음 할 일 (날짜별) | 오늘 뭘 해야 하나 |
| `00-overview/` | 개요 · 현황판 · 인수인계 · 가이드 | 어디까지 됐나, 새 창에서 어떻게 잇나 |
| `10-product/` | 로드맵 · 공모전 · 기획 검토 · 도슨트 기획 · 제안서 | 무엇을 왜 만드나, 심사에 뭘 내나 |
| `20-architecture/` | 시스템 구조 · 결정 기록(ADR) · UI 설계 | 왜 이렇게 만들었나 |
| `30-content-ops/` | 현장 취재 · 수요조사 · 베타테스터 · SNS · 팀원 소통 | 성지를 어떻게 찍고 누구에게 알리나 |
| `40-knowledge/` | 순교사 · 성인 · 교회사 · 영성 · 비즈니스 지식창고 | 성지 배경지식 |
| `50-research/` | 초기 리서치 · 디자인 레퍼런스 · 팀원 UI 패치 | 참고했던 것 (현재 구현과 다를 수 있음) |
| `70-agent-workspace/` | 에이전트 규칙 · 지시서(T-001~) · 보고 · 설계 스펙 | Codex·서브에이전트에게 무엇을 시켰나 |

**저장소에 없는 것** — 창업 지원사업 서류(모두의창업·코딧세이 등)와 사업계획서는 `.gitignore` 로 로컬 전용이다.
`docs/10-product/` 안에 파일은 있으나 GitHub 에는 안 올라간다.

## 문서를 새로 쓸 때

- 파일명은 한글로 써도 된다. 공백 대신 `-`. 날짜가 있는 기록은 `YYYY-MM-DD-` 로 시작한다
- 결정을 내렸다면 ADR(`20-architecture/adr/`)에 한 장 — "무엇"보다 "왜 그때 그렇게"
- 숫자(성지 수·사진 수·테스트 수)는 **잰 날짜**를 같이 적는다. 못 잰 것은 "확인 못 함"
- 새 파일을 넣으면 그 폴더 README 표에 한 줄 추가한다
